4. 再次被动确认 ADB/5037 为 `0/0`，对 exact external artifacts 完成独立 P0/P1/P2 静态复核，然后只运行一次 r14
   read-only preflight。它不得启动 launcher/helper/Gradle/JDK/ADB 或访问设备。
5. preflight 闭合后冻结工件与 receipt；其后不得运行会重建 module `build`、改变 Git trust root 或重启 default ADB
   的工具。只有用户针对新完整 SHA 明确授权后，才能启动一次 launcher；automatic retry 固定 `0`，旧授权不可复用。

## 仍未授权的范围

本清单不授权 install、ADB 命令、设备发现、T0、C1b 采集、截图、OCR、目标 App 启动、系统设置修改、关闭手机套件或
终止宿主进程，亦不放行
navigation、conversation、target、regions、layout、微信布局、editor action、T-L1、P0 或 execution。

## 后续记录要求

- 新 preflight leaf 只写 repo-external receipt 内部字段；进程结束后由外层独立计算 leaf/receipt SHA，并观察外部 exit、
  terminal state 与 primary/cleanup/recording failure count。receipt 不能自记自身最终 SHA 或尚未发生的进程 exit；
  两类证据必须联合消费后才能判 `prepared_not_authorized`。
- build-only one-shot 无论通过或失败都另建冻结 run 文档；记录 launcher/helper start 与 exit、retry、Gradle/签名/
  held Git/ADB/设备计数、正式输出与 failure-only sidecar 的 bytes/hash/ReadOnly 状态。
- 若 one-shot 失败，同一 SHA 不重跑；先冻结证据、更新本册与 backlog，再形成新 SHA。
