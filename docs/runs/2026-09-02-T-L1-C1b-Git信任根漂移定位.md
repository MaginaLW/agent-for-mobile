# T-L1 C1b · Git 信任根漂移定位（只读，已定位并机械闭合）

## 结论

- **漂移已定位为单一新增文件 `usr/bin/busybox.exe`，其余 9576 个文件与冻结值逐字节一致。**
  按 `scripts/lib/tablet-layout-c1b-build-env.ps1` 的同一规则（inventory → Ordinal 排序 →
  `relpath=sha256:hex` 以 LF 连接 → UTF-8 no-BOM 的 SHA-256）独立复算：
  - 现树 9577 文件的 catalog = `sha256:deeaa4c2f51603d56cf7477fc413d0b9b914f58450431fbb6921f392ccc134ee`，
    **与 `a661f36` smoke 退出后记录的漂移值完全一致**——这是本次复算规则本身的对照，规则复刻正确；
  - 仅排除 `usr/bin/busybox.exe` 后的 9576 文件 catalog =
    `sha256:4c5e585b10f371f181b42b60948a883409c0efda910b869ff98c2e5604267458`，
    **与冻结常量 `TL1C1bBuildEnvironmentGitCatalogSha256` 逐位相等**。
- 因此：**没有任何 Git 二进制被篡改**；`cmd/git.exe`、`mingw64/bin/git.exe`、三个 pinned DLL 等六个 key file
  本就在 r13 preflight 通过，本次全树复算进一步证明其余全部文件未变。漂移是"多了一个文件"，不是"改了一个文件"。
- **移除该文件即可精确恢复冻结信任根**，无需下载、无需安装、无需重启。
- **原计划的 `A-Acquire → B-Backup → C-HostChange → D-Reboot → E-Cleanup` 五道重装阶梯不能解决本问题。**
  该文件不在 Inno Setup 卸载日志中（见下），卸载器只删除日志内文件，因此卸载+重装后它仍会存在，
  文件数仍为 9577，门仍然 fail-closed。两次已消费的 A 授权走在一条**结构上无法闭合**的路径上。

### 为什么 `NotSigned` 本身不构成结论

同树对照：`usr/bin/sed.exe`=`NotSigned`、`usr/bin/msys-2.0.dll`=`NotSigned`、`cmd/git.exe`=`Valid`。
MSYS2 载荷二进制本就普遍无 Authenticode 签名，所以未签名是该目录的常态，不是异常信号。
（此处用的是 `-LiteralPath` 命名路径分支，不是 r2 踩过的 `-Content` blob 分支，结论可用。）
