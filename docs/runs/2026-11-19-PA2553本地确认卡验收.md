## 真机结果

| 项目 | 平板确认卡 | 网关与靶标证据 |
|---|---|---|
| Allow | 用户允许 | 一次具名点击，审计记录 `decided_via=overlay`、上下文重验和 `OK`。同一进程、Activity 实例、页面代次的独立回调计数从 0 变为 1。 |
| Stale | 用户允许 | 测试钩子切到桌面后，上下文重验返回 `E_STALE_REF / safety`。卡片图像中的按钮和 12 位确认编号与本轮状态记录一致。同一页面回调保持 0，终态后工具调用 0 次。 |
| Deny | 用户拒绝 | 网关返回 `E_BLOCKED / overlay`，审计同时记录 `confirmation=denied` 和 `decided_via=overlay`。同一页面回调保持 0，终态后工具调用 0 次。 |

第一次准备 Stale 时，重复分派相同 VIEW 后，网关确认目标包已处于前台。界面快照和靶标独立记录均显示原页面仍为 1，准备派单按失败入账。当时尚未发起 Stale 点击。现场用户随后批准在剩余各项开始前仅停止靶标进程一次。重新派单后，Activity 实例与上轮不同，独立计数为 0。

Allow、Stale、Deny 三次派单分别耗时 102、31、37 秒。计入四次页面准备，台账共记七次派单，其中四次成功，三次失败。三次失败分别对应一次沿用旧页面的准备失败，以及 Stale、Deny 两次符合预期的安全拦截。收尾时再次读回靶标和网关 APK 摘要，并确认本轮设备上的测试控制、确认状态、卡片图像及中转文件均已清理。[派单台账](ledger.csv)
