## R1 / R5

当前基线包含两项离线修复，但均缺真机验收。C1b runner 只安装独立只读探针，不包含 gateway MCP 或 `intent_send`，因此 R1 和 R5 不混入 C1b 两帧采集。如未来共用设备窗口，仍须分别固定 gateway 构建、候选、前置、授权、判据和证据，串行执行。

R1 需准备字段合法、`leg=1`、`executor=mobile` 且未消费的暂停件，记录暂停件前后内容、退出码和 `mobile -Confirm 已阻断` 信息，并核对执行器未启动及无设备副作用，证明命中专属阻断分支。普通 Codex + mobile 派单的拒绝不是该分支的证据；旧无 `executor` 的暂停件也不得恢复。gateway 确认卡如另验，需独立任务及设备端真人确认；PC `RESUME` 不是批准，安全终态不得恢复或重试。

R5 需无危险副作用的白名单目标及可复现反例。目前尚无已验证的现场反例；需独立佐证系统接受了请求且目标在验证窗口内未到前台，无法建立场景或证据时保持未验证。

离线核查尚未找到可直接复用的独立证据方案：现有系统前台快照只能证明采样时点，不能排除间隙中的短暂落地；现有审计也未绑定独立系统事件与轮询窗口。被测实现配置 3 秒超时并按间隔轮询，若无障碍实例不可用则直接返回失败，不代表已观察满 3 秒。后续须先验证证据来源、时钟关联和覆盖范围，不能把事件缺失或零散快照当作完整窗口的负证据。

官方资料提供可调查的正向线索：[Android 16 ActivityStarter 源码](https://android.googlesource.com/platform/frameworks/base/+/android16-qpr2-release/services/core/java/com/android/server/wm/ActivityStarter.java)有启动请求及结果码日志，[AOSP 窗口事件定义](https://android.googlesource.com/platform/frameworks/base/+/master/services/core/java/com/android/server/wm/EventLogTags.logtags)包含 activity 创建、恢复等事件；[logcat 文档](https://developer.android.com/tools/logcat)说明 system/events 环形缓冲及时间格式。厂商是否输出、可否读取、是否丢失和能否关联本次调用均未验证，日志可能含敏感信息；有事件也不等于画面已显示，无事件更不能证明未落地。官方 [Winscope ADB 方式](https://source.android.com/docs/core/graphics/winscope/capture/adb)需要 debug 构建与 root，不能假设用户平板满足。以上是未来取证可行性调查线索，不构成现场通过判据或运行许可。

R5 可供后续独立验收尝试的候选是以 `intent_send` 指定 `action=android.intent.action.VIEW`、`uri=xhsdiscover://search/result?keyword=test`、`package=com.xingin.xhs`，不传组件或 extras。这是只读导航，但目标 App 可能联网提交搜索。历史手机上 `open_uri` 曾在三秒内未落到小红书前台（[记录](2026-07-17-M1-spike.md)），不代表当前设备或 `intent_send` 必然复现。

需先按现行队列和批次规则排期，分别固定受测候选与 gateway 构建身份、设备/系统和 App 版本，并确认目标已安装、可解析和前台证据可用；再按现行规程报就位并取得针对本轮的开跑令。单次调用保留原始响应与审计，并用带外证据覆盖整个验证窗口。响应为“Intent 已分派但未能确认前台落在”对应的 `E_VERIFY_FAIL`，只表明被测代码走到 `startActivity` 未抛异常后的判定路径；还须以独立现场证据佐证系统接受请求、目标在窗口内未到前台，才能判定反例触达。无接收方、目标正常落地或证据不足均不算负向通过；不为制造失败而改权限、切前台或重发同一 Intent。以上只是准备，不新增批次或设备运行许可。
