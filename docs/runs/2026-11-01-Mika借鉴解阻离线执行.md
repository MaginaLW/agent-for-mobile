## R1 专属阻断：可交接测试对象与判据

未来一次性合法对象的形状如下；这是本记录里的资料，不是已创建的 `.pause.md`，不能直接恢复历史真实件：

```text
slug: r1-block-NONCE
leg: 1

---
[AWAIT_CONFIRM]
本轮 R1 专属阻断测试资料；不得据此执行任何设备动作。
```

`NONCE` 表示未来生成的本轮唯一 ASCII 字母数字串；替换后 slug 须符合 `[A-Za-z0-9._-]{1,80}` 且无 `..`。头部键大小写不敏感且唯一，非空行须为 `key: value`；必须有独占一行的 `---`。未消费应省略整个 `consumed` 字段，不能写空值。该分支不要求 brain/model/session_id，也不填真实收件人、会话或待恢复动作。

未来命令是 `dispatch.ps1 -Confirm` 指向本轮独立合法件。专属阻断在取锁、profile/DryRun、brain 校验、输入提示、消费写入和执行器启动之前；没有创建锁属于预期，不算失败。

| 必需证据 | 核对要求 |
|---|---|
| 测试身份 | 固定完整源码 SHA、PowerShell 版本、实际参数、本轮件身份与解析结果 |
| 调用前后对象 | 保存完整字节、SHA-256、大小；前后逐字节一致，仍未消费 |
| 进程结果 | 分别保存 stdout/stderr、非零退出码；明确含 `mobile -Confirm 已阻断`，不能是更早的非法输入拒绝 |
| 未启动及无副作用 | traces/ledger/锁的前后清单及内容摘要不变；受控 fixture 的 adb/claude/codex/npx 哨兵零调用、进程/子进程证据；单凭画面没变或没有 trace 不充分 |
| 范围说明 | 受控隔离证明不冒称新的真机结果；如按现行队列进行现场验收，另固定 C 的环境与未触达证据 |

## R5：独立完整窗口证据仍不可得

已核对 [IntentTools.intentSend](../../app/gateway/src/main/java/dev/magina/gateway/tools/IntentTools.kt) 第 54–97、243–277 行、[SystemTools.waitForegroundLanding](../../app/gateway/src/main/java/dev/magina/gateway/tools/SystemTools.kt) 第 256–270 行及 [Audit](../../app/gateway/src/main/java/dev/magina/gateway/core/Audit.kt)。

- 被测路径是 gateway app 的 `ctx.startActivity`；shell 启动使用不同身份，会改变后台启动条件，不能替代原调用验收。
- 目标已知但未获前台正证据时返回 `E_VERIFY_FAIL`；无接收方是 `E_NOT_FOUND`。无 component 的 VIEW 主要验证包级前台，不证明搜索页语义。
- 无障碍实例缺失会立即返回 false；否则约 200 ms 离散轮询、正命中提前结束。配置 3000 ms 不等于每次都完整观测 3 秒。
- 当前审计记录墙钟、进程内递增 ID、工具/参数、结果及总耗时；没有独立系统接收、实际轮询起止和完整采样轨迹，不能从墙钟加总耗时还原该窗口。

| 四项必需证据 | 当前结论 |
|---|---|
| 唯一请求关联 | 无已验证的 app 调用—系统事件跨来源关联；相近时间或同包名不充分 |
| 独立系统接收 | 未核实 PA2553 是否输出且允许读取所需系统请求/结果字段 |
| 实际窗口起止 | 当前实现未提供轮询起止与带外时钟映射；不能先假定可恢复 |
| 完整覆盖与丢失检测 | 无已验证的覆盖/断档/丢失判据，不能排除采样间隙瞬时落地 |

只读导航候选仍为 `action=android.intent.action.VIEW`、`uri=xhsdiscover://search/result?keyword=test`、`package=com.xingin.xhs`，不传 component/extras。它可能联网搜索；历史 `open_uri` 不落地不能证明当前设备的 `intent_send` 必然复现。

| 候选来源 | 权限与时钟/完整性条件 | 证明范围及停止理由 |
|---|---|---|
| system/events 日志 | 实际 buffer/tag/过滤和厂商字段待核实；环形缓冲可能覆盖，需保留原始流、配置和丢失判据，并映射时钟 | START/结果码、create/new-intent/resume 可提供正向线索；无事件不能证明从未落地，resume 不等于像素显示 |

| WM/SF/Winscope trace | 官方 ADB 路径需 userdebug/eng 与 root，当前设备不假定具备；需处理 buffer、display、时钟与 trace 丢失 | single dump 仍是快照；窗口状态不自动等于像素显示。不得为研究 root 或改系统 |

本轮复核了[Logcat](https://developer.android.com/tools/logcat)、[Android 16 ActivityStarter](https://android.googlesource.com/platform/frameworks/base/+/android16-qpr2-release/services/core/java/com/android/server/wm/ActivityStarter.java)、[AOSP 窗口事件](https://android.googlesource.com/platform/frameworks/base/+/master/services/core/java/com/android/server/wm/EventLogTags.logtags)、[Winscope ADB](https://source.android.com/docs/core/graphics/winscope/capture/adb)及[ADB 录像](https://developer.android.com/tools/adb#screenrecord)的说明；它们是公开资料依据，未验证 vivo 的输出或能力。
