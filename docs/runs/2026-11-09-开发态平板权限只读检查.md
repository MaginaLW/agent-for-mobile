## APK 权限清单

`aapt dump permissions` 显示当前 debug APK 声明：

```text
INTERNET
FOREGROUND_SERVICE
FOREGROUND_SERVICE_SPECIAL_USE
POST_NOTIFICATIONS
SYSTEM_ALERT_WINDOW
BLUETOOTH_CONNECT
ACCESS_WIFI_STATE
ACCESS_NETWORK_STATE
READ_MEDIA_IMAGES
```

没有声明：

```text
WRITE_SECURE_SETTINGS
DUMP
GET_APP_OPS_STATS
PACKAGE_USAGE_STATS
QUERY_ALL_PACKAGES
```

`DUMP` 只出现在 debug variant 的 ContentProvider `android:permission` 上，表示“调用方必须有 DUMP”，不是网关自身请求的权限。因此当前直接执行 `pm grant dev.magina.gateway android.permission.WRITE_SECURE_SETTINGS` 会报“has not requested permission”；要么改用 ADB shell，要么在 `app/gateway/src/debug/AndroidManifest.xml` 增加 debug-only 的 `uses-permission` 后重建。

## 结论

1. **ADB 是当前最可靠的主通道**：USB 已连通，`input`、`screencap`、`uiautomator`、`am`、`pm`、`dumpsys` 都不依赖 gateway 的无障碍进程。
2. **ADB 授权会 7 天过期**：`adb_allowed_connection_time=604800000`，开发态应改为 `0` 并读回确认。
3. **USB 模拟点击已就绪**：`persist.sys.adb.simulate.ic=true`，无需再改。
4. **无障碍当前只有 vivo 输入法**：启用 gateway 时必须保留现有条目，追加 `dev.magina.gateway/dev.magina.gateway.a11y.GatewayA11yService`。
5. **安全中心是已知变量**：6.2.1.3 未禁用，和项目静态分析同版本；若设置/微信/QQ 前台仍撤销服务，可逆试用 `pm disable-user --user 0 com.vivo.safecenter`，失败或异常则 `pm enable` 恢复。
6. **当前无 root**：`ro.debuggable=0` 且无 `su`，`adb root` 不可用；root/Device Owner 不是本轮现成选项。
7. **包列表仍有微信、支付宝、Gmail 等应用**：本轮只读包名，未读取内容；若为真实账号，自动读屏前应先换测试账号或专用用户。
8. **当前未安装项目 App**：实际 grant 状态无法检查；所有应用级授权必须在安装 debug APK 后执行。
