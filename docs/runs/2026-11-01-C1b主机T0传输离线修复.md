## 问题与最小修改

[上一阶段](2026-11-01-C1b新包采集冻结与传输契约复现.md)已离线复现：URI 手工加单引号后交给 exec-in，参考实现会再次 escape_arg，使原引号进入远端参数；fake ADB 统一 Trim 引号掩盖该层。exec-in 本地写完也不能据以核验远端输出或退出状态。

本轮没有增加传输抽象，将 T0 唯一写入点改为 `adb shell -T content write --uri '<URI>'`，保留现有 URI 校验与单引号。`-T` 禁用 PTY，shell protocol 支持 stdin EOF、分别读取 stdout/stderr 与远端退出状态；缺少协议时失败，不回退 exec-in 或 PTY。content 可能捕获异常、打印 stderr 后仍 exit 0，因此任意非空 stdout/stderr（包含空白）都失败。错误只记录长度，不落盘可能含 URI/nonce/serial 的远端原文；stderr 长度是字符串经 UTF-8 重编码的大小，不是任意坏编码的原始字节承诺。

既有 status ready_c1、producer/nonce/标题/制品绑定、一次写入、不补拍、abort、900ms/15s 与设备锁门全部保留。失败输出不证明写入未发生，所以仍尝试原 abort。源代码和同步规程见[候选 runner](https://github.com/MaginaLW/agent-for-mobile/blob/565bcf1ea4e440d93046b516b5a386d0d5c3360d/scripts/run-tablet-c1b.ps1)及[候选规程](https://github.com/MaginaLW/agent-for-mobile/blob/565bcf1ea4e440d93046b516b5a386d0d5c3360d/docs/runbooks/T-L1-tablet-c1b.md)。

选择依据仅为公开参考源码：[ADB 客户端](https://android.googlesource.com/platform/packages/modules/adb/+/refs/heads/main/client/commandline.cpp)的 raw shell/close-stdin 与 exec-in 分支、[daemon shell service](https://android.googlesource.com/platform/packages/modules/adb/+/refs/heads/main/daemon/shell_service.cpp)的 raw 半关闭输入，以及 [Content.java](https://android.googlesource.com/platform/frameworks/base/+/refs/heads/main/cmds/content/src/com/android/commands/content/Content.java)的复制到 EOF/异常打印行为。不据此证明本机 SDK 二进制等同参考源码或此前真机的唯一根因。
