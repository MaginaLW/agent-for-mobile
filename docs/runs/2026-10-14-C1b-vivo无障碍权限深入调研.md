## 新发现三：Android 16 有独立的服务登记检查

核对的是 `android16-release` 固定源码：frameworks/base `99b01a65cc4c104933788b3143285ab6bae65827`、Permission `fd6db90f998351ae7896543bc08d730ecbbc4f12`、Settings `0fb38ed81e9b49d5da4be8f50d9d69865c1192e8`。它们是平台参考实现，vivo 的实际改动和开关未知。

1. 正式“解除限制”针对 `ACCESS_RESTRICTED_SETTINGS`。ECM 对显式 allowed 直接认可应用级放行；只有隐式/default 状态才按来源等因素判断。未见该来源检查在几秒后自动清启用列表的定时路径。见 [Settings 确认处理](https://android.googlesource.com/platform/packages/apps/Settings/+/0fb38ed81e9b49d5da4be8f50d9d69865c1192e8/src/com/android/settings/applications/appinfo/AppInfoDashboardFragment.java#493)、[ECM clearRestriction / isPackageEcmGuarded](https://android.googlesource.com/platform/packages/modules/Permission/+/fd6db90f998351ae7896543bc08d730ecbbc4f12/service/java/com/android/ecm/EnhancedConfirmationService.java#289)。
2. `AccessibilitySecurityPolicy.canRegisterService()` 独立检查 `BIND_ACCESSIBILITY_SERVICE` AppOp。非 allowed 时跳过登记；之后重新解析服务列表、更新服务时，系统可以把不在登记列表里的组件从 enabled 中删除并持久化。只有完整时间轴才能支持这条因果链，不能凭 ECM allowed 排除它。见 [登记检查](https://android.googlesource.com/platform/frameworks/base/+/99b01a65cc4c104933788b3143285ab6bae65827/services/accessibility/java/com/android/server/accessibility/AccessibilitySecurityPolicy.java#599)、[登记过滤](https://android.googlesource.com/platform/frameworks/base/+/99b01a65cc4c104933788b3143285ab6bae65827/services/accessibility/java/com/android/server/accessibility/AccessibilityManagerService.java#2538)、[enabled 裁剪](https://android.googlesource.com/platform/frameworks/base/+/99b01a65cc4c104933788b3143285ab6bae65827/services/accessibility/java/com/android/server/accessibility/AccessibilityManagerService.java#3015)。
3. 实际 force-stop 的包重启事件会走[停止处理](https://android.googlesource.com/platform/frameworks/base/+/99b01a65cc4c104933788b3143285ab6bae65827/services/accessibility/java/com/android/server/accessibility/AccessibilityManagerService.java#975)，可移除启用配置；普通断连在[用户服务状态](https://android.googlesource.com/platform/frameworks/base/+/99b01a65cc4c104933788b3143285ab6bae65827/services/accessibility/java/com/android/server/accessibility/AccessibilityUserState.java#292)中仍 enabled、只是 unbound。普通 kill、force-stop 和直接改设置需区分。
4. `isAccessibilityTool=false` 的 API 文档提到延时隐私通知；Android 16 的[ECM 全局检查](https://android.googlesource.com/platform/packages/modules/Permission/+/fd6db90f998351ae7896543bc08d730ecbbc4f12/service/java/com/android/ecm/EnhancedConfirmationService.java#493)还在特定开关启用且存在不可信进行中通话时，可能返回 `PHONE_STATE` 授权查询限制。它不是自动撤销已启用服务的证据；本机开关及当次状态未知，不为排障伪装助残工具，也不采集电话号码。
5. 未导出服务不是系统 UID 不能绑定的当然理由；[平台访问检查](https://android.googlesource.com/platform/frameworks/base/+/99b01a65cc4c104933788b3143285ab6bae65827/core/java/android/app/ActivityManager.java#5212)允许 system UID 访问。现有探针曾收到连接回调，不能因 `exported=false` 就盲改配置。电池保活也不能替代上述权限检查。

[Android 16 CDD](https://source.android.com/docs/compatibility/16/android-16-cdd) §2.6 规定平板继承 handheld 要求，例外标星；受限设置条款未标该例外，不因编号含 H 就豁免平板。

## 若以后需要设备补证据，优先区分这几条路径

| 同一时间轴上的最小观测 | 支持的方向 |
|---|---|
| ECM 查询确认应用级受限，或已确认的 allowed 被改回其他状态 | 前者支持应用级限制；后者只证明确认状态变化，还需查谁重置及最终查询结果。default 不一定受限 |
| ECM allowed、绑定 AppOp 非 allowed，随后登记缺失、enabled 删除 | 独立绑定检查与列表裁剪；仍需查拒绝的策略来源 |
| 明确 force-stop 在前、enabled 删除在后 | 停止清理链；仍需查谁发起停止 |
| enabled 保留，但进程退出/crashed/连接消失 | 普通断连或应用问题，不能算已证明权限撤销 |
| enabled 删除且写入归属为 safecenter，缺以上旁证 | 系统侧撤销成立，具体机制仍 unknown |

只收目标组件存在性、两个 AppOp 的枚举状态、回调/进程/force-stop 的顺序与原因、设置写入归属；不收节点正文、聊天内容、电话号码、联系人或完整应用清单。取不到的字段保持 unknown。本表是取证准备，不授权新运行；实际操作仍按现行固定 SHA、独占设备、现场就位和开跑令执行。
