## 4. r14 preflight（勘察已完成，可直接动手）

它不是换常量而是加新逻辑。源是 `preflight-a661f36-r13.ps1`（300938 B / 6550 行）——
preflight 渲染器在**上一轮 leaf** 上做增改，不走模板（r13 做了 3 次精确替换 + 1 次约 630 行大块插入）。

| 对象 | 位置（r13 leaf 内） |
|---|---|
| 四次只读 Git 调用 | `rev-parse`(2189) · `ls-files --stage`(2205) · `status`(4834) · `ls-files --modified`(5636) |
| 统一入口 | `Invoke-ReadOnlyGit`(1233–1613) |
| 主 try | **1839–5757**，catch 5701–5703，**finally 5704–5757** |

四次调用全在主 try 内 → 前置挂 2189 之前、后置挂进已有 finally，天然满足
「前置不过不启动 Git、后置即使 Git 失败也执行」。

**后置在 `finally` 里不能 throw**（会遮蔽 primary）。照 leaf 既有惯例：
`$gitRootExitNotObservedCount` 流程中累加、终态汇总断言（6044 行）——finally 只记结果，汇总里判死。

可复用 leaf 自带原语，不另起平行实现：`TL1C1bPreparedNotAuthorizedFileIdentityV1::Read()`
直接给出 `LinkCount`/`FileAttributes`/`FileSize`/`StableId`；另有
`OpenFileReadNoFollowDenyWriteDelete`、`EntryExistsNoFollow`、`Assert-Preflight`。
Git 信任树冻结值：`9576` / `4c5e585b…7458` / identity `9489` / hardlink group `85`。

## 7. 本轮新增的判据纪律（已进 [harness.md](../knowledge/brain/harness.md)）

1. **漂移门报警后先分「新增 / 修改 / 缺失」**——三者恢复路径不同，重装只治「修改」。
   更一般：**恢复手段本身也需要一次对照**。
2. **`exit 1` 至少要分「跑了并失败」和「根本没跑」**（`check.ps1` 的 `#Requires` 会在执行前拒绝）。
   **本轮还踩到反向的一次**：`gradlew.bat` 路径写错、命令根本没跑，却因管道吞掉失败而报 `exit 0`。
   两个方向都要防——**判据是汇总表/用例清单出现过没有**。
3. **待办条目写的「必须解决」要先落到具体文件行号**，落不下去说明描述本身要先修。
4. **「某字符串不在日志里」必须先证明该日志能被检索到已知在场的字符串**（对照先行）。
5. **`NotSigned` 在 MSYS2 载荷目录里是常态不是信号**；`-Content` 与 `-LiteralPath` 是两条不同验签通道。
6. **信任根不能放在别人会自更新的目录里。** 选址判据：**这个路径由谁写？**
   答案不是「只有本项目」它就会漂——`~/.cache/**`、包管理器目录、IDE 自带运行时、`%TEMP%` 均不合格。
7. **超长 STATUS 条目本身就是错误源。** 09-06 那条已达 4382 字符，里面正躺着一处过时指令
   （「用钉定 7.6.4 跑」，而 7.6.4 已不存在）。没人读得完的条目只会被整段搬运。
