## 本阶段准入与非目标

用户在设计阶段完成后要求“继续，推进并完成下一个大阶段的任务”。本阶段仅实现已有 getter 的诊断计数及结果传输，来源和反例已由上阶段核定。旧阶段“本轮不实现”不延长为永久禁止；视觉截图、pane、几何/同代与动作 producer 的准入仍未满足。诊断不消费这些未证来源。

分支 `codex/c1b-inventory-diagnostics`；不合 main、不新排 C 批次、不创建任务卡、不操作设备、不采图/OCR、不新增 getter，不回填冻结证据。完成离线实现不等于真机验收或 T-L1 通过。

## 实现与审查

- `C1bWindowInventory` 仅统计现有 `windows().toList()` 和七个短路点，不改变 getter 次序、预算、帧数或 v1 `toJson`。缺失/不一致的诊断不能由 controller 猜补；同一 `BoundFrame.request` 下组装封套，转义后仍受原输出上限约束。
- 主机新增严格解封和计数验证；保持旧 v1 完整校验及所有 run/APK/T0 绑定。外层和内层分别保留原文字节及哈希，收据显式升至 v2；旧裸 v1 不自动降级，新格式不改写历史。
- 独立审查发现 P1：诊断 capture_id 可携带 nonce，先落封套后检查帧绑定会泄漏原标识。已在任何摘要或 payload 保存前递归检查解码后的键和值，并补原文/Unicode 转义反例；源码复审关闭，动态验证纳入 runner 套件。
- 严格 JSON 实现发现标准解析器可能替换属性名中的孤立 surrogate；仅检查 GetString 不足。保留标准语法解析，补原始字符串转义的 Unicode 配对检查；65 项离线反例通过，不扩为通用 JSON 框架。
- Kotlin、validator/schema 和 runner 分别独立审查，除已修 P1 外无遗留阻断项。冻结 v1 schema、validator、fixtures、Android 读取适配器、Provider 与 Protocol 对基线无差异。
