## 官方格式依据

本次实际核对 AOSP `android-16.0.0_r1` 源码；这些依据说明上游可能的输出形式，
不证明平板 ROM、本机 ADB 或本轮安装器实际走了其中哪条分支。

| 源码边界 | 能确认的格式事实 |
| --- | --- |
| ADB `install_app_streamed`，L233、L237、L241–243 | 连接及文件复制可以直接失败；读取到的安装状态只要不以 `Success` 开头也会失败，没有先要求 `Failure [...]` 或安装状态码。[adb_install.cpp](https://android.googlesource.com/platform/packages/modules/adb/+/refs/tags/android-16.0.0_r1/client/adb_install.cpp#233) |

因此，非零安装退出不保证存在可提取的错误码；`install_failure_code=null` 也不证明原输出没有状态码。
现有严格解析会拒绝未知码、多处 `INSTALL_`、不完整或带装饰的失败行及控制字符。
例如路径或详情中的另一处 `INSTALL_` 也会触发歧义拒绝；这次保留该原有边界。

## 最小改动与诊断语义

改动位于 `scripts/lib/tablet-layout-c1b-adb-server.ps1` 的现有提取函数和受控客户端调用函数。
提取函数增加可选引用参数，仍返回原来的本地允许码或 null；原 27 码允许列表、大小写规则和失败行正则保持不变。
受控安装失败的安全 Message 增加 `install_failure_extraction`，值只来自以下固定常量。
非安装操作不输出此标签；结构化 `tablet-layout-c1b-private-adb-guarded-client-diagnostic/v1`
的 schema 与字段不变。

| 值 | 精确含义 |
| --- | --- |
| `not_attempted` | 未进入错误码提取。例如双流尚未完整排空、溢出、严格 UTF-8 解码失败或超时。它不要求已经观察到非零退出。 |
| `unsafe_control` | 合并双流含被禁止的控制字符；此检查优先于 token 数量及失败行检查。 |
| `no_status_token` | 通过控制字符检查后，忽略大小写的 `INSTALL_` 出现次数为 0。 |
| `ambiguous_status_tokens` | 通过控制字符检查后，`INSTALL_` 出现次数大于 1；不表示设备实际报告了多个故障。 |
| `frame_rejected` | `INSTALL_` 恰好出现一次，但完整失败行不符合原有受限语法。 |
| `unsupported_code` | 唯一失败行符合语法，但码不在原 27 码允许列表中；不输出捕获到的未知码。 |
| `recognized` | 唯一失败行符合语法，返回允许列表中的本地固定码。它不代表安装成功。 |

这些值解释提取流程，不是安装失败根因。不输出原始正文、路径、任意 token、输出内容 hash，
也不携带原内部异常的消息或调用栈；不改变安装参数、退出语义、输出上限、清理或一次性执行边界。
runner 继续接收安全异常 Message 并按原路径输出失败，未引入重试。
合同及操作解释见[失败合同](../contracts/tablet-layout-c1b-v1.md#失败与归因)和
[运行规程](../runbooks/T-L1-tablet-layout-c1b-v1.md#失败与冻结)。
