# C1b：Android 底层与安全中心静态归因（2026-11-01）

## 结论

**已从这台平板实际安装的安全中心 APK 找到一条完整候选机制：按前台页面临时删除特定无障碍服务的启用项，再安排可被取消或延期的恢复。它不要求 AppOp 拒绝，也不要求杀死目标进程。** APK 的内置默认配置开启该功能，并将整个系统设置包列为监控对象；候选服务还可能来自“未知分类”，不只限于已明确判为风险的应用。

这比通用的保活或受限设置解释更具体，但**尚未证明本项目在 11-01 命中该机制，也没有修复或放行 C1b**。当前有效配置、目标包的缓存分类/名单成员关系及实际 false/true 写入时间线仍未取得。下一步应验证这条机制的运行态前提，而不是重复开启、重装、保活或自动写回。

并行核对还确认：AOSP 有独立 DPM/快捷方式/登记裁剪路径；平台 UiAutomation 可不依赖同一持久启用列表，但它是不同观察来源，且原生 `uiautomator dump` 有服务抑制和明文输出，不能直接替代现 C1b。

## 3. 内置默认配置与候选条件

`n6.e.i()` 的 `localEntity` 来自 `z9.l0.g(context,name)`，原指令确认该 helper 用 `getAssets().open()`；这里的 local 是 **APK 内置资产**，不是已经读取了设备私有配置。

内置资产为 version 3、`accCtrlSwitch=true`、`recoveryDelayTime=8000`、`monitorPayApp=true`、`monitorThirdDesk=false`；`com.android.settings` 没有 activities 限制，因此按这份默认值可匹配该包任意前台 Activity。支付 App 还可能动态追加到 monitorApps；没有证据证明当前微信已被追加。

候选 observerApp 的原指令规则另行要求：缓存查询 `safetype <> 0`、路径通过排除条件、存在无障碍服务、`cloud==1`，以及 `safeLevel>0`，或 `safeLevel==-1` 且计数条件成立。计数条件为：

```text
installCntZero && installCount == 0 → true
否则：(install阈值<0 或 installCount<=阈值)
   且 (spread阈值<0 或 spreadCount>=阈值)
```

资产中阈值为 100 / 10，另允许 installCount=0。字段单位和该探针的实际缓存记录未读取，不能擅自解释为侧载次数、下载量或已判恶意；特别是未知分类也有进入候选的代码路径。

配置选择在 serverVersion≥localVersion 时优先 server，等版本也如此。server 实体可来自更新入参或另一文件读取；后者用字面相对文件名，不能自动等同 `n6.f` 保存的 filesDir 绝对路径。初始化和更新入口均可在 DEX 找到，但当前选中实体、开关和注册状态未观察。**内置默认值不等于当前有效配置。**

另有观察 enabled 列表、生成 FraudEvent、匹配本地风险脚本的代码；已读部分没有直接连到上述 setter，未继续扩大这条旁线。不能把观察到列表变化的事件上报倒因为其主动撤销的证据。

## 4. AOSP 补充排除与另一条观测路线

本节是公开源码研究，固定 frameworks/base `99b01a65cc4c104933788b3143285ab6bae65827`，不是 vivo 实现证明。

- [AccessibilityManagerService](https://github.com/aosp-mirror/platform_frameworks_base/blob/99b01a65cc4c104933788b3143285ab6bae65827/services/accessibility/java/com/android/server/accessibility/AccessibilityManagerService.java#L2969) 还会独立检查 DPM 允许名单；快捷方式 toggle、PM/声明权限/XML 登记失败后的裁剪也可删除 enabled 项。普通 binder death、UiAutomation 抑制本身则不要求删除持久列表。两个 AppOp allow 不能穷尽前置。
- [SettingsState](https://github.com/aosp-mirror/platform_frameworks_base/blob/99b01a65cc4c104933788b3143285ab6bae65827/packages/SettingsProvider/src/com/android/providers/settings/SettingsState.java#L1830) 的 packageName 是设置行归属：同值写回可改变它，reset 也可保留旧归属。标准 AMS 用 system context 持久化通常归属 android，safecenter 元数据提高其 context 参与写入的可能性，但不是完整调用历史或触发原因。零散当前行不能拼成删除时间线。
- [UiAutomationManager](https://github.com/aosp-mirror/platform_frameworks_base/blob/99b01a65cc4c104933788b3143285ab6bae65827/services/accessibility/java/com/android/server/accessibility/UiAutomationManager.java#L81) 使用受权限保护的临时测试登记，不靠同一第三方 enabled 列表；普通 APK 不能据公开 getter 推定可获得连接。它仍走 accessibility 窗口/节点链，vivo 对该路径的修改未知。
- [Android 16 DumpCommand](https://github.com/aosp-mirror/platform_frameworks_base/blob/99b01a65cc4c104933788b3143285ab6bae65827/cmds/uiautomator/cmds/uiautomator/src/com/android/commands/uiautomator/DumpCommand.java#L62) 实际支持 `--windows`，不能笼统认定只取 active root；但 wrapper 默认 connect 会抑制现有服务，XML 有明文且省略空 root/部分不可见节点，没有本项目等价完整性状态，因此本轮没有运行它。
- 后续独立只读 PoC 若获准，应显式 [DONT_SUPPRESS](https://github.com/aosp-mirror/platform_frameworks_base/blob/99b01a65cc4c104933788b3143285ab6bae65827/core/java/android/app/UiAutomation.java#L171)，仅观测并保留错误/时序；连接本身改变临时 AMS 登记，不能声称系统零副作用。UiAutomation 默认 tool 身份与原 probe 不同，[敏感 View 过滤](https://github.com/aosp-mirror/platform_frameworks_base/blob/99b01a65cc4c104933788b3143285ab6bae65827/core/java/android/view/AccessibilityInteractionController.java#L175) 可能导致读树差异；它不是既有微信 opaque 的已证实原因，更不建议把原 probe 伪装为助残工具。

因此，UiAutomation 值得作为不依赖持久服务的独立诊断候选，但没有新 producer、合同、构建或真机结果，不能回填现 C1b，也不能据此放行布局、P0 或生产执行。
