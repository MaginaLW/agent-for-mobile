## 离线定位与传输修复

公开 [ADB client 参考实现](https://android.googlesource.com/platform/packages/modules/adb/+/refs/heads/main/client/commandline.cpp)（本次读到 blob `5cd3ab66dd0a7ba0173b01f954fbe76c21269483`）的 shell stdin 路径，与 `copy_to_file` 显式设置 binary mode 的路径不同；[Windows sysdeps 参考实现](https://android.googlesource.com/platform/packages/modules/adb/+/f4ba8d73079b99532069dbe888a58167b8723d6c/sysdeps_win32.cpp)的管道读取走 CRT，存在文本换行转换边界。这是参考契约，不是本机 SDK 二进制分支核验。

两路独立离线检查均使用本轮归档 T0，真实设备/ADB/server 调用为 0：

- 用固定 f983 的实际 `Invoke-Process` 调用本地 UCRT `_read` 子进程，显式 text 模式把 683 个 CRLF 改为 LF：输出 20,975 字节，SHA-256 `218707757450e7659bca3d8d33bf225ede29ed82c418a771c3dbbe7657848e56`；binary 模式逐字节保持原输入。单行 Base64 ASCII 经 text 读取再解码，也逐字节等于原 T0。
- 既有编译的 Android Factory/Pending/Model 分别对两份数据保留各自原字节哈希，JSON 值相同；在所测 JVM 链中未复现提前擦零或别名问题。这能复现“语义锚点相同、artifact 哈希不同”，不能证明真机实际收到 LF 版本、设备失配值等于上述 LF 哈希或这是唯一原因。

新候选保持原 T0 文件、哈希及所有绑定校验不变，只将 stdin 编为无 BOM/换行的标准单行 Base64 ASCII，远端固定解码后交给 content：

```text
adb shell -T "set -o pipefail && toybox base64 -d | content write --uri '<URI>'"
```

`&&` 保证 pipefail 设置失败不进入管道，pipefail 保留解码端和写端的非零退出；任意 stdout/stderr 仍失败，状态绑定、一次写入、必要 abort 与无回退规则不变。解码器可能先送出完整有效数据再失败，不能据失败假定未创建会话。依赖远端 shell 的 pipefail 和 toybox base64；公开 [toybox 帮助](https://android.googlesource.com/platform/external/toybox/+/988e2e2ba7c9a7540de39bb77185f20c83da8eb6/android/device/generated/help.h)及 [mksh 选项](https://android.googlesource.com/platform/external/mksh/+/2e46594a0b7f5014d1a6751020dabe80e576c954/src/sh_flags.opt)只作参考，本机 ROM 能力仍待新轮验收，未知或不支持即失败。
