# 确认卡离线覆盖核对

日期：2026-11-11。基线 `3e93d9389f0e3fb9c8d0531587ca3f3e91d979d9`，开发分支 `codex/reduce-manual-offline`。承接[减少人工介入实施计划 §10](../specs/2026-11-11-减少人工介入总体思路-design.md#10-实施顺序与批次验收2026-11-11)批次 3；本阶段只补现有确认状态机的必要测试，不改产品行为，不产生新的确认通道或免确认权限。

## 关键转移与证据入口

| 判据 | 真实执行边界 | 当前 JVM 用例 |
|---|---|---|
| Allow 只执行当前一次调用 | `SafetyGate.execute` 在 confirmer 返回允许后重新取得 context、逐字段复核，再调用 executor | `SafetyGateTest`：`allowed confirmation with unchanged context calls executor exactly once`；本次新增 `a successful dangerous call never authorizes the next call`，同一个 gate 的第二次调用被独立拒绝，executor 总计仍为 1 |
| Deny 不进入动作执行 | `SafetyGate.execute` 的 `ConfirmationRequired` 分支直接抛 `E_BLOCKED` | `rejected confirmation never calls executor or failure recorder`、`after confirmation hook never runs after denial`；两档风险和无标签点击另有门前拒绝用例 |
| 确认超时安全终止 | `ConfirmOverlay.ask` 超时抛 `E_CONFIRM_TIMEOUT`，SafetyGate 不执行 executor | `confirmation timeout never calls executor or failure recorder`；这是 confirmer 抛错后的门行为，不是 Android 计时器/窗口清理证明 |
| Stale 与 context recheck | `SafetyGate.validateContext` 绑定 package/activity/身份来源、目标字段、焦点/输入/会话证据，revision 不单独构成 stale | `SafetyGateTest` 已有参数变异、前台/身份/焦点/输入/准备目标/几何变异及 revision 正控；本次新增 `context reacquisition failure after approval terminates as stale without execution`，第二次 context 获取异常变为 `E_STALE_REF`，stale 记录一次，executor/成功回调均为 0 |
| Reentry 与旧批准不可重放 | `UiMutationCoordinator.runExclusive` 串行保护 mutator；`ConfirmApprovalArbiter` 绑定确认编号/nonce、唯一 future，close 只关闭自身确认 | `UiMutationCoordinatorTest.second mutation cannot enter while first waits for human confirmation`；`ConfirmApprovalArbiterTest` 的旧回执、错 ID/nonce、关闭、并发双决定和旧 close 不影响新卡；本次成功后新调用再次确认用例补齐“成功决定不复用” |
| 首帧与证据就绪前不启用按钮 | `ConfirmationReadinessGate` 要求 draw 与 frame commit 均完成，再进入证据就绪和按钮启用 | 已有 `evidence cannot start before hardware frame commit`、`buttons cannot enable until evidence is ready`、两个 draw/commit 时序正控与超时反例 |
| 任何阶段失效后不复活 | `ConfirmationReadinessGate.fail` 进入 FAILED；迟到绘制/提交/证据事件不能重新启用 | 本次新增 `failure from every reachable state rejects all late readiness events`，枚举九个可达状态，分别 fail 后检查 register/draw/commit/beginEvidence/evidenceReady/enableButtons 与重复 fail |
| 失败即终态，不把纵深计数器当重试许可 | `StaleReconfirmGuard` 类注释及站规明确当前重弹路径不可达 | `StaleReconfirmGuardTest.exhausted fallback follows the station rules instead of contradicting them`；本次没有新增自动重试或重弹逻辑 |

上述测试路径分别位于 `app/gateway/src/test/java/dev/magina/gateway/core/` 与 `overlay/`；源实现位于同名 `src/main/java/` 包。新增用例仅使用 JVM 内的决定和假 context，不操作设备，不自点 overlay；不能视为真正的人控批准证据。

## 实际修改及验证状态

- `SafetyGateTest.kt` 新增 2 项：成功决定不复用、批准后的 context 重取失败。
- `ConfirmationReadinessGateTest.kt` 新增 1 项：九个状态失效后所有迟到事件都不复活。该枚举只证明终态不复活，不声称穷举 Android 回调并发、WindowManager 或 ROM 全过程。
- 子代理只完成静态核对和 `git diff --check`，没有运行 Gradle；编译与实际 JVM 结果由主 A 的单实例检查补充。不能把未运行的用例计为通过。
