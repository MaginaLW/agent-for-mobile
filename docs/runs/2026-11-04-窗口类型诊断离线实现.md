# 窗口类型拒绝值诊断离线实现

日期：2026-11-04。起点 `90211388f7b585629e353bb25696209fcd542a57`，开发分支 `codex/c1b-type-diagnostics`。本阶段承接[前轮真机结果](2026-11-04-诊断后验与窗口采集.md)，实现[类型拒绝值诊断](../specs/2026-11-04-窗口类型拒绝值诊断-design.md)；未改旧证据、未重新调用设备或签名凭据。

## 依据与改动

`0..255` 随原 model/probe/schema 引入，是项目 wire 边界，不是 Android 官方范围保证。官方 API 返回 int；Android 16 固定 tag 的 AOSP getter/setter/Parcel 直接传递整数，窗口类型转换未匹配分支可返回 -1；类型 7 已在本项目映射中。来源、固定 tag 与 Gitiles 访问限制见设计中的官方链接。该查阅不证明 PA2553 前轮实值为 -1 或确定 ROM 原因。

新 producer 仅输出 `tablet-c1b-inventory-result/v2`，每帧增加 `rejected_type_code_counts`：仅复用原 getter 成功返回但范围门拒绝的 signed Int32，聚合为严格升序、无重复、最多 16 项的频次表，count 正且总和必须等于 `window_type_invalid`。不保存 ID、枚举位置、包名或跨帧关联，不继续读取已拒绝窗口的后续字段。

原 observation/c1b-v1、旧 v1 封套 schema、Android adapter、窗口拒绝/截断、拓扑与 IME 判据均未改。范围内未知类型仍保留为 unknown 并阻断相应能力；越界类型仍丢弃。消费者只接受新 v2，拒绝旧封套，不迁移历史结果。新文件名为 `tablet-c1b-inventory-result-v2.json`；run 收据保持 v2，字段含义不变，result_schema 显式指新封套版本。

实现按 Kotlin producer、PowerShell consumer/schema、runner 三个不重叠范围并行；主协调串行运行共享测试与构建。独立只读复审核对原 getter 次数/顺序、不可变快照、整数边界/Long 求和、闭合解析、绑定后守恒、隐私与历史版本，未发现 P1/P2。
