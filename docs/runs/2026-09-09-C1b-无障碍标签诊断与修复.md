# C1b 无障碍标签诊断与修复

用户在 `8b3bb5d` r2 返回 `needs-user` 后回复“开启了”。这记录设置页当前已开启的用户报告，
不直接证明系统已绑定服务，也不能补齐 r2 当时缺失的原始采样。
本轮将源码修复与现存安装的只读诊断分别记录；r2 保持原终态，无生产 r3。

## 已确认的源码缺陷

C1b 应用名称为“平板 C1b 只读探针”，服务没有单独覆盖 label；共享 C1a 检查却固定接受
旧名称“执行网关”。用精确 enabled component 与只含新标签的 Bound section 调用原函数，
实际得到 `Enabled=true / Bound=false / Ready=false`；换旧标签或精确组件后则全为 true。
这是可独立复现的假阴性，不依赖延长等待时间。

[AOSP 服务 dump](https://android.googlesource.com/platform/frameworks/base/%2B/HEAD/services/accessibility/java/com/android/server/accessibility/AbstractAccessibilityServiceConnection.java)
通过 `ResolveInfo.loadLabel()` 输出服务标签，Bound 记录可能不含组件；
[AOSP 用户状态](https://android.googlesource.com/platform/frameworks/base/%2B/a21de19/services/accessibility/java/com/android/server/accessibility/AccessibilityUserState.java)
分别保存 Enabled、Binding、Bound 和 Crashed。开关已开启不能代替 Bound 证据；Bound 也不等于采集完成。
项目已有手机标签格式经验，见 [Android 公共知识](../knowledge/android/common.md)，本次修复将实际 C1b 标签传至共享判据。

共享 `Test/Wait-TL1C1aA11yReady` 新增可选 `ExpectedLabel`，默认继续使用 C1a 标签；
C1b runner 明确传入其应用标签，保持 enabled 精确组件唯一命中和 Bound section 范围。
readonly AST 门同步 runner token pin，并要求该参数为精确字符串字面量。
没有改等待时限、设备设置或 needs-user payload schema。
