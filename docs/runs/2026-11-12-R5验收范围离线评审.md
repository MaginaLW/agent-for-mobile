# R5 验收范围离线评审

日期：2026-11-12。核对基线 `9dd102a51e2e5e40f07b71c8fb70d29794ea16a2`。本轮读取现有协议、验收设计、源码及测试，不运行设备、Intent、ADB、派单、构建或测试，不修改产品代码。本报告中的方案是供决定的建议，不改变现行验收判据、许可、队列或 R5 的未验证状态。

## 1. 评审结论

R5 有两个需要分别验收的命题：生产实现没有取得规定的正向落地证据时，必须报错；真实目标在指定时间范围内没有落地，且这一反例确实由本次调用触发。前者是程序的知识状态，后者是外部世界的状态。`E_VERIFY_FAIL` 不能独立证明后者。

现行生产路径已经调用前台验证，并将已知目标的非 `true` 结果映射为 `E_VERIFY_FAIL`。本轮没有发现可静态确认、需要立即修复的新缺陷，也没有发现通过新增纯判据测试就能补齐的决定性缺口。缺少的是实际 Android 调用及轮询分支的可辨识证据，以及现行强负向验收所要求的独立来源。不能用扩写测试、增加应用侧日志或重跑已有正例关闭 R5。

建议将待决定事项具体化为：是否接受先独立验收“真实 gateway 调用在未获正向证据时不误报 verified”，把“第三方目标全窗口从未落地”的强命题继续保留为未验证项。此取舍不必改变生产协议，但会改变当前验收设计的完成范围，须明确决定并同步相应设计后，才能实施最小观测候选或建运行卡。若要求两者同时完成，现有标准系统来源路线仍为 NO-GO。

## 4. 两条后继路线与明确取舍

| 路线 | 可以完成的交付 | 成本与停止点 |
|---|---|---|
| A：维持现行强负向合同 | 继续保留 R5 未验证；只有本次请求桥接、实际窗口、独立接收、完整覆盖与隐私限域均有可验证方案时，再核观测候选 | 标准 events 及 START+WM/transition 已核定缺请求桥接键；不重搜同字段、不采元数据试运气，不引入 root/隐藏接口/新特权 |
| B：显式拆分验收命题，先验产品失败语义（建议） | 为真实 gateway 已分派调用建立有限可观测链，证明未取得正向证据时响应与审计为 `E_VERIFY_FAIL`、不报告 verified、无自动 fallback/重发；强负例另保留 | 必须先决定改变验收完成范围。仅内部观测不能让强命题通过；真实第三方冷启动反例仍未证，不能把较窄子项完成写成原 R5 整体完成 |

不推荐把 `am start -W` 换成测试入口、用自有回执冒充第三方系统接收、关闭无障碍来制造所需原负例，或先添加 nonce/Provider/全系统 trace。既有调用和轮询足够定位建议的最小观测位置，没有必要先造通用事件系统。

### 可采纳的最小设计补充文字（提案，未生效）

建议仅在 11-01 强取证设计的“结论与范围”和 Mika 任务 4 增加以下补充；不改原 R5 完成标准或 M1 生产协议：

> R5 的真实调用验收分别记录“产品失败语义”和“第三方未落地反例”。前者证明原 gateway 路径在指定目标且未获规定的正向证据时返回 `E_VERIFY_FAIL`，响应、审计和实际验证分支相符，无误报 verified 或自动重发；不声称目标从未接收或从未出现。为核验该子项，允许先评审限于现有分派/轮询路径的最小内部观测候选，不再以系统四项独立来源全部成立作为该候选设计的前置；候选实施、固定构建、队列、现场就位和本轮运行许可仍分别满足。
>
> 第三方未落地反例继续保留原要求：原 gateway 的合法请求启动无异常，但目标未落地；现行唯一请求关联、独立系统接收、实际验证窗口及完整覆盖/丢失检查四项仍适用于这一事实声称。`no_a11y`、纯函数 `false`、参数拒绝、无接收方、原生异常、自有目标正例和有限快照均不能替代该反例。两个子项未都完成时，R5 整体保持开放；任何较窄子项通过均不放行生产接线或其他安全验收。

这段提案实际只解除“先做产品语义最小观测设计也必须等系统独立来源”的依赖，不删除第三方反例、不取消它的强证据门、不增加运行权限。采纳后能推进一个可实现子项，**仍不足以关闭 R5**；若目标是完整 R5，必须另提供强来源或明确改变原反例/事实声称范围，不能悄悄把 no-a11y 改称原反例。当前没有可直接承诺关闭完整 R5 的更小合同调整。

## 5. 路线 B 的最小真实验证方案（尚未批准实施或执行）

这份方案不是新运行卡，也不包含次数、时限或设备的许可。若选择路线 B，先将下列事实范围与原强设计的保留缺口写入相应设计并完成适用评审；之后才按队列、固定 SHA/制品和就位报告取得本轮运行许可。

最小代码范围只考虑在现有 `intentSend` / `waitForegroundLanding` 周围保留本次调用的内部研究观测：进程/启动实例与调用 ID、应用入口实际调用及正常返回/异常分类、实际轮询单调起止、实际检查次数、终止类别 `no_a11y` / `hit` / `timeout`。已知目标、最终 package/Activity 判据与原响应/审计必须对应同一次调用。既有生产响应、Intent 参数、3000 ms/200 ms 行为、权限、判据及重试策略不变；不增加系统接收或全窗口覆盖字段，不采 URI/标题/聊天正文来充当关联。具体承载和测试范围在候选设计时决定，本报告不规定新接口或有效 schema。

内部观测只能解释被测代码实际走了哪条分支；不是独立的世界状态证明。观测丢失、实例/调用错绑、审计缺失、实际未触达或退出原因不明，一律记未验证，不补算为超时。时钟只用同一设备单调域分析内部先后，不与宿主/系统日志按近似时间拼成独立关联。

| 场景 | 有限真实调用须得到的结果 | 验收声称与反例限制 |
|---|---|---|
| 合成导航正例 | 真实 gateway 一次调用，正常分派，按已有包/Activity 规则命中，响应 verified 与审计/本次观测一致；另有实际页面核对 | 只证明该固定环境/受控目标；优先复用仍可核的既有正例，缺少本次观测不能回填旧轮 |
| 原第三方候选未获正向证据 | 合法且经许可的原入口正常返回，实际轮询未命中且有确定退出原因，响应及审计 `E_VERIFY_FAIL`，没有 verified 或第二次分派 | `timeout` 只证明检查均未命中；`no_a11y` 只证明没有可用正向来源。两者均不证明目标从未出现，也不能互相冒充 |
| 无接收方/参数拒绝/原生调用异常 | 分别保留真实错误及是否触达，不进入负例通过 | `E_NOT_FOUND`、白名单拒绝、无效 component、调用前安全门拒绝不是所需“正常分派后未获正向证据”反例 |
| 指定组件只到同包其他页 | 不得以包名相同报 Activity verified；只有登记落地页或精确组件命中才算成功 | 若实际页面不可独立辨识，结果未验证；不凭猜测类名填写分享白名单 |
| 无指定目标 | 真实调用如实 `dispatched_unverified`、验证字段不冒充正向成功 | 不构造未知目标样例去替代已知目标失败路径；是否值得新运行须由验收缺口决定 |

第三方候选继续沿用既有设计中的小红书只读导航候选，而不是另换 shell 或自有目标：`VIEW` + `xhsdiscover://search/result?keyword=test` + `com.xingin.xhs`，无 component/extras。可能联网搜索，当前设备是否安装、可接收、能复现负例和隐私范围均未核实。本轮不查询设备、实发或创建任务卡；未来不满足许可/现场/固定身份即停止。若唯一调用正常落地，记录“正例/负例未触达”，不得现场改参数或多发到出现失败；无接收方、异常、结果未知同样冻结，动作副作用不因验收失败而被推定为零。

即使上述产品语义子项通过，下列仍不能声称：系统独立接受了这次请求、原第三方在整个实际窗口从未出现、目标业务页正确、平板 pane 或 T-L1/P0 通过、任何分享/消息已完成、允许重发、生产语义意图已接线。
