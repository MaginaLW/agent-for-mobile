## 传输契约复现：已知事实与限制

原会话末尾按 [AOSP commandline.cpp](https://android.googlesource.com/platform/packages/modules/adb/+/refs/heads/main/client/commandline.cpp) 及 [escape_arg 实现](https://android.googlesource.com/platform/packages/modules/adb/+/refs/heads/android14-release/adb_utils.cpp) 设计离线复现。现有 `New-C1bUri` 给 URI 手工加单引号，`shell` 的参考路径按原样连接参数，远端 shell 可消耗该引号；`exec-in` 的参考路径会再用 `escape_arg` 包裹参数，使原有外层引号成为 URI 的字面字符。参考 `exec-in` 路径也不提供远端 stdout/stderr 与退出状态的同等判据，因此本地主机写入完成不能证明 provider 接收。

已保存的复现直接提取实际 runner 的 `New-C1bUri`，只用合成输入，调用现有 Git bash 的独立 POSIX 解析器观察参数；9 项检查全 true、8 次本地 shell 调用、0 ADB/设备/凭据调用。原始结果及脚本已绑定哈希，本次收尾只复核它们，没有重跑一次性脚本。现有 fake ADB 将参数连接后统一去掉 URI 引号，遗漏了 `exec-in` 特有的再次转义层。

这证明参考传输契约下存在实质问题，尚未证明本机 SDK 二进制与所引源码完全一致、任一真机失败轮实际远端分支或远端错误原文。SDK 元数据为 `37.0.1`，不能仅据版本推出实现等同。e673 的信息保留修复没有解决本次真机故障，但也不能因此断言它的离线修复无效。
