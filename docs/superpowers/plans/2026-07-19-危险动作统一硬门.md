# 危险动作统一硬门 Execution Plan

> **For agentic workers:** REQUIRED EXECUTION FLOW: Use `subagent-driven-development` to execute this plan task-by-task when subagents are available. If no subagent capability is available, execute inline with the same task checklist and review checkpoints.

**Goal:** 让所有静态 D 级和首批动态危险动作在统一路由层机械确认，消除 `press_key(enter)` 等旁路，并以测试证明未经确认绝不执行。

**Approach:** 先建立纯 JVM 的失败测试，固定风险判定、确认结果和“handler 最多一次”不变量；再新增纯 Kotlin 安全核心并接入 `ToolRegistry`，把 `ui_action` 的局部确认和松散 `confirm` MCP 工具收敛到同一执行门。最后同步安全知识与项目状态，完成单测、debug 构建和静态旁路检查；真机 smoke 单独等待用户连接与 gateway 派单通道就绪。

**Materials:** `docs/specs/2026-07-19-危险动作统一硬门-design.md`；`app/gateway/src/main/java/dev/magina/gateway/mcp/ToolRegistry.kt`；`app/gateway/src/main/java/dev/magina/gateway/tools/UiTools.kt`；`app/gateway/src/main/java/dev/magina/gateway/overlay/ConfirmOverlay.kt`；`app/gateway/src/main/java/dev/magina/gateway/core/SkillPack.kt`；`app/gateway/src/main/assets/skillpack/safety.json`；`STATUS.md`。

**Validation:** `:gateway:testDebugUnitTest`、`:gateway:assembleDebug`、`git diff --check` 全部通过；测试覆盖拒绝/超时/上下文变化不执行、批准只执行一次、静态 D 自动拦截、`press_key(enter)` 动态升级及发送白名单失效；真机验证未执行前必须明确标为待验。

- [x] **Step 1: 增加本地单测依赖**

在 `app/gateway/build.gradle.kts` 增加 JUnit 4 与可在 JVM 运行的 `org.json` 测试依赖，不新增生产依赖。

- [x] **Step 2: 写出预期 API 和失败测试**

测试固定以下行为：

- `Level.D` 始终需要确认；普通 R/W 默认放行。
- `press_key(key=enter)` 需要确认，`back/home/del` 放行。
- `ui_action` 命中“发送/删除/支付”时需要确认；出现“文件传输助手”上下文也不能免确认。
- confirmer 拒绝或抛 `E_CONFIRM_TIMEOUT` 时 executor 调用次数为 0。
- confirmer 允许且上下文未变时 executor 恰好调用 1 次。
- 前台包/Activity 或动态目标签名变化时返回 `E_STALE_REF`，executor 调用次数为 0。
- 安全拒绝、超时不调用失败记录回调。

- [x] **Step 1: 实现纯 Kotlin 风险模型**

创建可在 JVM 测试的 `SafetyPolicy`、`SafetyAssessment`、`SafetyContext`、`TargetEvidence` 与 `SafetyGate`。`SafetyGate` 通过注入的 confirmer、上下文读取器、executor 和审计/失败记录回调工作，不直接依赖 Android UI。

- [x] **Step 2: 接入统一执行顺序**

在 `ToolRegistry.call()` 中按设计执行：敏感 App 黑名单 → 风险判定 → 人工确认 → 上下文/目标复核 → retry guard → handler。所有 `Level.D` 自动进入硬门；安全拒绝、确认超时和上下文失效不记入 retry guard。

- [x] **Step 3: 收敛动态危险规则**

- 将 `press_key(enter)` 升级为动态危险动作。
- 将 `ui_action(click|long_click)` 的危险词判定接入统一门，handler 内不再自行弹窗。
- 移除发送白名单的执行器侧放行效果；`文件传输助手` 上的“发送”仍需确认。
- 确认后重新获取前台包/Activity；带目标的动作重新解析并比较目标文本、描述、bounds 与来源。

- [x] **Step 4: 收口确认工具面**

从 `ToolRegistry` 删除独立 `confirm` MCP 工具；`ConfirmOverlay` 只作为内部 confirmer。同步工具说明，确保模型无法用自由文本确认授权另一动作。
