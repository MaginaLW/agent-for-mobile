# D1 前台窗口归属修复 Execution Plan

> **For agentic workers:** REQUIRED EXECUTION FLOW: Use `subagent-driven-development` to execute this plan task-by-task when subagents are available. If no subagent capability is available, execute inline with the same task checklist and review checkpoints.

**Goal:** 确认悬浮卡的窗口事件不再污染网关记录的前台 App/Activity，同时真实切换应用或页面仍会被安全门判为上下文变化。

**Approach:** 先把“窗口状态事件必须属于当前活动 APPLICATION 窗口”抽成可离线验证的纯 Kotlin 规则并做红绿回归，再让 `GatewayA11yService` 复用该规则。前台身份显式区分 Known/Unknown；窗口归属尚未确认时所有非只读工具由统一 `SafetyGate` fail-closed。最后运行全量 JVM 测试和 debug 构建，并只更新与该缺陷直接相关的状态与 Android a11y 知识。

**Materials:** `STATUS.md`、`app/gateway/src/main/java/dev/magina/gateway/a11y/GatewayA11yService.kt`、`app/gateway/src/main/java/dev/magina/gateway/overlay/ConfirmOverlay.kt`、`app/gateway/src/test/`、`docs/specs/2026-07-19-危险动作统一硬门-design.md` §4.3。

**Validation:** D1 回归测试先在旧实现上失败、修复后通过；测试同时证明 overlay/IME/inactive 事件不更新身份、乱序窗口事件可安全复核、Unknown 前台允许只读但拒绝所有非只读工具；`:gateway:testDebugUnitTest`、`:gateway:assembleDebug` 和 `git diff --check` 均成功。真机允许腿与失效腿仍必须通过受控派单另行验证，离线通过不得冒充真机通过。

- [x] **Step 3: 实施单一根因修复**

`TYPE_WINDOW_STATE_CHANGED` 只有在事件 `windowId` 属于 `type=TYPE_APPLICATION && isActive` 的窗口时才更新前台包名和 Activity；可用 focused APPLICATION 作为无 active 时的保守后备。只有事件窗口尚未出现在窗口列表时才暂存一次候选，并由紧随其后的 `TYPE_WINDOWS_CHANGED` 复核或消费；已知 inactive、网关 overlay、IME 和其他非应用窗口必须立即忽略。前台身份包含来源 windowId 并显式区分 Known/Unknown；当前活动应用窗口与已接受身份不一致时解析为 Unknown。`ctx()` 的 package/activity/known 必须来自同一解析快照，不能拼接旧 Activity。

统一 `SafetyGate` 在策略评估和确认之前检查 `SafetyContext.foregroundKnown`：`Level.R` 仍可用于诊断，任何 `Level.W`/`Level.D` 在 Unknown 时返回 `E_BLOCKED`，不显示确认卡、不调用 executor、也不记录为执行失败。`ToolRegistry` 必须把 a11y `ctx.foreground_known` 传入 `SafetyContext`。
