# Agent 主控监督式真机跑测 Execution Plan

> **For agentic workers:** REQUIRED EXECUTION FLOW: Use `subagent-driven-development` to execute this plan task-by-task, with a fresh implementer followed by spec and quality review for each task.

**Goal:** 将 P0 安全硬门真机验收改造成 agent 全程准备、派单、取证和判定，用户只在手机旁监督并点击真实确认卡。

**Approach:** 保持业务动作只能经 `dispatch.ps1 -> gateway MCP -> ToolRegistry -> SafetyGate -> executor`；把可重复的设备准备、微信测试态导航、证据拉取和语义判定放进 PC runner。调试构建提供受限且不可用于确认决定的测试控制面，release 构建不包含可用测试钩子。所有危险动作仍由真人在系统确认卡上作出允许/拒绝决定。

**Materials:** Kotlin/Android AccessibilityService、PowerShell 7、Gradle/JUnit、现有 dispatch harness、ADB（仅设备准备与取证）。

**Validation:** 新增纯 JVM 单测和 PowerShell 离线契约测试；运行 gateway 全量 JVM 测试、debug/release 构建、脚本解析检查、diff-check 与敏感信息扫描。开发会话不直接操作手机。

## Task 4：PC provisioner 与监督式 runner

**Files:**

- Create: `scripts/lib/p0-device-provision.ps1`
- Create: `scripts/run-p0-safety-smoke.ps1`
- Create: `scripts/tests/p0-supervised-runner-offline.ps1`
- Modify: `.gitignore`

**Steps:**

1. 先写 PowerShell 离线契约测试，使用 fake adb/fake dispatch 覆盖 Allow、Stale、失败即停、超时、证据缺失、敏感字段脱敏、清理恢复。
2. provisioner 负责设备发现、APK 安装/升级、无障碍与 IME 检查/引导、进程与端口准备、通过 `run-as` 同步私有 token；命令和错误不得打印 token。
3. runner 提供 `-Legs Allow,Stale -Executor gateway -Provision`；顺序运行且不重试，每 leg 创建唯一 run id/slug，写入一次性 debug 控制文件后只通过现有 `scripts/dispatch.ps1` 派单。
4. runner 轮询只读确认状态，提示用户只需在手机上点击确认卡；自动拉取确认卡截图、dispatch trace、gateway audit 与 manifest。
5. 语义判定：Allow 必须确认输入证据匹配且发送后置条件成立；Stale 必须真人先允许、随后真实返回 `E_STALE_REF` 且没有发送后置条件。任何缺证、超时或不一致都失败并停止后续 leg。
6. `finally` 清理控制文件、端口与临时状态，并尽量恢复原 IME；证据只写入 gitignored `docs/runs/evidence/<run_id>/`，manifest 不含 token 或输入明文。
7. 运行 `pwsh -NoProfile -File scripts/tests/p0-supervised-runner-offline.ps1`，并对两个新脚本做 PowerShell AST 解析检查。
