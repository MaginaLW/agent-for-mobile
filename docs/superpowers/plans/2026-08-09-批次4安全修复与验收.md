- Preserve and finish: `scripts/tasks/p0-safety-reentry.tmpl.md`

- [x] **Step 1: 固化七组失败用例**

  Add tests that prove the old implementation is unsafe or inconsistent:
  - redirected stdin containing `CONFIRM` must be rejected before consuming a pause file or starting a child process;
  - `TimeoutMin` values below 1 or above 60 must fail before any ADB/executor process starts, and any exception after process start must still terminate the whole child process tree;
  - a gateway pause containing `E_VERIFY_FAIL` after a dangerous call must not enter leg 2;
  - a standalone dispatch must not overlap runner provision, inter-leg work, or teardown on the same device lease;
  - Reentry must fail when independent observation never confirms away, when restoration fails, when dwell is outside 60–90 seconds, or when gateway wait does not cover the independently observed dwell;
  - task templates must accept multiple overlapping OCR boxes only when every normalized match represents the same marker, matching the runner's mechanical policy.
  - when stdout, stderr, trace, audit, ledger or manifest contains a fixture secret, failure handling must leave no copy of that secret in any known persistent artifact, including `docs/runs/ledger.csv`.

- [x] **Step 2: 修复根因**

  Implement:
  - fail closed when stdin is redirected/non-interactive; do not treat `Read-Host` as human identity without that guard;
  - validate `TimeoutMin` as 1..60 before side effects, and terminate the entire executor process tree on timeout or any post-start exception;
  - replace the incomplete safety-code denylist with a positive, structured proof that no dangerous gateway call has occurred before `[AWAIT_CONFIRM]`; if legacy pause data cannot prove this, reject it;
  - introduce one device-level lease held across the runner's full lifecycle; child dispatches must inherit/recognize the owner token instead of deadlocking or reacquiring independently;
  - start Reentry dwell only after independent ADB observation confirms the target App is away, require 60–90 seconds, require restoration, and make all three facts hard verdict inputs rather than warnings;
  - align both task templates with the existing semantic multi-box verdict;
  - on sensitive-output detection, delete or irreversibly sanitize every known affected artifact and replace required records only with a non-sensitive tombstone; never preserve a secret-bearing ledger row merely to report failure.

- [x] **Step 3: Verify the output**

  Check:
  - `pwsh -NoProfile -File scripts/tests/dispatch-offline.ps1`
  - `pwsh -NoProfile -File scripts/tests/p0-supervised-runner-offline.ps1 -ShardCount 3 -ShardIndex 1`
  - repeat shard indices 2 and 3

  Expected: all new negative cases fail on a recorded pre-fix control or equivalent isolated reproduction, then pass after the implementation; no phone access; no real dispatch.

- [x] **Step 4: Record the result**

  Report changed files, test counts, root-cause-to-fix mapping, and any compatibility decision for legacy pause documents. Do not commit.
