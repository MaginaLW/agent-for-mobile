# 无真机开发与验证

无设备环境可以完成脚本回归、纯 Kotlin/JVM 单测、Android Lint、APK 构建与静态检查。
这些结论不替代确认卡点击、ROM 行为、微信落地页与平板布局的真机验收。
当前待办与候选以 [STATUS](../../STATUS.md) 和 [backlog](../backlog.md) 为准。

## 验证尺度与复核

局部修改先运行受影响的专项检查；纯文档核对引用、现行结论和 diff，派单提示词/模板变更覆盖真实组装与配置消费路径。
完整发布或真机验收候选必须完成项目要求的全量门，专项结果不能冒充完整候选通过。
A 整合子代理结果时核对代码 SHA（有未提交改动则同时核对输入差异）、配置、环境、命令、退出码和可追溯日志；
独立复核不要求机械重跑同一套检查。出现新改动、失败、证据缺失或覆盖缺口时补验。
用例/套件数从本轮真实汇总读取，不以历史“五项”或某个固定总数判断所有检查均已执行。
冻结候选按下面的专用顺序执行；通用复核不覆盖冻结限制，C 的回报也不触发额外构建。

C1b 的 build-environment 离线套件也使用宿主全局构建互斥锁，不能与持有该锁的真实 C1b 运行并发。
遇到“canonical trust tuple 已由另一进程持有”时，记录为环境冲突并与持有者协调；
不要结束其他任务、改 mutex 或绕过门来求绿。相关专项可继续验证，整合门仍记未通过，不能把未执行的断言算作通过。
确认锁释放后，用同一钉定 PowerShell 单独运行 `scripts/run-tablet-layout-c1b-offline-gate.ps1`，
核对进程 exit 0 与本轮新生成的 summary，再追加补验结论；原失败日志保留，不改写成原整合门通过。

## 一键检查

在仓库目录用项目钉定的 PowerShell 运行（当前为 7.6.5）：

```powershell
& '<repos-root>/_toolchain/powershell-7.6.5/pwsh.exe' -NoProfile -File scripts/check.ps1
```

脚本要求 PowerShell 7.5 以上；旧版本会在正文执行前拒绝，只有退出码不能证明检查跑过。
先核对输出中的仓库路径，再看末尾汇总。完整日志在被忽略的 `.checks/`。
`-SkipGradle` 可用于纯脚本开发迭代，但结果会明确标记 Kotlin/Android 未验证。
普通全量检查会生成 probe module build output；需要固定 C1b build-only 候选时，必须先完成全量检查，
再按该候选规程处理已知构建产物并冻结 preflight，冻结后不再运行 Gradle/check。

Windows 必须允许创建符号链接，才能真正运行 C1b verifier 的文件链接和目录链接两条反例。
可在 Windows 开发者选项开启开发者模式，或使用具备该特权的终端；脚本不修改系统设置。
子套件可记录 `17 passed / 2 skipped` 便于定位环境问题，但聚合门会拒绝将跳过记为通过。
子套件报告的 PowerShell 版本必须与启动它的父进程一致，不再另外硬编码一个会过期的版本。

监督式 runner 的汇总必须有非零用例且零失败；并行运行还会检查每片身份、总数和覆盖数一致。
缺少某片结果、重复分片或空跑均会让检查失败。汇总消费逻辑自身的反例也纳入 `check.ps1`。

Windows CRLF 检出也须通过完整门。候选生成测试仅统一合成 fixture 的换行，再实际覆盖 LF/CRLF；
verifier 的源码集合审计接受 CRLF 行尾，仍严格拒绝额外 namespace。派单固定 wrapper 编码前使用 LF，
避免换行膨胀触及进程命令行长度限制；用户 payload 不作此转换。
这些处理不允许归一化冻结输入后冒充原始字节 hash 相同，见[本轮修复记录](../runs/2026-09-08-C1b-新候选主机准备.md)。

C1b 主机聚合门的子进程失败沿用有界脱敏诊断，stdout/stderr 分别最多 4096 字符。
完整 host 模拟套件使用固定测试入口和当前 PowerShell，统一 600 秒编排预算；
native exit 与两条输出流 EOF 必须都在该预算内，单流捕获硬上限仍为 1 MiB。
helper 与固定入口分别将 PowerShell 位置及 native 工作目录绑定到测试仓库；
E2E 合成程序编译使用 UTF-8 输出和既有有界失败捕获，避免编译错误正文被上层赋值丢失。
外层使用限额 64 的 kill-on-close Job 管理离线进程树，内部 private-ADB Job 限额不变。
summary 的最大跨度与 gate 实测耗时共用 600 秒；2 分钟新鲜度和 15 秒时间包络不变。
该调整依据 [b362639 的完整门时间线](../runs/2026-09-12-C1b-b362639-主机验收与真机入口.md)，
只影响整套纯离线测试的总预算，不改变单 runner 的 180 秒或任何设备操作时限。
退出码、覆盖项和汇总仍须全部满足；子套件另次诊断通过不能覆盖原完整门失败。
缺失的原始失败细节须明确记录；固定候选与已消费正式 Stage 继续遵守各自重跑边界。

## Kotlin 函数指标

```powershell
# 首次省略 -Offline，下载并校验锁定的独立 detekt JAR；已有缓存后可完全离线运行。
& '<repos-root>/_toolchain/powershell-7.6.5/pwsh.exe' -NoProfile -File scripts/measure-kotlin.ps1 -Offline
```

此命令同时跑内置语法树反例和全仓测量，结果在 `.checks/kotlin-metrics/`。
只有 `summary.json` 的 `status=passed` 才能使用排名。函数边界来自 Kotlin PSI；物理行数、
去注释代码行与复杂度是不同指标，口径和输入范围见[工具说明](../../scripts/lib/kotlin-metrics/README.md)。
它不修改生产依赖，不新增质量阈值，也不替代编译测试。

## 离线边界

- `dispatch -Confirm` 的暂停件解析与 DryRun 可以离线测试；真正执行仍要求人工输入 `CONFIRM`。
  暂停件字段不区分大小写且不得重复，头部非空行必须符合 `key: value`，显式 `consumed` 不得为空；
  仅规范 `leg=1` 能进入第二腿。路径按字面读取，方括号不会展开成其他文件。
- 语义意图的新基础模块可以先做纯单测。生产接线会改变真机行为，须按 backlog 排队验收。
- C1b 候选生成、静态复核和无设备预检应明确区分；生成脚本不能自动消费 build/install/采集授权。
- 分享落地 activity 白名单必须来自真机观测。没有观测时保持空值，不能凭类名印象填充。
