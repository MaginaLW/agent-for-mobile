# 合同改动联动检查

`scripts/check-contract-coverage.ps1` 只读 Git，检查 `docs/contracts/` 改动是否同时包含对应离线用例改动。它不运行用例，不证明测试有效，也不授予设备运行许可。

```powershell
& '<project-root>/toolchain/powershell-7.6.5/pwsh.exe' -NoProfile -File scripts/check-contract-coverage.ps1
# 检查从某一提交到当前工作树/index 的完整差异，适用于分支或 CI。
& '<project-root>/toolchain/powershell-7.6.5/pwsh.exe' -NoProfile -File scripts/check-contract-coverage.ps1 -BaseRef '<base-commit>'
```

默认比较 `HEAD`。工作树和 index 分别检查，工作树包含未跟踪文件；未暂存的用例不能替 index 中的合同过门。指定 `-BaseRef` 时，两视图都相对该提交比较，干净 checkout 因而覆盖提交差异。新增、删除、重命名合同均检查，删除测试不算增加覆盖；无合同改动时通过。Git/ref 读取失败时非零退出。

对应关系直接写在脚本的短映射表中：窗口 observation 对应同版本 observation 套件，inventory result 对应 inventory 套件，summary 对应聚合门，C1a sidecar 对应 sidecar 套件。C1b observation v1/v2 和 inventory result v1–v3 还接受真实语料回放套件 `c1b-corpus-replay-offline.ps1` 的相应改动；不将它扩展到 summary 或非 C1b 合同。未知合同不能因修改了其他测试而通过；新增合同时补上实际对应套件及映射。

确属不需改用例的修正，可显式给出本次理由：

```powershell
& '<project-root>/toolchain/powershell-7.6.5/pwsh.exe' -NoProfile -File scripts/check-contract-coverage.ps1 -ExemptionReason '仅修正说明错字，schema 与行为未变；已核现有用例'
```

空理由失败。豁免适用于本次所有未被对应测试覆盖的合同，并在 JSON 摘要中逐项标记 `exempted` 和原理由；将摘要与该批已有检查日志一并保留以供复核。它是调用者显式声明，不是审批系统，也不替代既有审查和测试要求，不应包含凭据或个人信息。

摘要的 `status=passed` 仅证明路径联动或显式豁免；`test_execution_verified`、`device_run_authorized` 固定为 false。没有语义分析：给用例加无关注释也会产生路径改动，因此仍须检查实际覆盖和执行结果，不能用本门代替它们。

离线专项入口为 `scripts/tests/contract-coverage-offline.ps1`。它在仓库忽略的 `.checks/reduce-manual-20261111/contract-gate/` 内创建一次性 Git fixture，TEMP/TMP 也仅对本次子进程指向该目录；不改本仓 index，不连接设备。覆盖两视图不互借、已提交差异、无关/删除测试、新增/删除/重命名合同、未知映射、真实回放映射边界、Unicode 路径、空输入与豁免/ref 失败。2026-11-11 专项为 23 passed / 0 failed；实际仓库无合同变更时返回空检查列表且通过。
