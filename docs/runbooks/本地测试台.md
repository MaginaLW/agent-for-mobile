# 本地测试台

入口 `scripts/run-local-testbench.ps1`，设计见[本地台架合同](../specs/2026-11-11-本地测试台-design.md)。仅面向脚本创建的可丢弃 API 36 AVD 与合成靶标，不连接真实手机，不更改现有默认 ADB server，不执行模型付费调用。

**旧候选失效记录（run-06）**：固定 `c6225db` 在 Windows/ADB 37.0.1 以本文直接 nodaemon 入口启动时，尽管带随机不存在的 `--one-device`，私有 devices 仍枚举到 PA2553。foreign-device 断言在任何 shell/安装/MCP 前停止，进程/端口已收尾；不能仅凭参数宣称没有 USB transport。该候选在反证后停止；后续修正与真实验证见下段，不允许忽略外来设备继续，也不重开已消费的真机轮。详见[实施记录](../runs/2026-11-11-离线减负实施.md#run-06usb-隔离反证ime-探针未进入)。

初始化门控修正已由固定 `b55ee448c0a3794d7c3668fed212b8a9f566cea2` 的 run-07 实际核定：请求 `ADB_USB=0`、`ADB_MDNS=0`、`ADB_EMU=1`，在启动 emulator 前实读空表，后续只接受本轮 emulator，IME 输入/恢复链通过。此前主机 PnP 仍观察到实体 USB Present/OK，未要求拔线。适用范围限本次 Windows/ADB 37.0.1；run-06 的参数过滤失效唯一原因保持未知，不把当前官方 Windows 源码归为漏实现。

## 准备输入

1. 在干净、固定完整 SHA 上，以 `-PlocalTestbench=true` 构建 gateway debug 与 test-target APK。保留现行 Android/JVM/Lint/只读制品门，不把靶标构建当成 PA2553 验收。
2. 由官方工具在区内 SDK 准备 `emulator`、`platform-tools`、`system-images;android-36;google_apis;x86_64` 和所需 `cmdline-tools`。复用已经接受且匹配的 license；首次缺许可时停止核定，不修改全局 SDK/AVD 或 Windows 加速配置。
3. 准备 JDK、区内同一 SDK 的 `avdmanager.bat` 与官方 `apksigner.bat` 显式路径。既有全局 22.0 avdmanager 本轮未识别区内镜像，区内 23.0 已创建成功；版本和位置同时改变，不作唯一根因归因。所有 AVD、Android/JVM 用户 home、TEMP/TMP、日志及输出均在新建的区内 `.checks/` 子目录。
4. 记录两 APK 的 SHA-256，并确认四个端口空闲。默认 ADB server 5039，console 5580、ADB transport 5581，HTTP forward 18848；不是默认 5037/8848。

`ApkSignerPath`是独立显式输入，精简的区内SDK可能不含build-tools；可使用另一个既有官方SDK的signer，不按SdkRoot猜路径，也不为补路径修改SDK。先逐文件核实存在，再做公开证书预检。11-13 R5输入准备曾在缺失signer路径处、任何SDK/ADB调用前失败；保留原输出后只修准备路径，新PrepareOnly通过，未启动AVD，见[记录](../runs/2026-11-13-R5失败语义离线观测.md#本地android链的输入准备与边界)。

SDK 和 APK 路径在下例中用占位符。不要把机器私有路径或 token 写入仓库文档。

```powershell
$benchInputs = @{
    SdkRoot = '<project-root>/toolchain/android-sdk-testbench'
    AvdManagerPath = '<project-root>/toolchain/android-sdk-testbench/cmdline-tools/latest/bin/avdmanager.bat'
    JavaHome = '<jdk-root>'
    ApkSignerPath = '<official-sdk>/build-tools/<version>/apksigner.bat'
    GatewayApk = '<project-root>/app/gateway/build/outputs/apk/debug/gateway-debug.apk'
    TargetApk = '<project-root>/app/test-target/build/outputs/apk/debug/test-target-debug.apk'
    ExpectedSourceSha = '<full-lowercase-source-sha>'
    ExpectedGatewaySha256 = '<gateway-apk-sha256>'
    ExpectedTargetSha256 = '<target-apk-sha256>'
    OutputDirectory = '<project-root>/.checks/<task>/testbench/preflight'
}
& '<project-root>/toolchain/powershell-7.6.5/pwsh.exe' -NoProfile -File scripts/run-local-testbench.ps1 @benchInputs -PrepareOnly
```

`-PrepareOnly` 是输入、公开证书、固定源码及端口预检，不创建 AVD、启动 ADB 或模拟器；状态只为 `prepared_not_run`。`matched`/`prepared_not_run` 不表示运行通过。输出目录必须全新，避免覆盖旧结果；SDK 必须位于仓库且不能通过 junction 指向区外。

## 实际运行

在同一固定源码和 APK 上，把 `OutputDirectory` 改为新的 `.checks/<task>/testbench/run-01`，再显式使用 `-Run`。启动前重新核官方 acceleration-check 成功、可用内存至少 4096 MB，模拟器 RAM 为 2048 MB；不为通过修改宿主虚拟化、驱动或 BIOS。默认总运行预算 900 秒，boot 上限 300 秒；若调整，预留至少 boot 加 180 秒，包含 60 秒真实确认超时、HTTP 回收与收尾。

```powershell
$benchInputs.OutputDirectory = '<project-root>/.checks/<task>/testbench/run-01'
& '<project-root>/toolchain/powershell-7.6.5/pwsh.exe' -NoProfile -File scripts/run-local-testbench.ps1 @benchInputs -Run
```

首次在受限沙箱里运行原生 JVM 若挂起，先核具体进程和日志；正式权限入口对照成功后才修正入口，不把未知状态当失败自动再次启动。运行中的进程由调用者按既有工具句柄跟踪，不因一次观察超时启动第二个模拟器。`state.json` 只辅助定位阶段，不能单独证明进程仍存活。

脚本创建唯一 AVD，使用官方 `-ports <console>,<adb transport>`。官方已安装 qemu 二进制包含 `ANDROID_ADB_SERVER_PORT`；这是选择独立 server 的依据，环境变量本身不证明隔离生效。独立 ADB 以 `-L tcp:<port> --one-device <本轮不存在的随机USB标识> server nodaemon` 启动并持有进程句柄，不传 `-a`，默认 loopback。`--one-device` 仅作为附加筛选保留，run-06 已反证它不能单独构成 USB 隔离证明。numeric-host 的 `-L tcp:127.0.0.1:<port>` 不是当前 ADB 支持的 listener 形式。

更早的隔离门在每个子进程环境显式设置 `ADB_USB=0`，依据官方 [client/main.cpp](https://android.googlesource.com/platform/packages/modules/adb/+/refs/heads/main/client/main.cpp)：值为 `0` 时跳过 libusb 和原生 Windows USB 两类初始化。`ADB_MDNS=0` 依据 [client/mdns_utils.cpp](https://android.googlesource.com/platform/packages/modules/adb/+/refs/heads/main/client/mdns_utils.cpp) 的 `is_enabled` 关闭 mDNS 发现，`ADB_EMU=1` 保留 emulator TCP 发现。当前已安装 37.0.1 binary 含这三个环境键，但字符串存在不证明门已执行。官方 commandline 把 one-device 直接传入 nodaemon server，当前 Windows 源码也在注册前检查所有权；这些源码与 run-06 反证不能拼成已证实的唯一根因。

每个 ADB 客户端（含 `devices` 和收尾）先核自持 server 活跃及监听 PID 归属，再显式使用 `-H 127.0.0.1 -P <port> -s emulator-<console>`。官方 [socket_spec.cpp](https://android.googlesource.com/platform/packages/modules/adb/+/refs/heads/main/socket_spec.cpp) 的 `tcp_host_is_local` 只把空 host/`localhost` 判为 local；[client/adb_client.cpp](https://android.googlesource.com/platform/packages/modules/adb/+/refs/heads/main/client/adb_client.cpp) 对 remote spec 的连接失败直接返回，不调用 `launch_server`。因此客户端显式 numeric host 用于防止 server 死亡后自动派生不受 USB 限制的新 daemon；仅设置 `ADB_SERVER_SOCKET` 不够，`-P` 可覆盖该值。上述为官方 main 源码依据，当前安装 binary 的实际连接/不自动启动行为仍须由本机 probe 与真实台架记录核定，不能外推为所有版本保证。

自持 server 活跃且监听归属正确后，**在启动 emulator 之前**只读一次其设备表，要求除标准表头和空白外没有任何行；不忽略未知状态或权限错误行。随后才启动本轮 AVD，后续设备表只允许预期 emulator serial 的标准状态，foreign-device 断言保留；目标在线后，再核 `emu avd name`、API 36 和 `ro.kernel.qemu=1`。任何外来目标、无注册、身份或端口失配都停止，不切换默认 server、不探测真实设备。Android/JVM home、emulator home、AVD home、子进程 HOME/USERPROFILE/AppData 和 TEMP/TMP 全部显式落在本轮输出目录，不修改宿主环境变量或 PowerShell 内置 `$HOME`。收尾同时核原进程退出和四个声明端口无监听；发现陌生监听只记录归属并判清理未证，不自动杀未知进程，不能仅凭旧句柄退出宣称 server 已清掉。

## 完成链与证据

### R5观测接线子项

只需核对内部观测接线时，可在独立核定的新固定候选及运行许可中显式使用 `-Run -R5ObservationOnly`；该开关默认关闭，与 `-ImeProbe` 互斥。固定源码、APK来源/摘要、私有server/端口/PID、初始空表、foreign拒绝、AVD身份和原收尾门均保留。若复用既有APK，须分别记录应用构建源与host候选源，并以应用输入树不变及原制品摘要证明对应关系，不能把新host提交冒称为原APK构建SHA。

此模式只经真实MCP运行list/search/conversation三次自有靶标路由和前台核对，前后读取AVD内gateway的唯一PID，随后采原audit。不调用ui_snapshot、输入动作或click，不读取路由页面控件；原完整链的控件缺失不会因此被改判。三条包级verified响应须各对应唯一的intent_send/OK/intent审计行及匹配的合成参数；新note必须是唯一v1 JSON、available为布尔true、同audit ID、同Android PID及进程实例、returned/hit、正整数checks和顺序一致的单调时刻。缺失、不可用、类型错误、跨进程或时序不符都失败，不补默认值或重发。

summary的verification_scope为 `r5_observation_only`，r5_observation_verified仅在上述检查全部通过时为true。即使status=passed，也只证明该子项，runtime_acceptance及production_execution_grant仍为false；普通输入、焦点、确认超时、完整台架及原R5强负例均不由它证明。应用PID采样及内部UUID不是系统独立接收或全窗口证据。默认不传开关时，原完整动作与确认审计判据不变；任一模式失败均保留证据，不自动重跑。

无SDK离线专项：`scripts/tests/local-testbench-r5-offline.ps1`，验证生产分支的三路由与审计关联，并拒绝缺失/重复/错类型/跨进程/倒序材料。该专项替换I/O，不是实际Android接线通过；准备和草稿发布也不授予新AVD运行许可。

### 默认完整链

- 安装两包并核已装 base APK SHA；授予仅该新 AVD 的无障碍/overlay 设置，启动 gateway。token 从该 AVD 的 `shared_prefs/gateway.xml` 读取到进程内存；原文、Authorization 头和 token 哈希均不写日志、配置或 summary。
- 真正访问 localhost `/mcp`，完成 initialize、tools/list、`intent_send` 的 list/search/conversation 深链及前台校验。现行 `ui_snapshot` 不透出 resource ID，故按唯一 `role=input`、固定合成文本和 `source=a11y` 取真实 ref。不能宣称用 resource ID 选择了目标。
- search 先由靶标标签读取真实输入焦点及触摸探索状态。现有 gateway 的 `focus` 是 `ACTION_ACCESSIBILITY_FOCUS`，非输入焦点；普通非读屏镜像下探测必须保留 `E_VERIFY_FAIL/a11y` 和失败审计，不计成功，也不重试该探测。新快照再执行真实 `set_text`，精确读回 `TESTBENCH_SEARCH` 并核正向 `OK/a11y` 审计，完成 §10.2 的受控输入动作。
- conversation 页面计数为 0 后，对真实发送计数按钮发一次 click；脚本不点 overlay、不注入 TestControl 或广播，不传 PC 批准。等待现有确认门返回 `E_CONFIRM_TIMEOUT`，读回同一 Activity 的计数仍为 0，并核应用内审计行。
- 只停止自身创建的 emulator/server 进程及 forward，保留 AVD 和原始证据。失败不覆盖旧目录，不重发危险调用；查清原因后形成新的本地台架尝试，不能用于重开真机冻结轮。

`summary.json` 的 `passed` 只表示本次真实 APK/HTTP/无障碍普通动作、确认超时不执行和审计闭环。普通深链路由不证明真实点击导航；无人段不证明真人允许后恰好执行一次。允许分支的 JVM 注入测试与人控证据分开，不能用本脚本自点确认卡。`cleanup_proven=false` 继续保留：进程退出不是应用数据逐字节清除或业务清理证明。

保存的 `*.request.json` 只有 JSON-RPC 正文，`*.response.json` 是真实响应；`audit.jsonl` 来自应用内部 `files/audit/`。`state.json`、native stdout/stderr 和摘要全部为本地忽略材料。任何必需响应、计数、审计或身份未知都不作通过；不会因模拟器成功放行 T-L1/T-L2/P0、生产视觉或 PA2553 ROM 行为。

Android 16 [View.requestAccessibilityFocus 源码](https://android.googlesource.com/platform/frameworks/base/+/refs/heads/android16-release/core/java/android/view/View.java)在无障碍或触摸探索未启用时直接返回 false。run-04 只记录到原生 focus=false，没有记录有效触摸探索状态，故不能倒推唯一原因；新靶标只读展示有效状态，明确区分负向焦点能力与正向文本写入。不会为了让测试通过把现行 gateway focus 改成另一种动作。

## 可选 F3 自有 IME 提交探针

`-ImeProbe` 仅在本脚本新建且已经核定 serial/API/qemu/AVD 身份的模拟器执行，默认不开启，原 run-05 链路不增加 IME 操作。本开关不继承或消费任何真机许可，F1 已完成的真机轮不重开。沿用上述固定源码、APK 与新输出目录要求，用法为：

```powershell
& '<project-root>/toolchain/powershell-7.6.5/pwsh.exe' -NoProfile -File scripts/run-local-testbench.ps1 @benchInputs -Run -ImeProbe
```

总预算至少为 boot 上限加 300 秒（默认 900/300 秒已满足）。原普通动作、确认超时及零回调链通过后，额外执行以下有限步骤；不重试 `type_text`，也不改变网关通道优先级或批准路径。

1. 保存该 AVD user 0 的 `default_input_method` 和 `enabled_input_methods`。未知或非法原值在设置写入前停止；只在需要时启用/选择 `dev.magina.gateway/.ime.GatewayIme`，读回默认值与启用成员。
2. 经真实 MCP 深链进入 `agent-testbench://target/ime-only`，核合成靶标前台、`ime_active`、真实可读的 focused editable 和拒绝计数初值 0。这个靶标保留正常 InputConnection，仅让 `ACTION_SET_TEXT` 返回 false；不是无节点或伪造文本通道。
3. 只发一次真实 `type_text(text="台架中文输入甲乙", mode="replace")`，**省略 `ref`**，由既有 API 将其传为 null。该路径先尝试 SET_TEXT；只有它失败后才走自有 IME。要求响应 `data.channel=ime_commit`、committed/verified 为真正 boolean true、精确 readback 相等；`ime_commit_ocr`、`+ocr`、错误或未知均不计通过。
4. 用新一次真实快照独立读回输入节点的精确文字，并核拒绝计数恰为 1；再恢复原默认 IME 和完整启用状态并读回逐字相等。正常和异常路径至多尝试一次恢复；若无法恢复，摘要显式保留未证/失败，不将销毁 AVD 当作恢复成功。
5. 复用应用内审计收尾：关联这次 `type_text` 的 audit id、OK、外层 `channel=a11y`，并核输入长度与 SHA-256、审计中没有输入明文。这里外层审计通道不是 `ime_commit`；后者只来自真实工具响应 `data.channel`，两者不能混写。

`summary.json` 新字段分开记录是否请求/开始、IME 响应通道、真实文本读回、SET_TEXT 拒绝次数、审计与恢复结果；只有这些均成立才计本探针 `passed`。本探针使用现有快照独立读回，异常树/读回路径可能触发既有 OCR；不声称零图像，也不把模拟器快照步骤直接推广为未来真机合同。任何新真机 IME 切换、输入或采集仍需其自身固定候选、现场和许可。
