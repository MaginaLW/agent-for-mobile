# 确认降频与有限授权合同

日期：2026-11-11。承接[减少人工介入 §10](2026-11-11-减少人工介入总体思路-design.md#10-实施顺序与批次验收2026-11-11)批次 6；源码核对基线 `3e93d9389f0e3fb9c8d0531587ca3f3e91d979d9`，实施分支 `codex/reduce-manual-offline`。

本文件完成合同研究：给出草稿优先的用户路径、有限发送集合与只读运行集合的拟议边界和验收。**未实施任何新运行模式，未修改现行逐次确认、开跑规则或授权状态。** 示例均为合成内容，不是运行卡、批准记录或未来许可。

## 2. 优先交付：本地草稿与外发队列

第一步只减少准备和核对的打断，不提前建立批量发送权限。

1. 大脑把合成或用户指定的待发内容送入**网关本地草稿**，不先写第三方输入框，不调用 Enter、发送按钮或任何外发接口。编辑草稿、删除尚未发送的本地条目，不等于对外发送。
2. 设备端显示目标 App、目标会话、完整明文、条数及每项状态。用户可以编辑或取消；任何编辑产生新的内容版本，旧参数/摘要和旧决定失效。
3. 用户选择一项后，由真实目标证据形成当前动作的确认卡。最终外发仍经现行 `SafetyGate`，设备端确认只覆盖该项当前唯一一次执行；其余队列保持未批准。
4. 成功、拒绝、过期、失配、执行失败及结果未知分别显示。失败或结果未知不重新入队、不换 Enter/点击/分享路线重试；取消或重排不会把已尝试项恢复成“未发送”。

最小示例为“测试联系人甲，`测试消息甲`”一条，随后增加“测试联系人甲，`测试消息乙`”。在当前规则下应出现两次独立的最终确认；减少的是草稿准备期间的往返，不能宣称已经减少了最终确认次数。草稿默认仅当前进程内存持有，退出即清；需要持久化、跨会话或导出时另核隐私与保存合同。审计仅记条目编号、状态、必要证据和已有安全字段，不新增正文、完整目标身份或批准凭据落盘。

完成判据是：真实本地草稿 → 设备端可编辑列表 → 一项现行确认 → 一次外发尝试 → 对应审计与终态；其他项 handler 次数为 0。目标证据缺失时停在本地草稿，不要求系统编造会话，不把 `DraftPrepared` 报为已发送或已批准。

## 3. 有限集合的共同数据与执行边界（拟议，未生效）

后续会话、队列、宏模式只讨论**有限、预先明示的 II 级文本发送集合**；支付、删除、账号/权限操作、安装及未知语义 I 级动作保持现行逐次确认。媒体、文件、动态模板和模型续写不在最小范围。扩展这些类别需另外说明取舍，不能由“同类”推导。

每份设备端集合至少展示并绑定：

- 固定设备/用户、App、可区分的会话目标；目标显示名是给人看的，执行时还需同源、可验证的唯一目标证据。同名、分身、双 pane 或来源不明时不得建立集合。
- 明确模式、全部条目及顺序、每项完整明文/长度/不可变摘要和参数指纹。预览截断、只显示首项、数量不可见或屏幕不足以核对时，退回逐项确认；不自动勾选隐藏条目。
- 最大条数、一次人控允许的生效时刻、持续时长、每项最多一次尝试、同时在途最多一项。没有无上限次数、开放内容占位符、自动续期或后台默许。
- 退出/撤销入口和“已执行的外部动作无法由撤销授权倒转”的说明；撤销只能阻止尚未越过执行临界点的动作。

集合状态只需 `待确认 → 有效 → 完成/拒绝/过期/撤销/失效/失败/结果未知`。允许时间只由胜出的设备端真人允许写入一次；迟到/重复回调、重连、进程恢复、下一个条目或新的证据不得刷新它。进程重启丢失所有未执行批准，不从审计、台账或已发送历史重建许可。

有限集合只保存在网关内存，不向大脑暴露可调用的批准令牌。若未来明确批准集合语义，才可由该次可见卡的唯一内部决定固定子项；每项仍使用单独 `intentId`、`confirmationId`/nonce 与一次性消费，在返回执行数据前移除，之后失败也不能恢复。集合只限制已明示子项，不能替代执行前目标/输入内容/参数/前台/焦点/几何与失效覆盖核验。`Rebuilt` 只证明读回匹配，不自动授予授权。

## 4. 三种降频模式的最小合同（拟议，未生效）

以下数值用于形成有限、可验收的设计样例，**不是用户已经批准的运行预算，也不是当前源码新增默认值**。

| 模式 | 设备端可见批准对象 | 示例边界与到期起点 | 消费、失效及回退 |
|---|---|---|---|
| 会话集合 | 唯一“测试联系人甲”，预先列出的 `测试消息甲`、`测试消息乙` 两项全文 | 最多 2 项、真人允许后 120 秒、顺序执行、每项 1 次尝试；不接受“接下来 AI 认为需要的消息” | 下一项必须重新证明同一目标且内容精确匹配；换会话、失去唯一目标、修改文字或到期即终结集合，剩余项回到未批准草稿，禁止自动重弹 |
| 队列集合 | 同一设备/App 下最多 2 项可完整核对的目标与全文清单 | 固定顺序、真人允许后 120 秒、单项 1 次、在途 1 项；清单任一条不能完整核对就用逐项模式 | 执行第一项前核对整份清单仍相同，再逐项取新证据；新增、删项、重排、替换目标/内容均使整个未执行部分失效；已执行项保留真实结果，不伪装为整队回滚 |
| 录制宏 | 设备端可见且版本固定的动作序列，以及**录制之后明确确认**的回放次数/目标/内容 | 最小仅 1 次回放、2 条已明示文本项、允许后 120 秒；录制过程本身不默示以后回放权限 | 版本/参数 diff 必须逐项为零，或变化项由人重新明确确认；导航读取可自动重建 ref，但每个外发项仍核目标与内容；危险失败/结果未知终结本次宏，不能从下一步续跑 |

同型历史 N 次只允许在卡上提出“查看有限集合方案”的入口；**历史次数不授权、不自动升档**。按钮由人主动打开后仍须完整展示本次集合及新边界，再由可见卡决定。当前不会因为历史成功、0/1 分反馈或一次“以后少问”就改变安全档位。

## 5. 必须先决定的源条款差异

本文件不改下列源文，也不宣布其提案已获批准。若后续确要实施有限集合，A 应一次呈现精确条款差异、风险取舍与范围，用户可以只批准本地草稿而不批准降频。

| 现行源条款 | 需要另行明确接受的最小拟议变化 | 保留的硬边界 |
|---|---|---|
| AGENTS 铁律 3“临界动作前停下…设备端可见确认卡确认后才继续”与两档逐次确认 | 仅对已完成有限集合实现与验收的 II 级文本发送，将“每个外发项当场确认”扩为“同一设备上人刚核对的完整有限集合内按序逐项执行”；未列出的动作仍逐次确认 | 仍必须真实设备端人控；不包含自确认、PC/MCP 批准、通知允许或不明目标；未明确接受前维持现文 |
| 硬门 §2 一次确认只授权当前调用；语义意图 §3 一次意图唯一一次执行 | 集合决定只固定列出的有限子项；每个子项保持独立唯一一次执行，不生成可重放通用令牌；实施时同步精确修订受影响不变量与注释 | 参数和目标不变、子项先消费、失败不复活；不能简单给现有 `IntentApprovalStore` 添加 reopen/reset 或多次 consume |
| 语义意图 §2.2/§2.5 与 backlog §6“两档均逐次确认” | 仅新增已批准且完成验收的 II 级有限集合模式；I 级保持逐次、无延后等待；缺唯一会话/非宏目标证据则不可进入 | 证据 TTL 不放宽，未接线模块不算可用；T-L1/P0、确认来源与 pane 证据等实际门禁照常 |

联动对象限定为上述安全源条款、`SafetyGate`/语义意图装配、ConfirmOverlay 的集合可见性及相应正反验收；不改通用全局审批规则、不建设授权引擎或网络授权接口。现阶段只形成提案，生效必须以未来获准的具体实现、固定候选验证和源条款读回为准。

## 6. T3 批量弧与常备只读授权合同（拟议，未生效）

现行 §7.3 已允许同一固定 SHA/制品/设备的一份报告覆盖有限只读阶段链，成功前置后无需逐阶段问。优先消除这种已有许可内的重复询问；不为模板化再设一个审批入口。

需要跨**多次采集弧**时，拟在 §7.3 增加一个范围有限的选择：用户在完整就位报告后，可以明确列出固定完整 SHA、制品 SHA/签名、设备/用户、读取来源、目的地与各弧判据，并批准有限 N 弧或期限内的有限只读诊断集合。未选择此模式时继续现行逐弧规则；不能把“常备”写成永久或不限量。

| 字段 | 批量弧最小示例 | 常备只读最小示例 |
|---|---|---|
| 业务范围 | 同一候选、同一制品、同一设备/现场的 2 条同型只读弧；每弧最多一轮两帧采集 | 同一项目、客户端、固定候选与固定只读管线的最多 3 条诊断弧；不跨候选或其他聊天自动继承 |
| 累计硬上限 | 2 弧、24 次 SDK、240 秒读取 | 3 弧、36 次 SDK、360 秒读取；8 小时有效期 |
| 首次激活 | 用户在报告后明确批准；第一次获准 SDK 调用前原子 claim 一次，并记录首次实际调用时刻 | 相同；8 小时从首次实际调用起算，不从询问发出时起算 |
| 最晚激活条件 | 同次就位证据和现场未改变；实际提案应写明该条件可检验的证据与最后有效界限，缺失就不可发送请求或激活 | 授权提案必须填写具体 `latest_activation_at`（含 Asia/Singapore 时区）并保证准备/复核余量；不得在此合同里预填一个等待用户时会过期的日期 |
| 弧间前置 | 每条弧仍生成完整自动就位摘要、核定身份/前置与剩余预算；范围完全相同才消费下一弧 | 相同，且设备重启、进程/绑定失效、来源漂移或现场变化使本集合失效，不凭“服务在线”继续 |
| 停止/撤销 | 任一失败、超预算、失配、结果未知、撤销或有效条件消失，终结整个集合，保留未用余额但不续跑 | 相同；到期、用户要求“以后问我”或针对该类的明确反例后停止依赖此约定，不以历史低分恢复 |

上表是构造有限提案的**合成预算样例**，不是对现有 C1b/S05 实际成本已足够的结论。实际请求必须用已准备管线的命令数和时限证明整链装得下，替换为经核定且用户实际批准的数值；如果样例装不下，不得拆弧绕过累计上限。

所有消费者共享同一个原子计数与首次激活记录。等待、工具/执行者切换、异常恢复和聊天恢复均不重置次数、读取秒数、弧数或有效期；原弧失败冻结，不能借剩余 N 弧重开失败目标。未证明作用范围、当前有效状态和累计使用量时停止依赖该集合。只记最小许可来源与已消费事实，不读全聊天、不向大脑交付设备批准凭据。

严格排除安装、权限/设置写入、危险动作、新图像/新来源、生产接线、凭据使用、外发和付费；这些对象不能因集合内还有预算而准入。安装超时后独立后验仍仅按既有 A10 条件事先列明，原安装保持冻结；不得把它扩为通用失败恢复。未知状态不自动重试、不换来源、也不触发后台定时器。

拟议提案应区分“这次有限运行集合”和“长期规则是否写入并生效”；许可来源、具体对象/阶段、累计预算、激活/最晚激活、停止条件、撤销与剩余未验证项一次呈现。必要新提问按 `approval-feedback` 的当前交互段带会话短编号及可省略的分数含义；编号和评分都不授予权限。本合同没有发出新请求，也不要求为了证明减少询问而制造评分样本。

## 7. 未来实施的负向验收与实际减负判据

| 验收输入/时序 | 必须观察到的结果 |
|---|---|
| 没有人控决定；来自通知 allowed、PC、MCP、测试控制或自点 overlay 的决定 | 全部子项 handler 次数 0，不能创建集合有效期 |
| 人只核对了首项；其他项被折叠/截断或目标不能区分 | 不允许集合批准；退回未批准草稿/逐项路径，不替人勾选 |
| 批准后内容、目标、App、设备、用户、顺序、数量、宏版本或参数变化 | 未执行部分失效，handler 次数 0；不从同型历史补许可 |
| 证据过期、读回 UNKNOWN、pane/IME/前台不成立或证据重建不匹配 | 当前项失败即终态、其余项不执行；不放宽 TTL 或伪造目标 |
| 两个并发消费者请求同一子项；重复/迟到允许；系统时钟回退 | 最多一次原子消费；时间回退失效；不能刷新首次允许/激活或计数 |
| 某项执行失败、超时或效果未知；随后请求换通道/重新发送 | 当前集合终结，未执行项为未批准；已尝试项保持失败/未知，不自动重新排队 |
| 第一项已成功后第二项失效/失败 | 保留第一项真实成功、第二项真实终态和后续未执行；不能报告“整队已回滚”或整队成功 |
| 撤销与临界动作并发 | 原子界定谁先越过临界点；未开始项不得执行，已越过项如实记录可能已发生，不承诺撤销外部效果 |
| App/设备重启、后台恢复、audit/ledger 重放或旧授权文件重读 | 不恢复进程内发送批准；读取元数据不等于重新允许 |
| 批量弧前置变化、单弧失败、结果未知、到期/撤销、候选/来源变化 | 整个运行集合停止；不把剩余预算转成重试、新源、新候选或安装许可 |
| 切换执行者、等待、上下文恢复或重新调用 runner | 共享原累计计数和激活时刻，不重新起算；无法核实则拒绝激活 |
| 已批准同型集合成功后再次发新对象或开放内容 | 仍无许可；只有用户主动核对新清单并明确决定才可能建立新的有效集合 |
