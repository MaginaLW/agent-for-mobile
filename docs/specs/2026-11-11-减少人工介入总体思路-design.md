# 减少人工介入总体思路

> **For agentic workers:** 本文件是方向与边界设计，不是运行许可。各轨道实施另立合同与验收；改变真机行为的提交仍按 backlog §7.2–§7.3 走 C 队列，危险动作仍由设备端确认卡逐次/按授权档位批准。

**Goal:** 除确属不可消除的人工环节外，把开发与测试中其余人工介入全部消掉：日常迭代零人工（自包含测试台承接）、单轮真机压缩为“每弧一次授权 + 仅危险动作设备确认”、生产使用把逐次危险确认压缩为“可逆优先 / 会话级 / 教一次”。

**Approach:** 三层改造。(1) 把回归测试搬到 AI 可完全控制的自包含测试台（API 36 模拟器 + 自建靶标 App + 真实 gateway APK 端到端，可选测试号容器），真机只验 ROM 差异；(2) 用 Shizuku 常驻与低争议权限消掉现场物理介入（姿态布置、免触安装、掉线重启、通知回执）；(3) 把授权从逐次提前到弧级/会话级/录制时（链式授权模板、可逆优先、宏授权），并自动化就位报告与归档。

**Materials:** 2026-11-11 会话头脑风暴与用户批复“除了真减不了的，其他都消掉”；[AGENTS 铁律](../../AGENTS.md)；[backlog §7.3](../backlog.md#73-开跑条件)；历轮真机语料（[597ca8b 轮](../runs/2026-11-04-诊断后验与窗口采集.md)的 5/4/1 + `window_type_invalid`、[abb7b0d 轮](../runs/2026-11-05-未分类窗口真机验收.md)的 5/5/0 全保留、`type=-1` unknown、退化 invisible root、IME `visible=false`）；现有完整离线门与 `scripts/tests/fixtures`。

**Validation:** 本文件为纯文档交付，随本批以统一脚本门 `check.ps1 -SkipGradle` 验证（14 PASS / 1 SKIP Android，纯文档未触及 Kotlin）。总体验收口径：T1 落地后日常迭代不再申请真机轮；单轮真机的人工动作清单随各轨道逐项缩短并记录在对应 run；不因任何轨道放宽铁律 3、§7.3 或“不关闭原生功能换通过”。

日期：2026-11-11。基线 `ef7df4c7e2738056beb94492c3205b1f20a663f7`。授权来源：本聊天同日用户明确指示；本文件不构成安装、设置写入、设备操作、推送或生产接线许可。

## 1. 结论与授权边界

用户已批准总体方向：除不可消除项外全部消掉，并落成本文件。具体含义：

- 批准**本地自包含测试台**准入（模拟器 + 靶标 App + 可选测试号容器），仅限本地开发测试，其证据不等价于 PA2553 真机证据。
- 批准按 T1–T6 轨道排期实施；每条轨道的实施另立合同，不因本文件跳过任何现行门禁。
- **未批准**与现行有效决定“不关闭原生功能换通过”冲突的对抗路线（见 §6 出界项）；vivo 开发者反馈线保持并行。

## 2. 不可消除清单（真减不了的）

| 环节 | 为什么不可消除 | 允许的极限压缩 |

## 4. 轨道设计

### T1 自包含测试台（最高杠杆，纯离线）

组成与顺序：

1. **真机语料回放门**：把历轮真实捕获（597ca8b、abb7b0d、-1 unknown、opaque root、IME false）固化为版本化字节级 fixture；任何解析/分类/合同改动必须全量回放逐字节一致，并附变异用例。现有 `scripts/tests/fixtures` 只有合成 shape，本步补真实语料层。
2. **合成窗口模糊器**：对 window inventory 系统性生成畸形输入（`type=-1` 变体、截断清单、`child_count=0` root、IME mode/binding 组合、越界几何），断言 fail-closed 分类与不变量。
3. **靶标 App**：自建复刻真实病灶的“WeChat 形状”应用：opaque 树、退化不可见 root、`-1` 窗口、多窗叠放、IME 状态切换，语料来自上一步。
4. **端到端台架**：API 36 模拟器运行真实 gateway APK，对靶标 App 跑完整 agent 循环（枚举、分类、确认卡、ui_action、审计）。模拟器上无障碍可自由授予，无 vivo 安全中心、无 §7.3、无冻结风险，可无人值守整夜回归。
5. **P0 预置导航靶标化**：靶标 App 额外复刻 P0 §3.0 的聊天列表→搜索→目标会话路径，导航宏在测试台离线迭代到稳定；真机 OCR 与真实微信差异仍需一轮独立核验，通过后才可取消该节人工预置。
6. **确认卡状态机 JVM 穷举**：Allow / Deny / Stale / Reentry / 超时 / context recheck 全转移纯单测覆盖，P0 Deny 腿（fail-safe 默认）先离线证明，真机每腿只留一次抽验。
7. **合同改动联动检查**：schema/合同文件变更时要求对应离线用例同步变更或显式豁免标记，否则门失败；最小实现即一条检查，不建审批系统。
8. **提交触发/定时回归**：复用现有 `check.ps1` 与本测试台门，提交后自动跑相关套件（可选本地计划任务做夜间全量）；不引入新 CI 平台。
9. **测试号容器（可选后置）**：真实微信加测试号在容器/模拟器中做 UI 级联调，封号风险由测试号承担；生产真账号继续走无障碍 + 确认卡路线。

边界：模拟器与靶标证据不等价于 PA2553 证据。ROM 特有行为（safecenter 撤销、overlay z-order、通知角标、安装监控、OriginOS 多窗）显式列清单留给真机差异轮。测试台不触碰生产 schema 与运行入口的现有门。

验收：离线门新增“测试台门”；在测试台上复现全部已知病灶并被现有合同正确处理；此后日常迭代不再申请真机轮。

### T2 Shizuku 常驻与现场自动化（S2 扩展）

范围：S2“Shizuku 重启存活”原有待真机项扩展为常驻后支持：免触安装（授权轮内）、窗口/姿态/IME 自动布置与读回验证、权限状态只读自检、首次无障碍开启单次辅助（写入后读回验证，失败即回退人工并明示，不循环对抗）、授权轮内临时屏幕常亮与 keyguard 只读检测（属设置写入，须列入该轮许可并轮后恢复）、构建/签名身份预检（keystore 路径钉定，防 `user.home` 类覆盖事故）。

实施原则：扩展现有 `-Provision`/runner 能力，不建新框架。另做一项 ADB 端口隔离有限试验（runner 用独立 adb server 端口，避免与 PC Suite 争 5037），试验失败即放弃并维持“冲突由用户处置”现行决定。

边界：Shizuku 是高危面，只做白名单动作；runner 仍不杀外部进程；首次开启辅助只做单次尝试，被撤销即回退人工，不与安全中心循环对抗；权限自检只读。改变真机行为的部分走 C 队列。

### T3 授权链与报告自动化

- runner 直接产出 §7.3 要求的固定格式就位报告（完整 SHA、设备、姿态证据、累计预算、停止条件），用户人工压缩为“读摘要 + 一句授权”。
- 把已批准的 A10“一份报告覆盖只读阶段链”做成每次请求的默认模板（后验、条件采集、条件清理，累计预算），授权从每阶段一次压到每弧一次。
- 常备只读预授权：固定管线干净多轮后，向用户申请范围明确的常备只读诊断授权（预算上限 + 熔断条件），属治理变更，由用户逐次批准设立。
- 批量弧预授权：介于逐弧与常备之间，一次批准同型 N 条弧（固定候选类型、期限、累计预算、熔断），到期或熔断后回到逐弧。
- ask 模板固定携带影响、默认建议与停止条件，减少决策往返；复用既有 approval 流程，不新建评分体系。

### T4 危险确认降频

按用户负担从轻到重，全部是把授权提前而非取消授权：

1. **可逆优先**：发送类动作先进草稿箱或外发队列，人只在设备上按最终“发送”。
2. **会话级预授权**：时限内、固定联系人、固定明文预览的发送确认一次管多次；超范围即失效回到逐次。
3. **宏=录制时授权**（M3 提前）：录制那次的人是授权人，回放时做参数 diff 校验。
4. **队列级确认**：多条同类待执行项汇总一屏（目标、预览、数量），一次核对后统一放行或拒绝；任一项不匹配则整队退回逐条。
5. **同型升级入口**：确认历史同型 N 次后，确认卡附带“升级为会话授权”按钮；升级决定仍由人当场作出，系统不自动升档。

红线：不实现自确认或自点 overlay；不降低 I/II 级现有证据要求；危险动作失败即终态、不重试的既有决定不变。

### T5 低争议权限包

电池优化白名单 + 前台服务加固、BOOT_COMPLETED 自启 + START_STICKY 崩溃自拉起（vivo 自启动管理需一次性用户放行；重启/长期绑定同时在真机差异轮验证）、通知监听回执、自有 IME、隔离视觉制品的 MediaProjection 常驻授权。每项独立小合同、随批次搭车验收；通知批准仍只能拒绝或查看（08-28 撤销决定不变），监听仅用于回执读取。

### T6 归档自动化

C 端 manifest 生成台账行与 run 记录草稿，A 校验签名合并，全程自动；人只审最终摘要。不改变台账“无论通过失败都归集”的既有要求。

## 6. 出界项（未批准，需单独明确改决定）

- **对抗 vivo 军备竞赛**：自愈 daemon 秒级重写 `enabled_accessibility_services`、root 冻结或卸载安全中心、系统分区化。均与“不关闭原生功能换通过”现行决定冲突；root 另有支付类 app 完整性检测连带风险；军备竞赛耗电且可能升级为杀进程。保持出界，厂商开发者反馈线并行。
- **自确认/自点 overlay**：删除产品安全主张，永久出界。
- **任何绕过 §7.3 的自动开跑**：连接状态、泛化推进指令和沉默都不是开跑令。

## 7. 与现行规则的关系

不变：铁律 1–3；§7.2–§7.3 验证与开跑流程；“每批至多 2–3 个改变真机行为的改动”；A11 推送授权范围；“不关闭原生功能换通过”；危险动作失败即终态。

新增：本地测试台准入（限本地开发测试）；明确不改变真机行为的离线改动（T1 语料/模糊器/靶标、T3/T6 工具）不占 C 队列批次名额。此为 §3 既有语义的显式化，非规则放宽。
