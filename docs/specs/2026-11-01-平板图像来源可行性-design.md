# 平板 window/pane 图像来源可行性核定

日期：2026-11-01。仓库查阅基线：`7d004fa3f92cb87a327b4f42e5a93eb706fc5524`。验证范围：本地源码、Android 官方 API 文档及 AOSP 参考实现查阅；未编译新代码、未调用设备、未截图/OCR。承接[视觉证据合同](2026-11-01-平板window-pane视觉证据合同-design.md)。

## 1. 结论

API 34 起的 `AccessibilityService.takeScreenshotOfWindow` 提供真实的原生 window 定向入口，参数来自 `AccessibilityWindowInfo.getId()`；因此不必把现有整屏 Bitmap 加上自报标签冒充 window-bound capture。项目 `compileSdk=35`，目标平板记录为 Android 16，接口级别具备候选条件，**尚不证明 PA2553 的实际截图、绑定连续性或 pane 语义成立**。

该入口只收窄“图像请求指向哪扇原生窗口”，不能独自满足整个视觉合同。关键缺口仍是截图与几何/树/IME 的同代关系、窗口内部 pane/区域语义、可见与触达状态，以及适用 ROM 的实测。当前结论为“原生定向来源可选，完整实施准入未通过”；不生成生产 schema、采集候选、任务卡或新设备批次。

## 2. 已核对来源

| 来源 | 本轮查到的事实 | 对本项目的意义 |
|---|---|---|
| [Android AccessibilityService](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService) | `takeScreenshotOfWindow` 自 API 34 提供，接收 a11y window ID；要求 `canTakeScreenshot`；可在 a11y overlay 盖住目标窗时取得底层窗口内容 | 原生定向请求优于按整屏坐标推测归属；同时意味着它不能证明用户实际看到了目标或确认卡 |
| 同页错误常量 | invalid window、secure window、无访问权、节流及内部错误各有结果 | 分开保留原因；受保护内容失败即结束，不能换整屏/其他通道绕过；超时另列，不能报“没有内容” |
| [ScreenshotResult](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService.ScreenshotResult) | 有 HardwareBuffer、ColorSpace、timestamp；timestamp 属 `SystemClock.uptimeMillis()` 域；buffer 不再使用后需关闭 | 现有包装丢弃 timestamp；新设计必须区分平台时间与本地请求/回调时间，并覆盖迟到回调的资源释放 |
| [AccessibilityWindowInfo](https://developer.android.com/reference/android/view/accessibility/AccessibilityWindowInfo) | ID、display、layer、bounds 可读；region 是可触区域，bounds 是该 region 的外接边界；API 34 transition time 只定义为 bounds 改变的 uptime 时间 | region/bounds 不能直接充当截图 surface 的完整坐标变换；transition time 不是 pane 内容、IME 或全局视觉 epoch |
| [AOSP AccessibilityInteractionClient](https://android.googlesource.com/platform/frameworks/base/+/master/core/java/android/view/accessibility/AccessibilityInteractionClient.java) | 本轮页面 blob `bdfc236d82e09a546519521c3e034b5461ec31e0`：`takeScreenshotOfWindow` 以 interaction ID 关联回调；`sendWindowScreenshotSuccess` 收到 screenshot 后用 `SystemClock.uptimeMillis()` 构造结果 | 平台 timestamp 不宜解释成精确的 compositor 像素采样时刻；请求/接收区间仍需保留。这里只是 AOSP 参考，不是 vivo 固件实现证明 |

Android 16 固定 tag 的 InteractionClient 页面本轮工具读取失败，未据此声称核过对应 ROM 或 Android 16 固定实现；上述 main 页面记录 blob 供区分本次查阅版本。官方文档的新增高版本接口不自动进入 compileSdk 35 的候选范围。

## 3. 仓库复用与禁止直接复用处

- [GatewayA11yService.captureBitmap](../../app/gateway/src/main/java/dev/magina/gateway/a11y/GatewayA11yService.kt)：当前调用 `takeScreenshot(DEFAULT_DISPLAY)`，仅返回软件 Bitmap，未保留平台时间戳或原生 window 请求关联。`captureBitmapRetry` 内部可延迟再截，不符合本阶段单次、无隐式补采的来源证明边界。
- [a11y_config.xml](../../app/gateway/src/main/res/xml/a11y_config.xml) 已声明 `canTakeScreenshot=true`；[构建配置](../../app/gateway/build.gradle.kts) 为 compile/target 35、min 30。以后使用 API 34 路径必须显式版本守卫；旧系统不回落到整屏猜绑。
- [AndroidTabletC1bSource](../../app/gateway/src/main/java/dev/magina/gateway/tablet/c1b/AndroidTabletC1bSource.kt) 已在进程内读取原生 window ID、display、bounds 和 root 关联；当前只把触摸 region 外接矩形保留为 bounds，未提供图像 surface 变换或 transition time。它的原生整数 ID 不能与脱敏 `awN/apN` 标签混用。
- `GatewayA11yService.ocrScreen` 的整屏 OCR、按 IME 顶边截取和 elapsedRealtime 缓存，不能接作本合同的 pane 识别路径；uptime 与 elapsedRealtime 跨睡眠不相等。旧 TTL、revision 和两端值相同都不能代替同代证明。

## 4. 最小候选路径与验证方法

以下是后续设计输入，不是已准入实现或设备操作步骤。

1. **在可信采集进程内选定原生窗。** 完整 inventory 是前提，依据 display、原生 ID、owner/root 关联选定唯一候选；不能按左/右、focused 或同包名猜测。请求上下文绑定服务进程代、一次调用和选定 ID，结果只能交给该调用；超时/销毁后迟到结果只释放资源，不恢复终态。脱敏标签仅用于引用。
2. **单次 window screenshot，保留时序区间。** 请求前和回调入口使用同一 uptime 域记录边界，保留平台 timestamp；检查顺序异常、超时、进程变化。参考实现支持关联回调，不能证明像素与其他来源原子一致；不把 API callback 时间或截图成功直接升级为 fresh/可执行。
3. **核定图像坐标和现场可见性。** 必须证明 buffer 尺寸、原点、旋转/缩放、window surface 与屏幕/可触 region 的关系；尺寸恰好相等不足以证明变换。窗口内容图与用户可见的合成画面分开判定，不能用避开 overlay 的图证明 safe-area 或确认卡无遮挡。
4. **在已绑定窗口内识别 pane，再裁区域做 OCR。** 原生截图不输出 conversation role、title/editor/message 区域。须单独设计可审计的识别依据、唯一性与拒绝条件；现有 opaque root 无法给出这些角色，不能从一个 root 推成一个 pane。未选定识别来源/算法前不生产目标证据。
5. **各阶段重证并验证变化覆盖。** 原生 window ID 只作为当前调用来源参数，不承诺跨进程或跨阶段持续身份；移除/重建、bounds/旋转、pane 内容和 IME 变化均须有明确失效路径。未证明事件覆盖时，前后相等不能排除中途变化。只有时钟/几何/失效覆盖依据成立后，才定 TTL、跨度和同步误差，不在此拍定秒数。

| 需要证明的事项 | 离线能完成的工作 | 后续真实验证与拒绝条件 |
|---|---|---|
| window → 图像绑定 | 审查原生 ID 传参及单次 callback 上下文；反例检查请求 A 的回调不能落入 B | 同包双窗各具不同可识别内容时核对归属；移除重建/失效 ID 不可静默换窗。当前未运行 |
| 坐标变换 | 把 buffer/window/screen/region 坐标分开定义；拒绝缺映射或越界 | 原生横屏多窗的移动/缩放/旋转与可触区域对照，检查 X/Y 和边界；无法解释的变换即拒绝 |
| 时间与同代 | 依据原生时钟语义设计区间校验、迟到/重启/乱序反例 | 验证来源延迟和布局/IME 变化检测覆盖；平台 timestamp 单值、两个端点相同均不足以通过 |
| 可见/可触达 | 将底层窗口内容、合成可见性和按钮触达拆成独立判据 | a11y overlay、遮挡、IME、受保护内容反例；window screenshot 成功不能代替合成证据 |
| pane/区域语义 | 定义识别输入、唯一性、区域完整性与拒绝逻辑；列表同名行/跨窗混淆必须拒绝 | 同名会话、双候选 pane、输入回显与消息区差异需独立核对；只有 OCR 文字或高置信度不通过 |
| 资源与隐私 | 检查 buffer 在正常/失败/迟到/取消路径释放，明确原文与图像生命周期 | 尚无图像采集授权；未来先定最小范围、内存处理、保留/脱敏和离设备边界，再按项目就位与开跑规则执行 |

没有直接承诺“一次最小截图就解除全部门禁”：获取 buffer 的可行性、坐标绑定、pane 识别、同代性和确认卡安全分别有验收边界；不得把探测成功扩大成动作许可。

## 5. 本轮可关闭与仍开放的项

可关闭的离线问题：已有官方 window 定向 API 候选；SDK 编译级别足够；截图能力已声明；uptime 时钟域、overlay 排除和安全窗错误有官方依据。现有整屏 Bitmap + caller metadata 不再作为首选来源。

仍开放的实施前问题：确定 pane 语义识别方法；证明截图 surface 与窗口/屏幕坐标关系；提出有依据的采集跨度、跨源同步误差与失效覆盖；明确图像隐私及可见性独立证明方法。窗口清单诊断只能解决缺失归因，不能代替这些条件。

下节把这些缺口收敛为明确选择与最小取证问题，避免用反复新增字段或设计文档替代真实来源。当前 C1b 合同与冻结 observation 不变。T-L1/T-L2/P0、R5 与手机暂停状态不变。

## 6. 推荐的最小方案与停止点

### 6.1 pane 识别：结构定位、区域 OCR；opaque 时停止生产链

推荐复用原生树做角色与区域定位，再仅对已绑定的 pane/title/editor/message 区域调用现有 [OcrEngine](../../app/gateway/src/main/java/dev/magina/gateway/ocr/OcrEngine.kt) 的 bundled 中文识别。图像本身使用 window 定向来源，不能复用旧整屏 OCR 缓存；OCR 返回的是文字与框，不是 pane 检测器。标题文字、输入区域可编辑属性及消息区域的结构关系须同时落在同一原生 window，且唯一匹配，缺任何一项即停止。

这条推荐**不能解决当前微信 root opaque 的实况**：存量树没有足够角色，现有 OCR 也没有非文字结构分割能力。本轮不选新增视觉模型或第三方服务，不把纯颜色分隔线/左右位置/标题文字当 conversation pane，不假定一个窗口就是一个 pane。现有能力下无法离线造出可信的全自动 pane 识别器，这是具体能力缺口，不是待补 schema 字段。

最小下一步是**来源可行性的只读人工核对**：在未来获准的 window 图中，由现场人员标注可观察的 pane、标题、输入、消息区域边界，判断是否确有可重复识别的结构。标注只作采集来源/后续算法需求的参考真值，不进入生产目标证据，不授予动作许可。若树仍 opaque 且图中没有可验证的结构定位方法，自动 pane 路径继续阻塞；届时需明确选择新增识别能力或缩小产品支持范围，而非直接实现已有 OCR 的整窗搜索兜底。

### 6.2 几何与同代：只接受可证区间，不宣称原子快照

推荐保留一次 window 请求及回调区间，读取并比较该窗口在区间两侧的 ID/display/可触 region/bounds、display 旋转和图像尺寸；窗口消失、进程重启、尺寸不符或任何已知变化都拒绝。该方案仅用于发现不一致，**两侧一致不是整段无变化的充分条件**，也不是允许执行的门。

公开 `ScreenshotResult` 没有同时返回原生窗口几何变换矩阵、pane 布局版本、IME 状态或 compositor 像素帧号；`getTransitionTimeMillis` 只覆盖 bounds。因此仅凭本轮已核对公开接口，无法纯离线证明“图像、树、IME 严格同一代”或完整 window surface→屏幕变换；当前不能为动态布局批准生产执行。一次真机成功或有限样本中的前后相等，同样不能证明所有漏事件均不存在。

可直接设计的是拒绝规则、分开的坐标空间、请求关联和资源生命周期；必须取证的是目标 ROM 实际 buffer 几何、可见/遮挡语义、变化时序及失败表现。收集延迟用于描述观察区间，不能据最大观测值直接宣称硬上界或据此拍定 TTL。若不存在可证明的失效覆盖，后续方案只能维持只读诊断，或就明确缩小的支持/保证范围另作决定。

### 6.3 最小取证范围：先回答三个问题，不启动任务卡

这是一份未来范围审查输入，不是新增批次、次数许可或现场指令；仍受当前 C 队列、图像授权、新就位与完整 SHA 开跑条件约束。

| 问题 | 最小应包含的对照 | 可据此得到/不能得到的结论 |
|---|---|---|
| API 是否在目标 ROM 对准正确窗口，buffer 坐标是什么 | 同包两个可区分的窗口；原生 ID 定向返回图与现场可见内容逐一核对；同一窗口至少一个已知几何变化对照，独立记录 X/Y 边界与图像尺寸 | 可以发现错窗、裁剪/缩放差异及不支持；不能凭包名、尺寸相等或一次正确推定持续绑定 |
| 原生多窗里 pane/区域有没有可识别结构 | 同一获准图像的人工区域标注，区分会话列表同名行、真正标题、输入区和消息区；先不运行 OCR | 可以核定下一步算法所需输入及歧义；人工标注不变成生产 pane 身份，不证明自动识别准确率 |
| 窗口图与实际可见/变化状态有什么差别 | 原生多窗基线与一个明确 IME/遮挡变化状态；记录 window 图与现场状态不一致处，以及请求/平台/回调时间 | 可以反证把底层图当用户可见画面、发现旧图/晚回调；不能自动放行确认卡、证明完整失效覆盖或进入发送测试 |

优先采用用户指定、内容可公开的测试会话和非敏感文本。无需重放 ccc8cce 或重进无障碍设置；不做发送、支付、删除、不切权限、不因失败换源再采。对照数量和具体动作必须在范围审查中固定；这里不以泛化“持续推进”代替现场开跑令。

### 6.4 隐私默认与现有能力限制

推荐默认：单个获准目标 window 在设备内处理，不采整屏、不上传、不新增网络服务；不保存图像、聊天原文、OCR 内容或内容 hash 到 Git、日志、审计。仅持久化本轮绑定、受限尺寸/时序/状态和人工核对结论；raw ID 只在采集进程内，落盘使用本轮脱敏引用。若审查需要复核原图，必须先明确独立受控存储、访问范围、脱敏方式和删除条件，不能默认扩大留存。

内存按调用持有，终态不再保留引用；HardwareBuffer 在正常、失败、取消和迟到路径关闭，派生 Bitmap 及 OCR 临时对象释放引用。Java/Kotlin 字符串与 ML Kit 内部缓存不能承诺可验证的逐字节擦除；本轮也未审计该 SDK 的内部遥测或所有网络行为，因此“仅端侧识别”是所选调用方式与设计边界，不能宣称已完成无外传审计。若后续确需 OCR，先复核 SDK 数据处理/网络行为，且禁用旧异常中“交大脑目检”之类自动扩权建议；当前最小来源取证不调用 OCR。

`OcrEngine.recognize` 对同一位图做原图和增强图两次识别，不是两次截图；但当前返回文本和增强 Bitmap 的生命周期、超时后的迟到任务处理并未按本合同审计。可复用模型依赖与核心识别能力，不能原样接入并宣称隐私、时序或取消语义已满足。

因此当前最具体的下一交付是：把上表作为只读来源核验范围候选审查，先解决真实窗口图与几何/结构的可观察性；生产 pane 识别与严格跨源同代继续明确阻塞，不先写无证据的 producer 或执行许可。
