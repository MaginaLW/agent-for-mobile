# 窗口清单最小诊断设计

日期：2026-11-01。源码基线：`7d004fa3f92cb87a327b4f42e5a93eb706fc5524`。本次为离线源码核定与设计，没有实现、fixture、设备调用或新运行批次；T-L1/P0/execution 状态不变。

承接[视觉合同 §5/§7](2026-11-01-平板window-pane视觉证据合同-design.md)。目的只回答 window inventory 为什么不完整，不解释 ROM 根因、不恢复 opaque 树的语义、不生成布局许可。诊断可独立完成设计，但不能凭本设计直接创建真机候选。

## 1. 已核对的读取与丢弃边界

[TabletC1bProbe.captureFrame/captureWindowShell](../../app/gateway/src/main/java/dev/magina/gateway/tablet/c1b/TabletC1bProbe.kt) 先执行一次 `windows().toList()`，成功后只处理 `take(maximumWindows)`；默认预算 16。以下表按现有执行顺序列出**导致窗口壳丢弃的首次停止点**。不得为了诊断继续读后续字段。

| 次序/阶段 | 读取失败类别 | 成功读取但不合法类别 | 现有合法边界 |
|---|---|---|---|
| 1 type | `window_type_read_failed` | `window_type_invalid` | 0..255；未识别的合法值仍保留为 unknown |
| 2 display | `window_display_read_failed` | `window_display_invalid` | 0..16 |
| 3 layer | `window_layer_read_failed` | `window_layer_invalid` | -32768..32767 |
| 4 touchable bounds | `window_touchable_bounds_read_failed` | `window_touchable_bounds_invalid` | null 合法；非 null 须满足现有 isSchemaBounded |
| 5 active | `window_active_read_failed` | 无独立非法值类别 | 布尔值；按现有失败/null 分支记读取失败 |
| 6 focused | `window_focus_read_failed` | 无独立非法值类别 | 同上 |
| 7 id | `window_id_read_failed` | `window_id_invalid` | 非负原生 ID；只在内存比较，不输出值 |

`windowBounds` 在以上七步之后读取；读取失败、非法 bounds、title 失败、root 缺失或读取失败均**保留窗口壳**，不能计入上述丢弃。pane/node 预算也不是 window 丢弃。跨 display 的合法窗口会保留并产生原有 blocker，不能把它算作非法 display。

现有 `diagnosticCodes` 是集合，既失去发生次数，又混有保留窗口后的读取错误。[C1bRawFrame.toJson 与 TabletC1bAssembler](../../app/gateway/src/main/java/dev/magina/gateway/tablet/c1b/TabletC1bModel.kt)不序列化该集合，assembler 另从 observation 重算高层 reason。故不能简单把整个集合公开为诊断计数，或将其加入现有 reason_codes。

## 2. 最小持久数据及守恒

以下语义的具体建议 wire 在 §3.1 固定，尚未发布或实现。每帧只增加一个定长汇总，不增加逐窗口记录、getter、帧或图像。

- 枚举状态：`complete` / `failed`。这里指既有 `windows().toList()` 整个表达式完成与否，不进一步声称是 Android windows 调用还是本地列表复制失败。
- 数量状态：`exact` / `unavailable` / `overflow`。精确输入数量 N、预算 B、尝试 A、保存 S、丢弃 D、未尝试 U；B 仍为原预算，A/S/D 各不超过 B。输入与未尝试可用 0..2147483647 的整数承载，所有运算先提升为 Long 后校验，不截断或饱和成“精确值”。当前 Kotlin List.size 不会超该范围，overflow 仅为无法精确表达时的明确失败形态，不读取额外内容来补数。
- 12 个固定失败类别的计数（表中 type/display/layer/touchable/id 各两类，active/focused 各一类），未发生为 0，禁止自由文本/未知类别；每个被丢弃窗口只记首次停止类别。
- 无需新增 unknown-type 计数：从原 observation 已保存窗口的 `type == unknown` 重算即可。也不重复输出 root/树诊断或窗口原生 ID。

枚举完成且数量精确时，consumer 必须独立验证：

```text
1 <= B <= 16
A = min(N, B)
N = A + U
A = S + D
D = sum(12 个首次停止类别计数)
S = 本帧原 observation.a11y_windows.length
windows_truncated = (U > 0 || D > 0)
```

枚举失败时 N/U 不可知，不能写 0；A=S=D=0、各失败桶为 0、数量状态 unavailable、`windows_truncated=true`，原 observation 窗口数组为空。失败信息仅限闭合状态，不存异常内容或推断异常类型。

overflow 时所有无法精确表达的数量为空，不能把 unknown 当零；诊断验证结果明确为不可用，不进入上述守恒成功分支，不替代原 observation 的截断判断，不授予新结论。

空清单是 complete/exact 且 N=A=S=D=U=0，区别于枚举失败；它仍受原窗口数量与拓扑门限制。unknown type 可以出现 N=A=S、D=U=0、windows_truncated=false，但类型 inventory 不完整，原 IME/focus 阻断保持。root 完整但 opaque 与 subtree read_error/truncated 仍分别由原合同判断。

## 3. 承载选择：同次结果中的独立版本封套

建议保留现有 C1b-v1 observation 的字段、schema、校验器及冻结证据不变，在未来固定候选的**同一次 result 响应**中使用独立闭合版本封套。封套仅含版本、原 observation JSON 字符串和两帧诊断汇总；汇总按 `capture_id` 与 `capture.token` 精确绑定，顺序必须 c1/c2，不重复抄写 run/SHA/T0 身份。

选择 JSON 字符串而非解析后重序列化对象，是为保留 producer 已生成 observation 的 UTF-8 原文，避免引入规范化/哈希重建规则。解出字符串后用严格 UTF-8 无 BOM 编码，原 observation 的现有绑定与校验不变；新封套自身及原 observation 分别保存原始字节哈希。控制/失败响应继续保持控制对象，不当成成功封套。具体建议版本与字段见下，不直接改现行 v1。

| 方案 | 成本与边界 | 结论 |
|---|---|---|
| 同次 result 封套 | controller 组装时绑定原文与定长汇总；runner 显式解封并分别校验。没有第二次设备读取或新的设备生命周期；JSON 转义会增加字节数 | 推荐；仍保持现有总输出上限，超限失败，不截断、不重试、不自动回退 |
| 独立设备 sidecar | 需要新读取端点/允许列表、两产物寿命及跨读取身份/完整性绑定，还要定义部分读取失败和清理 | 本阶段不选；为计数诊断增加额外协议与设备读取 |
| 给 v1 frames 或 reason_codes 塞字段 | 改动现有 closed schema 与精确 key 测试，容易使旧消费者误收新版本 | 不选；不改冻结合同 |

封套不是透明兼容层。旧 runner 遇新封套必须拒绝；新诊断候选遇裸 v1 也应拒绝诊断验收，不能默默退到“无诊断也通过”。历史 v1 继续由原入口离线验证，不能为历史帧合成缺失计数。

### 3.1 建议 wire：tablet-c1b-inventory-result/v1

外层是对象，**仅允许且必须包含**以下三个键；所有层级均拒绝重复键、未知键、错误类型和大小写变体。以下是可评审设计，不新增 schema 文件或实现代码。

| 键 | 精确值或约束 |
|---|---|
| `schema` | 字符串常量 `tablet-c1b-inventory-result/v1` |
| `observation_json` | 未经解析重排的原 v1 JSON 字符串；解码后的严格 UTF-8 字节数 1..1048576 |
| `inventory_frames` | 恰好两个对象，顺序分别绑定内层 frames[0]/frames[1]，token 固定 c1/c2 |

每个 inventory_frames 对象仅含以下必填键：

| 键 | 约束 |
|---|---|
| `capture_id`、`capture_token` | 分别精确等于对应内层帧 capture_id、capture.token；候选当前 controller 仍为 capture-c1/capture-c2 与 c1/c2 |
| `enumeration_status` | `complete` 或 `failed` |
| `count_status` | `exact`、`unavailable` 或 `overflow` |
| `maximum_windows` | 整数 1..16（B） |
| `input_count`、`unattempted_count` | N/U；exact 时整数 0..2147483647，其余状态为 null |
| `attempted_count`、`saved_count`、`dropped_count` | A/S/D；整数 0..B，所有数量拒绝小数、字符串、负数、布尔值和指数数字表示 |
| `first_stop_counts` | 恰好包含 §1 的 12 个失败类别键，每项整数 0..B，零项也必须存在；无逐窗口数组 |

合法状态组合只有三种：

1. `complete/exact`：满足 §2 全部守恒式及内层 truncated 对照。
2. `failed/unavailable`：N/U=null，A=S=D=0，12 桶全零；内层窗口数组空且 windows_truncated=true。
3. `complete/overflow`：N/U=null；A=S+D≤B、D=桶和、S=内层数组长度，仍需验证；但永远给出诊断失败 `count_overflow`，不输出计数完整结论。该组合不强行修改内层 windows_truncated，避免以诊断状态反写旧 observation。当前 List.size 范围内不会自然产生此状态；consumer 必须拒绝它进入成功路径。

其他组合、count_status 缺失或把 null 换成 0，均为 `shape_invalid`。capture_id/token 在不同 run 会重复，**不是跨 run 唯一标识**：可信关联来自 controller 同一 `BoundFrame.request` 的 c1/c2 组装，且 `c1.request == c2.request`；consumer 校验内层 run_id、候选 SHA、APK 哈希和原 T0 字节锚点。封套来自固定 APK 的同次结果通道而非任意拼装文件；哈希只校验保存完整性，不自证 producer 真实性。没有另加可自报的外层 run/SHA 来假装独立证明。

严格解析顺序：先验证外层总字节数仍为 1..1048576，拒绝 BOM/非法 UTF-8；以能检测重复键的解析器读外层，拒绝 JSON trailing 内容、孤立 surrogate、非法转义及嵌套深度超过现有 100 上限。对解出的 observation_json 再检查完整 Unicode scalar 序列，并以严格 UTF-8 无 BOM 编码，不 trim、不换行转换、不 Unicode 归一化；对内层所有对象同样拒绝重复键和非法 Unicode，再运行现有 v1 形状/绑定 validator。不能使用默认“后键覆盖前键”解析器跳过这一层。输出上限不因字符串转义膨胀而提高，超过即失败。

内层 `observation_json` 首字符不得为 U+FEFF（BOM），不能通过 trim 或重编码移除后接受。

### 3.2 持久产物与 run 收据兼容

新候选使用 `tablet-c1b-run/v2` 收据，保留现有字段及含义；新增且仅新增 `result_schema`、`result_envelope_sha256`、`inventory_validation`。前两项初始 null，成功识别外层后分别为上述常量及原始封套字节的 sha256；绑定未通过时可以在收据记录哈希，但不保存未绑定内容。`inventory_validation` 是闭合对象，键为 `status`（not_run/failed/passed）与 `reason_codes`（固定字符串数组）。not_run/passed 必须空 reason；failed 恰好一项，对应首次停止点。

闭合 reason 集合：`encoding_invalid`、`duplicate_key`、`shape_invalid`、`version_mismatch`、`observation_invalid`、`run_binding_mismatch`、`capture_binding_mismatch`、`count_mismatch`、`count_overflow`、`output_size_exceeded`。只记录首个校验停止点对应的代码；不记录异常原文、坏值、nonce 或 raw ID。outer/inner 编码错误统一 encoding_invalid，原 v1 验证失败统一 observation_invalid，原 run 绑定失败仍保留已有 result_diagnostic.binding_failure 的精确闭合字段名。

成功验证 run 绑定后，新增持久文件 `tablet-c1b-inventory-result-v1.json` 保存接收到的封套原始字节；既有 `tablet-layout-observation-c1b-v1.json` 保存 observation_json 解码后的严格原文 UTF-8 字节。已有 observation_sha256 继续指内层原文，result_envelope_sha256 指外层，两者不可互换。两份文件都纳入归档清单。诊断失败仍使 run outcome=failed；保留已通过绑定的证据和失败收据，不重采或改写内层结果。

run.json 的 v2 是显式兼容边界：消费它的 runner 离线 fixture、归档步骤和任何按 schema 验证的脚本须一起检查；未知版本消费者停止，历史 v1 收据不迁移、不补字段。本建议不改变现有协议控制对象或其 schema；新 runner 用预期结果版本区分控制失败、新封套和裸 v1，不做启发式兼容。

## 5. 最小反例与实施门槛

本表仅是设计验收输入，尚未新增或运行测试。

| 反例 | 必须检查的结果 |
|---|---|
| 枚举抛异常 vs 成功空列表 | 前者 N/U 不可知且 truncated；后者精确零；不得同判 |
| N=17，前 16 个均保留 | A=S=16，U=1，D=0；第 17 个没有 getter |
| N=17，预算内 12 个首次停止 | A=16，S=4，D=12，U=1；不能用“保存 4”反推输入只有 4 |
| 同一窗口 type 与 layer 均会失败 | 只执行 type 读取并计一次，layer 未读；用调用日志断言，不只验计数 |
| 七个阶段各自抛异常，五个可非法字段各自坏值 | 分别命中 12 桶；短路之后 getter 调用数为零；错误消息/坏值不出现在 JSON/toString |
| touchable null、合法 unknown type、合法异 display | 均保留壳；unknown/跨 display 原阻断仍在；不能误记丢弃 |
| windowBounds/title/root/child 出错 | 壳保存计数不减，原几何/语义/树 blocker 仍在 |
| 一帧计数不守恒、S 与数组长度不符、桶和错误 | 新诊断验证失败，不默默修正、不影响旧证据 |
| 诊断帧互换、重复 token、旧 run observation 拼接 | 绑定失败；外层版本和字段集合严格检查，任何新增自由字段拒绝 |
| 两个 run 都使用 capture-c1/c1，诊断汇总被跨 run 搬入 | 不能靠帧标签判断可信；producer 同一 BoundFrame/request 组装约束和候选结果通道必须有测试，内层错 run/SHA/T0 必须拒绝；离线自报计数不能冒充真实来源 |
| outer/inner 重复键、孤立 surrogate、非法 UTF-8、BOM、尾随 JSON | 编码或重复键检查拒绝，不能由宽松解析/重编码修复；原文字节不变 |
| 外层哈希/内层原文字节不符、旧 runner 读新封套 | 拒绝；不靠 JSON 重排“修好”字节，不自动降级 |
| overflow、封套转义后超过现有上限 | 诊断不可用或现有输出大小失败；无伪精确计数、无升限/重采 |
| 新实现与基线相同 fake 输入 | 原 v1 序列化及所有安全结论相同；getter 次序、次数一致，无新设备读取 |

§3.1–§3.2 已给出供审查的精确版本/字段和 run 收据兼容建议；实施前完成 probe→controller→runner→归档完整链审查，不再以“另定 wire”为独立研究阶段，也不得只实现 producer。实施时复用 [ProbeTest](../../app/gateway/src/test/java/dev/magina/gateway/tablet/c1b/TabletC1bProbeTest.kt)、[RuntimeControllerTest](../../app/gateway/src/testDebug/java/dev/magina/gateway/tablet/c1b/TabletC1bRuntimeControllerTest.kt)、[RuntimeSurfaceTest](../../app/gateway/src/testDebug/java/dev/magina/gateway/tablet/c1b/TabletC1bRuntimeSurfaceTest.kt)及 [runner 离线测试](../../scripts/tests/tablet-c1b-runner-offline.ps1)，保留 v1 精确 key/隐私/现有高层阻断回归，按[离线规程](../runbooks/离线开发与验证.md)运行必要门禁。

当前仅完成诊断来源、分类与最小承载设计；并未解决视觉来源、阶段时钟、pane 语义或真机准入。后续实现仍受视觉合同 §7 与 backlog 队列约束，真机须固定完整 SHA、新就位和专属开跑令；不得以本设计回填 ccc8cce 或其他冻结轮。
