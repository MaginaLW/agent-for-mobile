# 本地测试台：靶标与网关闭环

日期：2026-11-11。承接[减少人工介入 §10](2026-11-11-减少人工介入总体思路-design.md#10-实施顺序与批次验收2026-11-11)批次 3–4。基线 `3e93d9389f0e3fb9c8d0531587ca3f3e91d979d9`，实施分支 `codex/reduce-manual-offline`。

目标是把普通开发迭代搬到可丢弃的 API 36 模拟器：运行真实 gateway APK，经现有 HTTP MCP 入口导航到合成靶标、枚举并操作合成控件、等待确认及核对审计。靶标不是微信替身的有效性证明，不能消掉 ROM 差异轮，也不能绕过设备端真人确认。

## 1. 当前源码与环境核对

- `app/settings.gradle.kts` 现有 gateway 与独立 C1b 模块；gateway compile/target 为 35，minSdk 30。API 36 模拟器运行不要求把生产 compile/target 升到 36。
- `McpServer` 绑定 `127.0.0.1:8848`，入口 `POST /mcp`，Bearer 鉴权及 MCP 版本策略沿用原实现；`GET /health` 只证明 HTTP 入口，不证明无障碍可操作。
- `ToolRegistry` 的 `ui_action` 为 W 级，`SafetyPolicy` 对 **所有** click/long_click 要求确认；未命中风险词也不免确认。focus/set_text 没有该动态危险判据，但仍经过已知前台与目标证据复核。台架不得按“测试控件无害”取消确认。
- SDK 只读目录核对：已有 platform-tools、platform 35、cmdline-tools latest（source.properties 为 22.0，含 sdkmanager/avdmanager）；缺 emulator、platform 36、API 36 system-image。当前 JAVA_HOME 未设，PATH 可定位 java/javac；实际 JDK 版本和可用虚拟化仍需执行准备时核验。本次摸底未运行 SDK 管理器、Gradle、ADB 或模拟器。
- `Audit` 写应用 `files/audit/YYYYMMDD.jsonl`，每次工具调用带 audit id；取证使用隔离模拟器的 `run-as dev.magina.gateway`，不能用旧 external-files 路径或只看客户端响应。

上述是本地源码/目录检查，尚不是台架运行结果。

## 2. 靶标最小实现

模块 `app/test-target`，applicationId `dev.magina.testtarget`，仅显式 `-PlocalTestbench=true` 纳入，C1b 隔离构建不纳入。复用已有 Android/Kotlin 插件及 compile/target 35，不加第三方依赖。清单没有权限、网络、账号、Service 或 Provider，内容全部为固定合成文本。Android 的系统状态/任务截图不在 App 业务存储控制范围内，不宣称系统逐字节擦除。

靶标入口为普通 launcher，另支持 `agent-testbench://target/<route>` 的 ACTION_VIEW。页面包括：

| route | 内容与观测点 | 能证明什么 |
|---|---|---|
| list → search → conversation | 真实按钮路径、搜索输入与固定联系人甲会话；列表和标题含同名项 | 有条件的人控点击导航覆盖；自动深链只能证明路由，不能冒充点击导航 |
| conversation | 普通可访问标题、合成消息、输入框、发送按钮、内存计数 | gateway 可枚举/解析 ref，focus/set_text 可落地；未确认不得触发按钮回调 |
| opaque | Canvas 画固定内容，并隐藏其可访问子树 | 可见画面与无语义子树的合成案例；不保证等同微信 opaque 根或不触发 OCR |
| degenerate | 一个应用 View 声明不可见、屏幕/父坐标均为零矩形 | 应用节点的畸形声明；框架可能裁剪/规范化，必须采样，不等于系统根状态 |
| ime | EditText 请求系统 showSoftInput | IME 请求与实际 keyboard_state 分开；请求成功不证明实际可见/绑定 |

稳定资源 ID：`target_search_input`、`target_composer`、`target_send`、`target_action_count`。发送按钮只累加本 Activity 的内存 callback 次数；不保存、不联网、不访问真实 App。新页面/Activity 重建计数归零，观察途中不得通过重建把“不知道是否执行”改成零次。

## 3. 能复刻与不能复刻的分界

| 病灶 | 靶标/模拟器方法 | 留给宿主或 ROM 的部分 |
|---|---|---|
| 普通树与标题/输入/同名项 | 原生 Android Views | 微信真实结构、会话身份、安全区域 |
| opaque 子树、不可见/退化节点 | App 公共无障碍节点声明 | 系统返回根的具体过滤及微信真实 opaque 原因 |
| 多任务、两个应用窗口 | resizeable Activity；隔离模拟器显式创建两个任务并读回窗口 | LaunchAdjacent/分屏请求可能被系统忽略；OriginOS 同一微信双窗、悬浮窗与层叠规则仍是 ROM 差异 |
| IME 显示/隐藏 | 普通输入框和系统 IME，读回实际窗口状态 | OriginOS 浮动/硬键盘策略与安全区域；不将保守 false 当隐藏 |
| `type=-1`、截断、非法层号/几何组合、清单计数不守恒 | **仅宿主已有真实语料与有界变异** | 普通 App 没有公开 API 指定系统返回的 AccessibilityWindowInfo type；不能声称在靶标造出同一系统窗 |
| vivo 安全中心撤销、后台保活、确认卡 z-order、安装监控 | 模拟器不证明 | 明确留真机差异；不改安全中心、不模拟成“已修复” |

靶标只产生输入。判定继续走现行 reader/validator/SafetyGate，不另造一套宽松预期。

## 4. 实际使用链路与完成证据

所有步骤限定台架自己创建的 AVD、模拟器 serial 与 localhost 端口，开始前确认无物理设备目标。ADB 每条命令必须显式隔离 server/serial，不能使用不带 serial 的默认设备选择；若所装 emulator 无法可靠绑定隔离 server，先停下解决隔离，不探测或切换到手机。

1. **构建与身份**：固定完整 SHA，构建真实 gateway debug 和 test-target APK；分别记录 APK SHA、公有签名证书 SHA、包/版本。生产源不因台架添加免确认能力；生成物只在忽略目录。
2. **一次性台架准备**：启动可丢弃 API 36 AVD，验证系统 API 与目标 serial；只在该 AVD 安装两包、授予 gateway 无障碍并启动前台服务。gateway token 仅从该 AVD 私有状态读取到本地忽略配置，不输出、不入库；不是生产凭据许可。
3. **现有真实入口**：通过 localhost 转发访问 `/health`；向 `/mcp` 执行 initialize、tools/list、foreground_app。正常调用必须得到 gateway 的标准信封、上下文和 audit id。可以使用现有 gateway HTTP MCP 入口作确定性台架；若跑大脑，经 `dispatch.ps1 -Brain codex -Executor gateway` 的官方订阅入口，不用测试台直连模型私有接口。台架确定性调用与真实大脑派单结论分别记录。
4. **路由与枚举**：用现有 `intent_send`、ACTION_VIEW、package=`dev.magina.testtarget`、URI=`agent-testbench://target/search`，核前台落地；`ui_snapshot` 以唯一 input 角色和固定合成文本取当前 ref。资源 ID 只稳定靶标内部结构，现行 gateway 快照不输出它，不能声称按 ID 定位。深链不修改生产技能包或伪造分享组件白名单；list/search/conversation 各自快照可证明路由，不证明实际点击导航。
5. **无需确认的受控动作**：从当前真实快照取 search/composer ref，执行 `ui_action focus`、`ui_action set_text`（只填合成短文本）。再次快照逐字核对输入，audit 的 `result=OK`、`channel=a11y`、audit id 一一关联。ref 变化时重新感知只用于新的普通动作，不重试失败危险动作。
6. **真实确认等待与不执行**：在 conversation 页读取计数 0；对 `target_send` 的真实 ref 发一次 `ui_action click`。观察已有 ConfirmOverlay 等待，台架不向 overlay 发送点击、广播、TestControl 决定或 PC 回执。等既有 60 秒确认超时，要求标准 `E_CONFIRM_TIMEOUT` 及对应审计；重读计数仍为 0。命令/HTTP 上层等待需大于确认自身超时，防止客户端先断开留下结果未知。
7. **收尾**：收取对应时段的原始 MCP 响应、应用内 audit、靶标计数快照与固定身份到本地忽略目录，输出脱敏汇总；关闭仅本轮启动的模拟器并核进程终止。响应、审计或身份缺失即 UNKNOWN/FAIL，不把“进程结束”当作应用业务清理证明。

这一无人段证明真实 APK/入口的路由、枚举、普通动作、确认等待、超时不执行和审计闭环。一次真实允许后恰好回调 1 的路径，以及真正的点击 list→search→conversation，需要真人在可见设备确认卡逐次决定；该人控段不能因模拟器被称为无人值守。批次 3 的 JVM confirmer 注入只覆盖状态机，不能替代这个人控证据。

## 5. 依赖准备与停止条件

依赖准备和首次台架启动由主 A 单实例执行，预计需下载约 GB 级 system-image 并占用数 GB 内存；精确大小和资源以 SDK manager 元数据及启动前实际读回为准，不承诺在未知环境整夜运行。

- 复用现有官方 cmdline-tools，`sdkmanager --sdk_root=<project-root>/.checks/reduce-manual-20261111/testbench/sdk "platform-tools" "emulator" "system-images;android-36;google_apis;x86_64"`。已有 compile 35 可继续供构建读取；若需要同一 SDK root 构建，再准备 platform/build-tools 的锁定版本，不能悄悄升级工程插件或生产 target。
- 仅复制已接受且与所需包相符的 license 文本；缺必要许可时保留精确缺项，不自动改全局 SDK/AVD 状态。SDK manager、AVD manager、emulator 子进程的 TEMP/TMP、ANDROID_USER_HOME、ANDROID_AVD_HOME、cache 和日志显式落在本轮 testbench 目录；不使用全局默认 AVD，不改系统环境变量。
- AVD home、name、端口、RAM 和数据目录均预先固定；优先无快照、无音频、无真实账号的可丢弃 AVD。启动前核 CPU 虚拟化/加速可用性及当前内存；加速不可用或启动超时保留日志，不为了通过自动改 BIOS、驱动或 Windows 功能。
- 下载失败/校验失败不伪报安装；只在原范围、预算与无副作用可核实条件下恢复。模拟器启动/安装/服务前置失败则不进入 MCP 动作段；错误证据先保存，修正明确原因后形成新本地台架尝试。此本地测试恢复规则不追溯改变真机冻结轮。
- 任一 MCP 安全终态、出现非靶标前台、serial/包身份失配、审计丢失或误触真实设备，立即停本链并保留未知，不切目标或自动重发危险调用。
