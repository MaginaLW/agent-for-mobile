- 决策人：Magina（用户）
- 当前状态见 [STATUS.md](../../STATUS.md)；危险动作确认以 [危险动作统一硬门](2026-07-19-危险动作统一硬门-design.md) 为准
- 证据基础：[主设计](2026-07-16-方向一-手机执行器与订阅大脑-design.md) · [M0 跑测记录](../runs/2026-07-16-M0.md) · [M1 Spike 结论](../runs/2026-07-17-M1-spike.md) · [执行 harness](2026-07-17-执行harness-design.md)

## 0. 一句话

M1 执行器从「无障碍服务 + 截图 + MCP server」升级为**多通道执行网关**：六级通道按成本从低到高排序（系统 API/CLI → Intent/深链/分享 → 通知 → 无障碍语义树 → 本地 OCR/视觉融合 → 大模型看原图），网关内建自动降级与复核，**能走结构化接口的操作默认不许用截图**。这是把 cost.md 的可行性结论（深链、树优先是可行性前提）从大脑侧规约下沉为执行器侧机械结构。

## 1. 问题定义（M0/M0.5 实测）

M0 的核心病灶是**「大脑逐轮看图」循环**（截图 → 理解 → 算坐标 → 点击 → 再截图）：纯视觉任务成本高一个数量级（任务 2 病态排障 $6.44/186 轮）；截图缩放坐标错位、软键盘坐标漂移、页面回弹导致误触与空转；剪贴板中文输入被系统拦截；`uiautomator dump` 在重动画 App 超时、对微信恒空。根因都是**信息在最贵的通道上流动**，M1 的架构任务是按通道成本重新分配信息流。

## 2. 与主设计的关系

方向一致，是超集扩展。对主设计的修订（均已应用）：

- 执行器职责改为「手 + 眼 + 反射弧（机械策略）」，MCP 契约仍是唯一边界。
- 工具面 v0 → v1（§5），`screenshot` 降级为受控 `screen_capture`。
- 技能包数据拆两半：决策知识留大脑侧 skills/，路由数据（深链表、页面指纹、模板图）编译进执行器，同源维护（§11 约束 3）。
- minSdk 26 → 30（`takeScreenshot` 需要）。
- 站规「同法失败 ≤2 次」由网关机械化（`E_RETRY_EXHAUSTED`），站规降为提醒。
- M1 验收另加成本维度：台账记 `executor`，新旧链路同任务对比。

## 3. M1 分层架构

```
大脑（Claude Code / Codex CLI，M1 在 PC · M2 迁 Termux）
    │  MCP Streamable HTTP + token（唯一契约，不变）
    │  M1: adb 端口转发 / 局域网 · M2: localhost
┌───▼──────────── 执行网关 App（Kotlin/Compose，minSdk 30）────────────┐
│ L0 网关核心（横切）                                                  │
│    Ktor MCP server · 能力探测(capabilities) · 动作分级/黑名单         │
│    统一安全门 · 统一响应信封+错误模型 · 同法重试计数器 · 审计 jsonl   │
├──────────────────────────────────────────────────────────────────────┤
│ L1 系统通道   Kotlin API（无特权）→ AppOps 授权类 → Shizuku shell 白名单│
│ L2 意图通道   深链注册表 · Intent 白名单 · 系统分享 · 执行后前台校验    │
│ L3 通知通道   NotificationListener · 快捷操作 · RemoteInput 直接回复   │
│ L4 UI 通道    自研 AccessibilityService：事件驱动树缓存 · ref/revision  │
│ L5 视觉通道   a11y takeScreenshot → 本地 OCR → 节点/OCR 融合语义 JSON  │
│               图标模板匹配（技能包资产）· 页面指纹分类                 │
│ L6 兜底       screen_capture(受控原图)：要 reason · 局部裁剪优先        │
├──────────────────────────────────────────────────────────────────────┤
│ 伴生服务：自有 IME（commitText 精确注入，兼作剪贴板读取通道）           │
│           确认卡悬浮窗（统一安全门的唯一批准 UI）                       │
│ 数据：执行器侧技能包（深链表 · 页面指纹 · 图标模板 · 危险控件词表）      │
└──────────────────────────────────────────────────────────────────────┘
```

**自动降级策略（L0 统一实现）**：每个工具声明自己的通道序列；纯机械的回退（如 Kotlin API 拿不到 → Shizuku shell）网关内直接换；需要改变路径的（如深链失败 → UI 导航）返回结构化错误（原因 + 是否允许回退 + 建议下一步）由大脑决策。同一「工具+参数指纹」失败计数 ≥2 后第三次调用直接拒绝（`E_RETRY_EXHAUSTED`）。安全失败不计入该计数（硬门不变量 8）。

**坐标主权收归网关**：网关内一切坐标均为物理像素；裁剪图携带 offset/scale 元数据；模型只见 ref 与 bounds（仅供理解布局，不用于点击）。

## 4. 统一响应信封与错误模型

所有工具共用一个信封；**每个响应自带执行环境快照 `ctx`**，减少「点完再问在哪」的往返：

```json
{
  "ok": true,
  "data": { },
  "ctx": {
    "app": "com.tencent.mm", "activity": ".ui.LauncherUI",
    "page": "chat|unknown", "revision": 18,
    "keyboard": { "visible": true, "height": 882, "ime": "own|other" },
    "screen": "on", "caps": ["a11y", "shizuku", "notif", "ime"]
  },
  "audit_id": "a-000123"
}
```

```json
{
  "ok": false,
  "error": {
    "code": "E_STALE_REF",
    "message": "ref v18 属 revision 12，当前已是 17",
    "channel": "a11y",
    "retryable": false,
    "fallback": "先 ui_snapshot 刷新再操作"
  },
  "ctx": { }
}
```

错误码枚举（封闭集，大脑可据此写死策略）：

| code | 含义 | 典型 fallback 建议 |
|---|---|---|
| `E_PERM_MISSING` | 缺权限/能力位（附开启指引文本） | 报告用户，人工开启 |
| `E_CHANNEL_DOWN` | 通道不可用（如 Shizuku 未激活） | 网关已自动换通道仍失败时才抛 |
| `E_UNSUPPORTED_KEY` | system_* 的 key 不在白名单 | 无，改用 UI 通道 |
| `E_NOT_FOUND` | 元素/通知/媒体未找到 | ui_snapshot / 滚动查找 / wait_for |
| `E_AMBIGUOUS` | 多个匹配（data 附候选列表） | 大脑挑选后按 ref 精确操作 |
| `E_STALE_REF` | ref 已过期；危险调用确认后上下文失效也用此码 | 非危险调用：ui_snapshot；危险调用：安全终态 |
| `E_TIMEOUT` | wait_for / 操作超时 | 换条件或报告 |
| `E_VERIFY_FAIL` | 动作已发出但复核不符（附实测值） | 大脑决策：重试/换路/报告 |
| `E_BLOCKED` | 命中敏感黑名单，或用户在确认卡上拒绝 | 无，报告并停 |
| `E_CONFIRM_REQUIRED` | 危险动作未获确认 | 安全终态，按终态报告，不得重试 |
| `E_CONFIRM_TIMEOUT` | 确认卡超时无人响应 | 安全终态，按终态报告，不得输出 `[AWAIT_CONFIRM]` |
| `E_RETRY_EXHAUSTED` | 同法失败已达 2 次 | 换通道或收尾报告 |
| `E_LOW_CONFIDENCE` | 视觉融合置信度低 | screen_capture(region) 视觉复核 |
| `E_RATE_LIMITED` | 截图/动作节流 | 稍候（data 附冷却毫秒） |

危险调用的 safety 结果（拒绝、超时、stale、blocked、确认通道/权限错误）一律是本腿终态，见[硬门 spec](2026-07-19-危险动作统一硬门-design.md) 与执行 harness spec §5。

## 5. MCP 工具面 v1

定稿时 22 个；2026-07-19 起 `confirm` 移出工具面（见 §5.4）。动作级别：**R** 只读 / **W** 普通写（自由 + 审计）/ **D** 危险（统一硬门确认）。级别是工具默认值，`ui_action`、`press_key` 等的实际级别由**目标与参数**决定（命中危险控件词表即升 D；`press_key(enter)` 恒按危险处理）。

### 5.1 系统层（L1）

| 工具 | 级别 | 参数 | 返回 data | 实现通道（主→备） |
|---|---|---|---|---|
| `device_info()` | R | — | 物理分辨率/密度/系统版本/能力位/电量 | Kotlin API |
| `system_get_state(key)` | R | key ∈ 白名单枚举：bluetooth, wifi, airplane, battery, network, volume, brightness, screen_lock, do_not_disturb… | `{value, source, cross_checked}` | Kotlin API → Shizuku `dumpsys` 交叉复核 |
| `system_set_state(key, value)` | W（部分 D） | 可写 key 是读白名单的子集 | `{applied, verified, actual}` | Shizuku shell 白名单 → 失败报错建议 Intent 设置页 + UI 兜底；**内部强制执行后复核**（settings 键不可信，用 dumpsys/API 做真值） |
| `system_verify_state(key, expected)` | R | 同上 | `{match, actual, source}` | 同 get，但走与 set 不同的真值源 |
| `foreground_app()` | R | — | `{package, activity, page_hint}` | 自研 a11y 窗口事件 → Shizuku `dumpsys activity` |
| `keyboard_state()` | R | — | `{visible, height, ime_package}` | a11y windows（输入法窗口） |
| `app_launch(name_or_package)` | W | 名称经技能包解析到包名 | `{launched, foreground_verified}` | Intent LAUNCHER → Shizuku `am start`；执行后前台校验 |
| `app_stop(package)` | W | — | — | Shizuku `am force-stop`（无特权则报 E_CHANNEL_DOWN） |
| `clipboard(op, text?)` | R/W | op ∈ get/set | `{text}` | set: ClipboardManager；get: 自有 IME 焦点通道（Android 10+ 仅默认 IME 与焦点 App 可读） |
| `media_query(type, album?, order?, limit?)` | R | type ∈ image/video/screenshot | `[{uri, name, time, size}]` | MediaStore ContentResolver |

**硬约束：不存在 `shell(command)` 工具。** Shizuku 通道是网关内部实现细节，暴露给模型的只有类型化白名单工具；白名单命令、参数校验、执行后复核、审计全部在工具内部完成。

### 5.2 意图层（L2）

| 工具 | 级别 | 参数 | 返回 data | 实现 |
|---|---|---|---|---|
| `open_uri(uri)` | W | 深链或 https；先查技能包深链注册表 | `{opened, foreground_verified, registry_hit}` | Intent ACTION_VIEW；**执行后必验前台**（OriginOS 深链假成功实锤）；失败返回 UI 导航兜底提示 |
| `intent_send(action, uri?, extras?, package?, component?)` | W | action 限白名单（VIEW/SEND/SENDTO/MAIN/设置类 action 枚举）；component 仅接受技能包注册项，显式 package 与 component 所属包须一致 | `{sent, target_package, foreground_verified, verification_scope, verification_status}` | 指定 package/component 时等待正向前台落地；组件须命中该组件或已登记的分享落地 activity，超时/无证据报 `E_VERIFY_FAIL`。未指定目标仅报告 `dispatched_unverified`（已分派、未验证）。真机验收状态见 [backlog](../backlog.md) R5。 |
| `share_text(text, target?)` / `share_file(uri, mime, target?)` | W | target 为空走系统分享面板 | 同上 | ACTION_SEND；uri 经 FileProvider/MediaStore |

### 5.3 通知层（L3）

| 工具 | 级别 | 参数 | 返回 data | 实现 |
|---|---|---|---|---|
| `notifications_list(package?, limit?)` | R | — | `[{id, app, title, text, time, has_actions, has_remote_input}]` | NotificationListenerService |
| `notification_actions(id)` | R | — | 动作清单 | 同上 |
| `notification_reply(id, text)` | **D**（对外发送） | — | `{sent, verified}` | RemoteInput + PendingIntent.send；微信国内版大概率不带 RemoteInput，价值主要在短信/邮件/国际 IM |
| `notification_open(id)` | W | — | `{opened, foreground_verified}` | contentIntent.send |

### 5.4 UI 层（L4）+ 视觉层（L5/L6）

| 工具 | 级别 | 参数 | 返回 data | 实现 |
|---|---|---|---|---|
| `ui_snapshot(scope?)` | R | scope ∈ interactive(默认)/full/region | `{revision, page_hint, elements:[{ref, role, text, desc, bounds, source, confidence}]}` | **事件驱动缓存**：a11y 监听窗口/内容变化持续维护语义树，snapshot 读缓存而非现场 dump；**树空/稀疏时自动融合 OCR**（L5），元素带 `source: a11y|ocr|fused` 与置信度；网关自身确认卡不进入快照 |
| `ui_diff(since_revision)` | R | — | 增/删/改元素 + 当前 revision | 缓存树 diff；间隔过大时降级返回全量 |
| `ui_find(text?, role?, desc?, scroll_search?)` | R | scroll_search=true 时网关自己滚动查找（≤N 屏） | 匹配元素列表 | 缓存树查询 + 可选机械滚动 |
| `ui_action(ref, action, params?)` | W（目标定级） | action ∈ click/long_click/set_text/scroll/focus/dismiss | `{done, revision_after, verify}` | 节点动作为主；ocr 来源的 ref 用 bounds 中心手势；**点击前二次校验**（ref 文本/位置与缓存一致才出手）；命中危险控件词表即进统一硬门；机械拒绝作用于网关确认卡；set_text 走 §8 输入链 |
| `type_text(text, ref?, mode?)` | W | mode ∈ append/replace；ref 缺省用焦点控件 | `{committed, readback, match}` | §8 输入链；**内置读回验证** |
| `press_key(key)` | W（`enter` 升 D） | back/home/recents/enter/del… | — | a11y 全局动作 + IME sendKeyEvent |
| `wait_for(condition, timeout_ms)` | R | text_appears/text_gone/app_foreground/keyboard_shown/hidden/idle | `{met, elapsed, revision}` | 事件驱动等待（不轮询、不烧大脑轮次） |
| `screen_capture(reason, region?|ref?)` | R（受控） | **reason 必填**：low_confidence/unknown_page/icon_unrecognized/layout_changed/risk_review | `{image(base64), scale, offset, revision}` | a11y takeScreenshot（秒级节流）；给 ref/region 时只回裁剪图；reason 记审计 |
| `macro_run(name, params)` | 按宏内容定级 | — | — | 通用宏系统排 M3；目前仅 debug 白名单宏（见[监督式跑测设计](2026-07-22-Agent主控监督式真机跑测-design.md) §5.3），其余返回 E_CHANNEL_DOWN |

`confirm(action_desc)`：曾作为带内确认工具（悬浮窗点头，超时走 `[AWAIT_CONFIRM]`）。2026-07-19 因批准不能绑定具体工具、参数与页面而移除，确认下沉为所有 handler 之前的统一安全门，见[硬门 spec](2026-07-19-危险动作统一硬门-design.md)。

## 6. 每层实现选型

**特权位阶**（L1 内部三级，能力探测上报 `caps`，工具按位阶自动降级）：

1. **普通 App API**（零授权）：BluetoothAdapter/WifiManager 读、BatteryManager、MediaStore、Intent、ClipboardManager 写。
2. **AppOps 授权类**（用户手动开一次）：无障碍、通知使用权、悬浮窗、自有 IME 启用。
3. **Shizuku shell 白名单**：`dumpsys`（状态真值）、`svc`/`cmd`（系统开关）、`am`/`pm`（启停）、`settings put`、`ime enable/set`。`WRITE_SECURE_SETTINGS` 可一次性 `pm grant`，IME 切换不再依赖 Shizuku 在线。

关键选型：

- **系统开关写操作离不开 shell 位阶**：Android 13+ 普通 App 无法编程开关蓝牙/WiFi；Shizuku 不在线时降级为「Intent 开设置页 + a11y 点开关」。
- **截图用 a11y `takeScreenshot`，不用 MediaProjection**：免每次授权弹窗与前台服务纠缠；MediaProjection 留给未来连续录屏/宏录制。
- **前台 App / 键盘态用 a11y 事件流**，不用 UsageStats，也不常态用 dumpsys。
- **剪贴板读取靠自有 IME**：自建 IME 顺带解锁这条通道。

## 7. 五个 M0 验收任务的推荐链路

所有发送步骤都经统一硬门确认，「文件传输助手」无白名单（2026-07-19 铁律）。

| 任务 | 推荐链路 | 兜底 |
|---|---|---|
| 1 蓝牙关 | `system_get_state` → `system_set_state(bluetooth, off)`（内含复核），零截图、不碰 UI | Shizuku 不在线：`open_uri(设置)` + `ui_find/ui_action` |
| 2 微信发中文 | `app_launch` → `ui_snapshot`（微信树不可读，走 OCR 融合）→ 定位文件传输助手 → `type_text`（读回验证）→ 发送（确认卡）→ `wait_for` 验证上屏 | 列表点击不导航：改走搜索框 |
| 3 小红书总结 | `open_uri(xhsdiscover://search/result?keyword=…)`（执行后验前台）→ `ui_snapshot`/`ui_diff` 读列表 → 进详情/返回（单击纪律：详情图片区双击=点赞） | 深链失败：UI 导航兜底 |
| 4 截图发微信 | `media_query(screenshot, limit=1)` → `share_file(uri, image/*, target=微信)` → 选人页定位 → 名称复核 → 发送（确认卡）；整段跳过相册与微信选图器 | 分享组件失效：系统相册 App 路径 |
| 5 京东物流 | `app_launch` → `ui_snapshot` → 我的 → 全部订单 → 详情 → 查看物流；「更多」菜单内**危险控件词表拦「删除订单」** | 京东订单深链（入库前按深链规程验证） |

## 8. 中文输入链

三级：**a11y SET_TEXT（首选）→ 自有 IME commitText（兜底）→ 报告失败**。剪贴板粘贴机制废弃（Android 16 实锤不可用）。

- 自有 IME：`commitText()` 字面注入，绕开预测引擎（吞空格、篡改大小写）；`deleteSurroundingText + commitText` 实现 replace。
- IME 切换：`WRITE_SECURE_SETTINGS` 或 Shizuku `ime set`；完成后恢复用户原 IME。
- **验证闭环内置**：提交后读回焦点节点文本；树空场景用 OCR 对输入框区域裁剪读回。a11y 焦点不可得时的显式降级见 [IME 单命名空间降级门](2026-07-25-IME单命名空间降级门-design.md)。

## 9. 本地视觉选型

| 方案 | 判定 | 理由 |
|---|---|---|
| **ML Kit Text Recognition v2 中文（bundled 版）** | 选定 | 端上运行、不依赖 GMS（国行设备无 GMS，必须 bundled）；Spike S3 实测精度与延迟达标 |
| PaddleOCR mobile | 备选升级位 | 中文精度上限更高，集成成本高一档；仅当 ML Kit 精度不达标时启用 |
| 图标模板匹配（技能包资产） | 小规模 | 每 App 固定几个图标按物理分辨率归一后匹配 |
| 轻量目标检测（YOLO-n / UIED 类） | 不进 M1 | 成本高；残余场景须先用台账数据证明存在 |

融合规则（L5）：a11y 节点为骨架，OCR 文本框按 IoU 挂到节点/补空缺，模板命中生成 icon 元素；输出统一 elements JSON（`source` + `confidence`）。整屏 OCR 结果按 revision 失效缓存。

## 10. 权限、ROM 限制、安全与不可实现边界

**权限清单**：无障碍（vivo 有静默回收风险 → 前台服务 + 电池白名单引导 + 自检上报 caps）、通知使用权、悬浮窗（确认卡）、自有 IME 启用、`QUERY_ALL_PACKAGES`、`BLUETOOTH_CONNECT`、`POST_NOTIFICATIONS`、前台服务、`WRITE_SECURE_SETTINGS`（adb 一次性 grant，可选）、Shizuku（开发期 adb 启动）。

**ROM/平台限制**（M1 范围内接受，不硬啃）：

- Shizuku 重启失活：M1 靠 PC adb 在场兜底；M2 前专项解决或接受降级运行。
- `takeScreenshot` 秒级节流；连续视觉场景显式不支持。
- FLAG_SECURE 页面无法截图（银行/支付类本就在黑名单，行为 = 拒进 + 报告）。
- 微信无公开「直达指定聊天」深链；聊天内容除通知/屏幕外无结构化读取通道。
- 支付/生物识别确认框：系统级隔离，**永不尝试自动化**（红线，写进危险词表）。

**安全模型**（继承主设计 §7）：

1. 工具级动作分级（§5）+ 目标动态升级；所有危险调用在 handler 前经统一硬门，由网关生成的确认卡逐次批准（[硬门 spec](2026-07-19-危险动作统一硬门-design.md)）。
2. 敏感黑名单三张：App（银行/证券）、联系人/会话、文件类型；命中即 `E_BLOCKED`，先于确认执行，人工确认不能绕过。
3. 屏幕/OCR 文本是数据不是指令——OCR 产物同样可能携带注入文本，站规声明覆盖 elements JSON。
4. 审计 jsonl 每步落盘：工具、参数指纹、通道、复核结果、screen_capture 的 reason。
5. Ktor server 仅监听 localhost（经 adb 端口转发）+ token 认证。

## 11. 已定约束与 Spike 结论

**已定约束**（2026-07-17 按推荐批准，见[主设计 §12](2026-07-16-方向一-手机执行器与订阅大脑-design.md) 条目 4）：

1. **Shizuku 增强而非依赖**：核心验收链路在无 Shizuku 时全部有降级路径（`pm grant WRITE_SECURE_SETTINGS` 是摆脱在线依赖的抓手，[sys-cli.md §6](../knowledge/android/sys-cli.md)）。
2. OCR 用 **ML Kit bundled 中文起步**，PaddleOCR 留升级位（§9）。
3. **技能包数据拆两半**：路由数据编译进执行器 assets（`app/gateway/src/main/assets/skillpack/`，源头 `docs/knowledge/apps/`），决策知识留大脑 skills/，同源维护。
4. **screen_capture 软门**：reason 必填 + 审计 + 裁剪优先，不设整屏张数硬限额。
5. **通知层进 M1b**（读侧价值确定；RemoteInput 对微信不抱期望）。
6. **minSdk 30**。
7. **ui_snapshot 树空/稀疏时自动融合 OCR**，不设独立语义工具——大脑保持单一心智模型。

**Spike 清单与结论**（可执行版见 [M1 Spike runbook](../runbooks/M1-spike-runbook.md)，结论见 [2026-07-17 Spike 记录](../runs/2026-07-17-M1-spike.md)）：

- **S1 微信树**：自研 a11y 下微信贡献 0 可读节点 → OCR 融合层提前进 M1a，作为微信类任务主通道。
- **S2 系统开关**：`svc`/`cmd` 蓝牙/WiFi 有效，真值源为 `dumpsys` 状态文本；Shizuku 可激活。
- **S3 OCR**：ML Kit bundled 中文精度与延迟达标。
- **S4 截图**：`takeScreenshot` 单次数十毫秒，连发为软节流而非硬失败。
- **S5 分享/通知**：`ShareImgUI` 分享组件有效；RemoteInput 待外部消息实测。

阶段划分：M1a（L0 核心 + L4 + L2 + L1 无特权子集 + 自有 IME 输入链 + 确认卡 + screen_capture + 技能包）→ M1b（Shizuku 位阶、通知层、OCR 融合与模板、ui_diff、IME 自动切换）→ M1c（站规 v3、台账 executor 列、双脑对照、cost.md 再校准）。各阶段当前进度见 [STATUS.md](../../STATUS.md)。

## 12. 降本估算（估算，以台账实测校准）

锚点（实测）：a11y 型只读任务 $0.44/5 轮；纯视觉任务 4 复测 $2.01/55 轮；每轮带整屏截图是成本主因。

| 任务 | 新架构估算轮次 | 估算进模型截图数 | 估算成本 |
|---|---|---|---|
| 1 蓝牙 | 2–3 | 0 | <$0.1 |
| 2 微信中文 | 8–15 | 0–2 | $0.2–0.6 |
| 3 小红书 | 8–12 | 0–2 | $0.3–0.6 |
| 4 截图发微信 | 5–8 | 0–1 | $0.15–0.4 |
| 5 京东物流 | 6–10 | 0–2 | $0.2–0.5 |

依据：轮次降幅来自链路结构（任务 4 的相册/选图器/坐标排障被 `media_query` + `share_file` 替代，置信高）；单轮成本按 a11y 型约 $0.09/轮锚定。S1 判定微信树不可读、S3 判定 OCR 达标，因此任务 2/4 取区间上限。整体目标：纯视觉任务进模型截图数降 90%、成本从 $2–3 级降到 $0.3 级——**这是目标不是承诺**，实测见 [cost.md](../knowledge/brain/cost.md)。
