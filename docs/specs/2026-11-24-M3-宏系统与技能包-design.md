# 设计说明：M3 声明式宏系统与 App 技能包（2026-11-24）

- 日期：2026-11-24
- 决策人：Magina（用户）
- 当前状态见 [STATUS.md](../../STATUS.md)；总体架构承接 [方向一设计 §6](2026-07-16-方向一-手机执行器与订阅大脑-design.md#6-宏系统教一遍核心差异化)

## 1. 背景与目标

2026-11 PA2553 实测与台账（[ledger.csv](../runs/ledger.csv)）表明：

- 常规日常任务纯由大脑逐轮驱动时，单次仍需消耗 **115k–411k 输入 token**、耗时 **54s–98s**（例如小红书 5 条笔记总结 `73s / 322k tok`、淘宝查物流 `90s / 279k tok`、微信横屏就位 `36–48s / 80k–143k tok`）；
- 核心降本路线是：**把可复现、确定性的前置导航与页面核验下沉为网关侧声明式宏（零/低大脑轮次），遇到不确定或页面漂移时精准断点交大脑接管（Handoff）**。

本设计定义 M3 首个可控落地闭环，范围聚焦**「声明式宏资产 + 统一安全执行管线 + 断点 Handoff 契约 + 首个端到端样板（小红书公开笔记搜索预备宏 `xhs_search_prepare`）」**。

## 2. 核心设计边界（与 Debug P0 宏隔离）

| 维度 | Debug P0 验收宏（已有，保持不动） | M3 生产声明式宏（新增） |
|---|---|---|
| 工具名称 | `macro_run`（仅 `src/debug` 公布） | `skill_macro_list`（R）、`skill_macro_exec`（W） |
| 资产来源 | 硬编码 `P0WeChatPrepareMacro.kt` | `app/gateway/src/main/assets/skillpack/macros/` |
| 安全通道 | 专属适配器与 `PreparedTargetEvidence` | **逐步骤调用 `ToolRegistry.callFromMacro`（即 `ToolExecutionPipeline.call(..., CallOrigin.MACRO)`）** |
| Release 行为 | 封闭失败，不注册进 `tools/list` | 可用，但严守同一黑名单、`SafetyGate` 与 `ConfirmOverlay` |

> **绝不合并**：现有 `macro_run` / `P0WeChatPrepareMacro` / `DebugMacroToolCatalog` / `ReleaseMacroToolCatalog` 保持原样，确保既有 P0 安全回归与 Release 隔离契约不受影响。

## 3. 声明式宏资产规范

### 3.1 目录结构
- 索引文件：`app/gateway/src/main/assets/skillpack/macros/index.json`（`{"files": ["xhs_search_prepare.json", ...]}`）。
- 单宏定义：`app/gateway/src/main/assets/skillpack/macros/<id>.json`。

### 3.2 强约束 Schema
- **元数据**：
  - `id`（唯一非空标识符，`[a-z0-9_]+`）
  - `version`（正整数）
  - `app`（App 中文别名）
  - `expect_package`（预期包名；**不得命中 `safety.json` 的 `blocked_app_prefixes`**）
  - `description`（给大脑的简洁用途说明）
  - `readonly`（布尔值，标记是否纯只读宏）
  - `verified`（`""` 或 `YYYY-MM-DD`；**未真机实测通过前必须为 `""`**）
- **参数契约（`params`）**：
  - 每个声明参数包含 `type`（当前仅 `"string"`）、`required`、`min_length`、`max_length`；
  - 运行时**拒绝任何未声明的额外参数**、缺失必填参数或长度越界（统一抛 `E_INVALID_ARG`）。
- **步骤定义（`steps`，非空有序数组）**：
  - `id`：步骤唯一短标识；
  - `tool`：仅允许既定白名单子集：`foreground_app`、`system_get_state`、`skillpack_lookup`、`app_launch`、`open_uri`、`wait_for`、`ui_snapshot`、`ui_find`、`ui_action`、`type_text`、`press_key`。**严禁嵌套 `skill_macro_exec` / `macro_run` / `screen_capture`**；
  - `args`：参数模板对象，仅允许 `{{param}}`、`{{param|urlencode}}`（UTF-8，空格编码为 `%20`）与 `{{ref:slot}}`；装配期静态校验所有 `{{param}}` 必须已在 `params` 中声明；
  - `optional`：布尔值（默认 `false`）；仅当 `true` 且工具返回 `E_NOT_FOUND` 时记录跳过并继续下一步；
  - `save_ref`：可选，从 `ui_find` 恰好 1 条命中的结果中绑定 `ref` 至指定槽位；**任何写操作（`MUTATING_STEP_TOOLS`）执行后立即清空所有 `savedRefs`，严禁跨界面变化复用旧 `ref`**；
  - `handoff_if_foreground_is` / `handoff_reason`：可选；当该步返回的前台包名命中目标值时立即优雅交接给大脑（例如已经在小红书前台时按站规转由站内搜索框提交）；
  - `assertions`：可选后置断言（`package_equals`、`not_packages`、`blocking_overlay_false`、`no_login_wall`、`min_matches`）；
  - `capture_as_final_snapshot`：布尔值，保留该步快照数据放入成功回执的 `final_snapshot`，减少大脑额外调用 `ui_snapshot`。

## 4. 安全零旁路与安全终态铁律

1. **零旁路执行**：`MacroEngine` 不直接调用 `GatewayA11yService` / `IntentTools` / `UiTools` 的内部写方法，每一步**必须**经 `ToolRegistry.callFromMacro(step.tool, resolvedArgs)` 走完完整的：
   - 敏感前台检查（`blockedAppAllows`）
   - 统一安全门 `SafetyGate` + 危险词 / 纯图标 / Enter 证据检查
   - 现场可见 `ConfirmOverlay` 真人批准（若任一步命中危险或泛化确认）
   - `Audit` 落盘（审计 `note` 自动带 `origin=macro`，且敏感输入仍走脱敏摘要）。
2. **安全失败即终态（`handoff_allowed = false`）**：
   - 当任一步骤返回 `E_BLOCKED`、`E_CONFIRM_REQUIRED`、`E_CONFIRM_TIMEOUT`、`E_STALE_REF` 或 `E_PERM_MISSING` 时：
     - 宏立即中止，不再执行后续步骤；
     - **原样抛出对应 `ErrorCode` 的 `GatewayError`**（附带 `extra` 注明 `macro_id`、`failed_step`、`completed_steps` 与 `handoff_allowed = false`），保证外层 MCP 信封 `ok = false`；
     - 严禁返回 `handoff_required`，严禁大脑重试同一动作或换路绕过。

## 5. 非安全失败断点接管（Handoff）与成功回执

- **非安全断点（`handoff_required`）**：当遇到页面已在目标 App 需走站内入口、系统弹窗（如 `com.vivo.appfilter`）、登录墙关键词、深链 `E_VERIFY_FAIL`、`E_NOT_FOUND`、`E_TIMEOUT` 或 `blocking_overlay = true` 时，宏优雅停止并返回正常信封：
  ```json
  {
    "status": "handoff_required",
    "handoff_allowed": true,
    "macro_id": "xhs_search_prepare",
    "completed_steps": ["..."],
    "failed_step": "open_search_deeplink",
    "failure_code": "E_VERIFY_FAIL",
    "failure_reason": "...",
    "blocker_detected": true,
    "next_hint": "...",
    "context_summary": { "package": "...", "actual_package": "..." }
  }
  ```
- **成功完成（`completed`）**：返回 `status = "completed"`、`completed_steps`、`skipped_steps` 与 `final_snapshot`，供大脑直接读取结果页并汇总，无需再从头启动导航。
- **修复回写纪律**：大脑发现页面改版或新阻塞并给出更优步骤后，修复必须经人工审阅更新至宏 JSON 并通过离线校验与单测，不自动在设备上改写资产或放宽安全边界。

## 6. 首个端到端样板：`xhs_search_prepare`

- **基线参照**：2026-11-19 `xhs-tokyo-five-unassisted`（PA2553，无协助，**73 秒 / 322k 输入 token / 13 次网关调用**）。
- **样板职责**：在当前不在小红书前台且无 `com.vivo.appfilter` 拦截时，一步串行完成：
  1. `foreground_app`（校验非 `com.vivo.appfilter`；若已在 `com.xingin.xhs` 则按 `m0-3-xhs-summary.md` 站规交由站内搜索框路径接管）
  2. `open_uri("xhsdiscover://search/result?keyword={{keyword|urlencode}}")`
  3. `wait_for(app_foreground, "com.xingin.xhs")`
  4. `wait_for(idle, quiet_ms=800)`
  5. `ui_find(text="全部", scroll_search=false)`（`optional=true`）
  6. `ui_snapshot(scope="full")`（断言 `package=com.xingin.xhs`、`blocking_overlay=false`、无登录墙，并返回 `final_snapshot`）
- **预期效果**：大脑仅需 `1` 次 `skill_macro_exec` + `0–3` 次详情/翻页阅读即可完成 5 条公开笔记总结，预期显著压低前置导航轮次与输入 token。
