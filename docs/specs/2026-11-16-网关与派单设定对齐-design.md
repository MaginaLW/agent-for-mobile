## 1. 九项对齐契约

### 1.1 `ui_action(click / long_click)` 确认边界
- **普通具名控件**：具备非空可读 `text` 或 `description`，且未命中 `sensitive_targets`、`danger_words`、`action_confirm_words`、`send_words` 时，判为 `SafetyDecision.Allowed`（普通写 W + 审计，不弹确认卡）。
- **敏感目标**：命中 `sensitive_targets` 时在门前直接 `E_BLOCKED`，人工确认不能绕过。
- **可撤回发送类**：命中 `send_words` 时 `ConfirmationRequired(RiskTier.RETRACTABLE)`。
- **不可逆与泛化确认动作**：命中 `danger_words` 或 `action_confirm_words`（`确认/确定/提交/下单/购买/结算/去结算/同意/授权/允许`）时 `ConfirmationRequired(RiskTier.IRREVERSIBLE)`。`action_confirm_words` 独立于 `danger_words`，不污染 `hasSensitiveSurfaceSemantics` 的页面级敏感判定。
- **无标签纯图标控件**：`text` 与 `description` 均为空时按 fail-closed 要求确认：`ConfirmationRequired(RiskTier.IRREVERSIBLE)`。

### 1.2 `press_key(enter)` 生产规则
- 不再强绑 debug 专属宏的 `preparedTargetEvidence`；只要 `focusIdentity` 与刚提交的 `inputCommitEvidence` 有效自洽（`IME_ONLY` 仍要求 `readbackVerified == true`），即可进入 `ConfirmOverlay`。
- 当 `preparedTargetEvidence == null` 时，确认卡展示 `目标会话：未绑定会话标题，请核对屏幕` + 前台包名 + 输入预览，交现场真人核对决定；当 `preparedTargetEvidence != null`（如 P0 宏场景），仍严格校验包名、焦点身份与几何一致。

### 1.3 黑名单出站拦截与确认超时
- `app_launch`、`open_uri`、`intent_send`、`share_text`、`share_file` 在发起前校验目标包名是否命中 `blocked_app_prefixes`，命中即 `E_BLOCKED`，阻断主动拉起黑名单 App 的路径。
- `ConfirmOverlay` 默认确认超时由 `60s` 对齐为 `90s`（`90_000ms`）。注：阶段 6B-1 已于 2026-11-26 完成语义意图生产接线并通过离线门禁，2026-11-27 通过 PA2553 真机验收（PR #93），`intentTtl 360s` / II 级 `foregroundWaitBudget 300s` 已随生产接线启用。

### 1.4 PA2553 无障碍自愈策略
- 保持 `com.vivo.safecenter` 开启（不靠关闭系统安全中心换通过）。
- 允许 `scripts/dispatch.ps1` 预检在检测到网关 `caps` 缺失 `a11y` 且当前前台**不是** `com.android.settings` 时，执行至多一次有界 `enabled_accessibility_services` ADB toggle 重绑并轮询验证 `caps` 恢复 `a11y`；仍失败则立即 `preflight-fail`。

### 1.5 PA2553 横屏三层窗口拓扑
网关按可见、正面积的 `TYPE_APPLICATION` 窗口集合划分三层：
1. **`single`**：单应用窗口，照常运行。
2. **`same_app_multi`（同包多窗 / vivo 平行视界）**：≥ 2 个可见应用窗口且全部非空 `root_package` 归属同一包名。原生支持：
   - `ForegroundWindowTracker` 在同包窗口间切换焦点时平滑接续包级身份，不报 `WINDOW_ID_MISMATCH`；
   - `ui_snapshot` 为每个元素（含按窗口矩形归属的 OCR 元素）标注 `window_id` 与 `pane`（`left`/`right`/`top`/`bottom`/`full`）；
   - 确认卡补充「所在窗口」；
   - 仅当同包多窗且处于 `IME_ONLY`（缺少焦点 `bounds`）时拦截 `press_key(enter)`，要求改点目标窗口内的具体按钮。
3. **`cross_or_unknown_multi`（异包分屏 / 小窗 / 未知归属多窗）**：≥ 2 个可见应用窗口包含不同包名或空包名。严格 fail-closed：`foreground_known = false`（`cross_app_multi_window`）阻断 W/D 动作，且 `ui_snapshot` 拒绝混采（`E_BLOCKED`）。

### 1.6 M1 验收口径
- PA2553 上 M1 主验收按非微信日常任务执行（如 M0-3 小红书总结、M0-5 京东/淘宝查物流 + 确认卡演练/系统任务；M0-1 蓝牙若因进设置触发 `safecenter` 则记录为 ROM 边界或待 Shizuku），与 M0 同口径对比；
- 微信两项（M0-2、M0-4）保留在后置列表，后续结合三层窗口与点右窗「发送」按钮确认卡单独验证，不阻塞 M1 收官。

### 1.7 `dispatch.ps1` 一站式预检与自启收尾
- 内建顺序：`adb get-state` + 唤醒 → 检查 `GatewayService`（未运行则单次后台拉起并标记由本轮自启）→ `adb forward` → `/health` 探测 → 若本地缺配置或仍是占位符且本机为可读写 `run-as` 的 debug 包则原子同步 token → MCP `device_info` 校验授权与 `a11y` 能力（缺 `a11y` 且非设置页前台时执行单次 toggle 重绑）。
- `finally` 收尾只停止由本轮自启的 `GatewayService` 与本轮建立的端口转发，绝不误停派单前已存在的网关服务。
