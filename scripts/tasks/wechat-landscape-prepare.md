# PA2553 横屏微信「文件传输助手」就位

本次只做导航和输入焦点核对。保留全部草稿。不要输入、发送、按键、切换输入法、调取图片、读取消息或抄录草稿。遇到阻塞或任一工具报错，立即以失败结束，不换路、不重试。

1. 读取 `foreground_app`。已在微信则沿用。已确认是解锁后的系统桌面才可调用一次 `app_launch(name="com.tencent.mm")`，随后复核微信已取得前台。锁屏、其他应用、身份不明或遮挡时停止。
2. 用 `foreground_app` 返回的 `windows` 核对两个横向并排的微信应用窗口及其边界、窗口 ID、活动和焦点。只接受 `window_topology=same_app_multi`。用 `ui_find(text="文件传输助手", scroll_search=false)` 定向查找，按完整文字、位置和窗口归属识别右窗顶部标题。
3. 若右窗已活动并持有焦点、顶部标题精确匹配，直接进入第 4 步，即使查找只返回这个标题也已完成导航，导航点击为零。当右窗顶部 1/5 未见「文件传输助手」标题、且左窗（`pane="left"` 且 `window_id` 与左窗一致）恰好存在 1 条「文件传输助手」命中（含 `source="ocr"`、`role="text"`）时，直接对该唯一左窗 ref 调用一次 `ui_action(action="click")`（报错或 `E_STALE_REF` 即立即结束，零重试），切窗后丢弃旧 ref 并重读 `foreground_app`、`ui_find(text="文件传输助手", scroll_search=false)` 与 `keyboard_state(probe_cursor_anchor=true)` 复核右窗标题、活动与焦点。
4. 调用 `keyboard_state(probe_cursor_anchor=true)` 核对键盘状态与 IME 光标锚点。若第 2/3 步 `ui_find(text="文件传输助手", scroll_search=false)` 已报 `focused_identity_source="ime_cursor_anchor"` 且 `ime_cursor_anchor` 证实右窗底部编辑栏（`pane="right"`、`window_id` 与右窗一致、非 `TYPE_NULL`、`editor_bounds` 落在右窗底部编辑行内），跳过 `ui_find(role="input")` 直接进入第 5 步，不要点击。若右窗顶部 1/5 已确认「文件传输助手」标题且 `keyboard_state(probe_cursor_anchor=true)` 返回 `ime_cursor_anchor_reason="input_type_null"`（冷启未聚焦会话页），先调用一次 `ui_find(text="可按住转文字", scroll_search=false)`：仅当右窗（`pane="right"` 且 `window_id` 与右窗一致）底部 1/5（`bounds[1] >= right.bottom - height/5`，含 `source="ocr"`、`role="text"`）恰好存在 1 条命中时，才可对该唯一 ref 调用一次 `ui_action(action="click")`（报错或 `E_STALE_REF` 即立即结束，零重试；数量不为 1 或落点不在底 1/5 时严禁点击），点后立即丢弃旧 ref 并重读 `foreground_app`、`ui_find(text="文件传输助手", scroll_search=false)` 与 `keyboard_state(probe_cursor_anchor=true)` 以证实 `input_type_is_null=false` 与右窗有效 `editor_bounds`，证实后跳过 `ui_find(role="input")` 直接进入第 5 步；若「可按住转文字」缺失（如语音态、已有草稿或空白底栏）则直接失败停止，绝不盲点空白区。其他情形再调用 `ui_find(role="input", scroll_search=false)` 核对右窗底部编辑栏：仅接受带原生可编辑标志 E、已启用、边框完全位于该右窗编辑行内的唯一输入框；排除键盘、会话消息、语音控件和「发送」。已经具有输入焦点时不点；否则只可对该编辑框的新 ref 调用一次 `ui_action(action="click")`。除上述右窗底 1/5 唯一「可按住转文字」ref 与唯一原生可编辑输入框外，禁止对无引用的空白区域、其他文字提示或控件试点。
5. 最后在同一页面修订下重读 `foreground_app`、`ui_find(text="文件传输助手", scroll_search=false)` 与 `keyboard_state(probe_cursor_anchor=true)`；走原生分支时再读 `ui_find(role="input", scroll_search=false)`。仅在满足以下二选一时才报告执行器已就位：（a）原生分支：右窗唯一 `a11y/fused` 编辑框带 E 和 F、`focused_input_id` 非空且 `focused_input_bounds` 与其边框一致；（b）IME 光标锚点分支：`ui_find(text="文件传输助手")` 报 `focused_identity_source="ime_cursor_anchor"`、`focused_input_id=null`、`focused_input_window_id` 与右窗一致、`focused_input_pane="right"`，且 `keyboard_state(probe_cursor_anchor=true)` 返回有效右窗 `ime_cursor_anchor`（无 `ime_cursor_anchor_reason`、非 `TYPE_NULL`、非单位矩阵、`editor_bounds` 位于右窗底部编辑行内且与 `focused_input_bounds` 一致）。键盘显隐与所用分支单独报告。宿主另外核对系统焦点与输入法目标窗口。

按站规终态格式报告起点、启动次数、导航与编辑栏各自的点击次数、右窗和输入焦点、键盘状态、是否出现确认卡及首个阻塞。只报告证据类别和结果，省略草稿、联系人列表和消息正文。
